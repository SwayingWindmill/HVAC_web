# 确定安全、租户隔离与审计基线

Type: grilling
Status: resolved
Blocked by: 01, 02, 04
Part of: ../map.md

## Question

平台从浏览器到 Go 服务、消息总线、ThingsBoard 和 EnergyAgent 的信任边界如何定义？需要确定用户 JWT、服务身份、mTLS/HMAC、密钥管理、租户和 Site 隔离、最小权限、数据脱敏、审计内容与不可变性、Webhook 防重放、内部接口暴露、速率限制、安全事件和合规保留要求，并明确哪些控制必须进入架构验收。

## Comments

- 平台采用默认不信任的分层信任模型。互联网只暴露 `platform-gateway`、受控 Realtime 入口和专用 Webhook Ingress；浏览器、移动端、第三方系统、内部网络、Pod IP、消息生产者及 ThingsBoard 均不因网络位置而自动可信。浏览器不能直连领域服务、Copilot Runtime、EnergyAgent、数据库、Kafka、对象存储或 ThingsBoard；所有南向访问只能经过对应 Connector，所有 Agent 数据访问只能经过 AI Tool Broker。生产内部服务使用私有网络与 NetworkPolicy，但网络隔离只是第二道防线，每次调用仍必须完成服务身份、Audience、协议、资源 Scope 和动作授权验证。
- 外部 IAM 是用户主身份、密码、MFA 与认证会话的唯一权威。浏览器采用票据 08 确定的 OIDC Authorization Code Flow + PKCE 与服务端 BFF Session，浏览器只持有 `HttpOnly/Secure/SameSite` 不透明 Cookie；Access Token、Refresh Token、ID Token、Session Secret 不得进入 localStorage、URL、WebSocket Query、前端日志或 Agent。Gateway 对 JWT 执行算法允许列表、签名、issuer、audience、token type、`exp/nbf/iat`、密钥状态及最大时钟偏差校验，拒绝 `alg=none`、错误 Audience、过期或用途错误的 Token；JWKS 超过允许陈旧度时 Fail Closed。WebSocket 必须验证同源、当前 Session 与短期连接授权，会话撤销后终止连接。
- 客户端提交的 `X-Principal-*`、`X-Organization-*`、`X-Site-*`、Role、Admin、Scope 或授权声明全部视为不可信。Gateway 在认证后构建类型化 `PrincipalContext`，内部协议只接受由受信 Gateway 或 IAM 通过 mTLS 身份传递的上下文；领域数据所有者仍依据当前 Membership、RoleBinding、SiteBinding、资源权威归属和 Policy 执行最终授权。Token Claim 只可作为身份和会话线索，不能替代当前业务授权事实；高风险控制、导出、Review、跨组织访问和权限管理必须在线或通过满足最大陈旧度的权威投影重新验证。
- 每个生产服务、Worker、Connector、消费者和自动化主体使用按 Environment、Service 与 Deployment 隔离的短期 Workload Identity，优先采用 SPIFFE 兼容或云工作负载身份，由平台 CA/身份系统自动签发和轮换 mTLS 证书。证书必须绑定服务名、Environment、Trust Domain 与允许 Audience；不同服务不得共享超级账号、客户端证书或长期 API Key。内部 HTTP/gRPC 使用双向 TLS，TLS 1.3 优先、TLS 1.2 为最低兼容基线，禁止关闭证书校验或使用自定义弱加密。Kafka/Schema Registry 使用独立生产者与消费者身份、mTLS 或等价强认证及最小 Topic/Subject ACL。
- 用户委托与服务认证严格分离。服务间调用使用自身 Workload Identity证明“谁在执行”，并使用由授权服务签发的短期、Audience 受限、不可转委托的 `DelegationGrant` 表达“代表谁、在哪个 acting Organization、对哪些 Site/资源、允许哪些动作、到何时、基于哪个 Policy Version”；Grant 必须包含唯一 `jti`、发起主体、执行服务、Scope、动作、Audience、到期和撤销状态，不能由下游扩大或转发给第三方。AI 的 `InteractionGrant`、`ToolExecutionGrant` 是该模型的专用子类型；浏览器 Token不得被当作内部委托凭证。
- 授权模型统一为默认拒绝、显式允许、显式拒绝优先，基础事实由 IAM 拥有。OrganizationMembership 只表示成员关系；RoleBinding、SiteBinding、资源 Scope、动作权限、风险等级和有限 ABAC共同决定访问。读取、管理、导出、审批、命令提议、命令执行、AI Tool、Replay、审计读取、Secret 管理和安全管理必须拆分权限。高风险权限变更、SiteTransfer、Break-glass、Command Approval、审计保留策略与生产 Kill Switch 必须支持职责分离和双人审批；同一人不得在策略禁止时同时提出并批准同一高风险动作。
- Organization 是租户安全边界，Site 是默认最细业务授权边界。所有租户数据表、事件、缓存、对象、搜索文档、向量/分析分区、导出及审计引用必须携带不可变 `organization_id`，Site 范围资源同时携带 `site_id`；不得由名称、URL、设备 Key 或客户端 Header反推租户。PostgreSQL 数据访问层强制注入事务级租户上下文，应用数据库角色不得 `BYPASSRLS`，Row-Level Security 作为第二道防线；服务数据库 Owner 与运行时账号分离。禁止跨租户 JOIN、事务和缓存复用，受审计的平台管理查询使用独立身份与入口。Redis Key/ACL、对象存储前缀与 Bucket Policy、搜索索引过滤、ClickHouse查询条件和 Kafka消费者均执行租户约束；最终返回前必须重新授权，不能仅依赖索引或缓存中的旧 ACL。
- 租户上下文必须端到端保持且不可被下游覆盖。Outbox/Event Envelope 固定写入来源 Organization/Site、actor、授权快照、aggregate 与版本；生产者从权威业务状态注入，消费者验证与本地资源归属一致，错租户、缺失 Scope、冲突或版本倒退进入 Quarantine。后台任务、批量导出、Replay、Analytics 和 AI Run 在创建时固定 Scope Revision，执行过程中不能通过参数、Prompt或消息扩大范围。高合规或高噪声租户可升级独立数据库/Schema、Topic/Namespace、分析资源组或部署单元，但公共契约和授权语义不变。
- 生产内部 API 默认不对公网、办公网或浏览器暴露。Gateway 之后的服务使用明确服务允许列表、NetworkPolicy、私有 DNS 与端口级入站规则；管理、迁移、诊断、`pprof`、Metrics 和 Health 端点分离，Health不得返回 Secret、连接串或租户数据，生产调试端点默认关闭。运维访问通过受控管理平面、强认证、短期 JIT授权和完整审计，不允许长期 VPN 即获得数据库或服务管理员权限。服务 Egress 默认拒绝，只允许明确的 ThingsBoard、模型 Provider、通知或受控 Webhook目标；所有任意 URL功能必须防止 SSRF、DNS Rebinding、私网/Metadata访问和重定向越界。
- ThingsBoard 是独立外部信任域，只有 `thingsboard-connector-control` 与 `thingsboard-connector-data` 可以访问其 API，并使用按 Environment、IntegrationInstance 与数据/控制用途隔离的凭证。Connector 验证 TLS、Endpoint allowlist、IntegrationInstance状态和 ExternalBinding，不允许其他服务持有 ThingsBoard Token、直接调用 RPC 或访问原始外部 ID。控制凭证与数据读取凭证分离，控制权限只覆盖已验证 Capability所需最小 RPC；Token轮换支持双版本短暂重叠、立即撤销和审计。ThingsBoard原始 Payload、错误和 ACK作为不可信外部输入执行大小、Schema、内容类型和资源绑定校验。
- Secret、签名 Key 与加密 Key 统一由受控 Secret Manager/KMS/HSM边界管理，按 Environment、服务、租户集成和用途隔离，禁止写入仓库、镜像、普通配置、数据库明文、Kafka消息、Prompt、Checkpoint、错误响应或日志。服务优先使用工作负载身份换取短期凭证；确需静态 Secret时必须有 Owner、用途、创建/到期、轮换周期和撤销流程。数据库、对象存储、备份和消息磁盘使用平台级静态加密，ThingsBoard Token、Webhook Secret、模型 Provider Key等高敏字段使用应用层 Envelope Encryption；Key版本和密文绑定上下文，轮换不改写业务主键。禁止自创密码算法，签名与 HMAC比较使用成熟库和常量时间验证。
- mTLS 是内部服务身份认证的默认机制，HMAC 不作为内部服务共享身份替代。HMAC-SHA-256主要用于无法采用非对称签名的外部 Webhook：签名覆盖 HTTP Method、规范化 Path、时间戳、唯一 Nonce/Event ID、Content-Type 与原始 Body Hash，并携带 Key ID。接收方必须在解析正文前验证 TLS、Endpoint、签名、允许的时钟窗口、Nonce/Event ID未使用及 Payload大小，默认时钟窗口为 5 分钟并可按 Provider策略收紧；Replay记录至少覆盖签名窗口与最大重试期。重复合法事件按稳定 Event ID幂等返回，签名失败、时间过期、Key未知或同 ID不同 Payload必须拒绝并审计。Key轮换允许受控双 Key窗口；出站 Webhook使用相同原则、短期重试、目标 Allowlist和DNS/IP复核，Secret不得放入 URL。
- Control/Data Backbone、Schema Registry和管理接口执行独立身份、Topic/Subject最小 ACL、配额与加密传输。Producer只能写其拥有的事件家族，Consumer只能读明确 Consumer Group与Topic，普通服务不能创建 Topic、修改 ACL、读取其他消费组或重放生产流量。消息不得携带 Token、Secret或可直接使用的南向凭证；敏感 Payload使用最小化、必要时字段加密或受控 Artifact引用。Replay只能通过受审批 Replay Job、独立身份和命名空间执行，默认禁止产生 Command、Webhook、通知、收费模型调用等外部副作用；任何跨 Backbone Bridge同样验证租户、Schema、版本与授权。
- 数据分类采用 `PUBLIC/INTERNAL/CONFIDENTIAL_OPERATIONAL/RESTRICTED`，分类标签随 Dataset、Artifact、Evidence、Conversation、导出和派生结果传播，派生数据默认继承最严格来源。`RESTRICTED` 包括 Token、Credential、控制 Secret、未脱敏个人信息、高敏设施和跨租户数据，默认不得进入普通日志、外部模型、通用搜索、非受控导出或客户端缓存。日志、Trace、Metric、Problem Details、通知和审计默认只保存稳定 ID、分类、Hash和安全摘要，不保存完整 Prompt、模型响应、原始遥测大 Payload、密码、Token、Grant、Cookie或 ThingsBoard凭证；诊断 Payload仅在明确策略下加密、短期、受限保存，读取本身审计。
- Audit Ledger 是不可变合规审计权威。业务服务必须在本地权威事务中原子写入 Audit Intent与Outbox；本地 Audit Intent不可持久化时，高风险控制、授权变更、Review/Approval、导出、Replay、Secret操作和正式 AI结果提交必须失败。Ledger使用append-only事件、Organization/时间分片 Hash Chain、周期签名 Checkpoint及保留锁/WORM归档，检测截断、插入、重排和修改。审计至少覆盖登录与会话安全事件、授权允许/拒绝、Membership/Role/SiteBinding与Policy变更、数据读取与导出、Command全链路、AI Grant/Tool/Model/结果/Review、Webhook验证、Replay、Secret/Key生命周期、Break-glass、配置/发布/Kill Switch、Retention/Delete/Legal Hold和安全隔离。
- 审计记录包含事件 ID、时间、Environment、initiating principal、executing service principal、acting/owning Organization、Site/资源 Scope、动作、资源 ID/revision、授权与Policy版本、结果/拒绝原因、correlation/causation/trace、幂等或Fence、Payload/前后值Hash及必要证据引用；不保存Secret、Token、密码、完整凭证或无必要的大型正文。普通用户不能修改或删除审计；审计查询、导出和Legal Hold本身需要独立权限与审计。Command、Break-glass和控制安全审计至少保留7年；其他安全、业务和访问审计按版本化Retention Policy、合同与法规配置，Legal Hold只暂停删除，不扩大访问。
- Break-glass是受控紧急路径而非通用管理员角色。启用需要强认证/MFA、明确事故或工单、最小资源 Scope、短有效期、理由和独立审批；极端紧急场景可先启用后强制限时复核，但不得绕过设备硬边界、Execution Fence、租户隔离、不可变审计或直接访问 ThingsBoard。启用、使用、到期和撤销实时通知安全责任人，所有读取与写入单独标记并在事后复核；Break-glass Credential不得长期发放或用于日常运维。
- 限流与滥用防护分层实施。Gateway按IP、Session、Principal、acting Organization、Endpoint、动作风险和Payload大小限制请求；领域服务按Organization/Site/资源、并发、时间范围、扫描量、导出、命令和AI预算再次限制；Realtime限制连接、订阅、队列与消息速率；Webhook限制来源、Endpoint、失败率和重放缓存；Kafka、数据库、对象存储、模型和ThingsBoard Connector均有独立配额与Circuit Breaker。超限返回稳定`429`与`Retry-After`，不得通过无限队列、静默截断或共享全局限流器让单租户影响其他租户；降级优先级遵循命令与安全审计、遥测摄取、核心查询、Realtime、历史、报表、AI。
- 生产软件供应链实行可验证构建与最小运行权限。依赖和基础镜像锁定版本并持续扫描，CI执行Secret Scan、SAST、依赖/SBOM与License检查、生成构建Provenance并签名镜像；部署只接受批准Registry与可验证签名。容器默认非Root、只读根文件系统、最小Linux Capability、Seccomp/AppArmor、独立ServiceAccount和资源限制，禁止Privileged、HostNetwork、HostPath及未批准调试工具。CI/CD、Migration与生产运行身份分离，数据库Migration只由数据Owner的专用短期身份执行；高风险配置和Policy变更使用Git审查、双人审批、灰度、回滚和审计。
- 安全事件响应必须支持按Principal、Session、Workload Identity、Certificate、Grant、Secret、IntegrationInstance、Organization、Tool、Model、Workflow或全平台粒度立即撤销和隔离。发现跨租户、凭证泄漏、未授权控制、审计破坏或数据出境风险时，平台停止相关新请求，撤销活动Grant/连接/Lease，启用Kill Switch，将结果或数据置为`QUARANTINED`，阻止Command交接，轮换Key，保全证据并启动影响分析。恢复必须通过权威IAM、状态、Audit、Outbox、Fence和Deletion Ledger对账，不得仅重启服务后恢复流量。安全通知按法律、合同和事件响应政策执行，普通错误响应不暴露攻击检测细节。
- 安全控制必须进入架构验收并自动化验证：公网扫描证明只有批准Ingress暴露；伪造内部Header、错误issuer/audience、过期Token、撤销Session、错误mTLS身份和Grant Audience均被拒绝；数据库/RLS、Redis、Kafka、对象存储、搜索、Analytics、导出、AI Tool和Realtime跨Organization/Site访问成功数为零；未知或旧Fence控制、未验证Capability、未审批高风险Command及Agent直连ThingsBoard成功数为零；Webhook重复、过期、签名篡改、Key轮换和DNS Rebinding测试通过；Secret不得出现在仓库、镜像、日志、Trace、Metric、消息、Prompt和Checkpoint；Audit链篡改、截断和Outbox故障可检测且高风险事务Fail Closed；IAM撤销后新请求立即拒绝，活动Session、Realtime和短期Grant在60秒内失效；限流、单租户噪声、Break-glass、备份恢复、Deletion Replay、证书/Key轮换、供应链签名、Egress阻断和安全Kill Switch均通过故障注入。跨租户泄漏、未授权设备控制、Secret泄漏、旧Fence提交和审计篡改未检测的容忍值均为零。

## Answer

平台采用零信任式分层边界：外部用户只通过Gateway/BFF，内部服务以短期Workload Identity和mTLS认证，用户委托通过Audience受限、不可转委托的短期Grant传播；客户端Header、网络位置、Token中的业务Role或Scope均不是最终授权事实。IAM拥有Principal、Membership、RoleBinding、SiteBinding与Policy，领域数据Owner基于当前授权、资源权威归属和固定Scope执行最终判定。浏览器凭证、服务凭证、ThingsBoard凭证与Agent Grant严格分离，任何组件不得共享超级身份或直接跨越Connector、Tool Broker与Command Governance。

Organization是租户安全边界，Site是默认业务Scope。`organization_id/site_id`必须贯穿数据库、RLS、缓存、消息、对象、搜索、Analytics、导出、Realtime和AI，错租户数据进入隔离而非继续处理。内部API默认私有、Egress默认拒绝；ThingsBoard仅由按IntegrationInstance隔离的控制/数据Connector访问。Secret和Key由Secret Manager/KMS管理并使用短期身份、Envelope Encryption、自动轮换与独立审计；内部服务使用mTLS，HMAC仅用于受控Webhook等外部兼容边界，并强制时间戳、Nonce/Event ID、Body Hash、幂等和防重放。

安全审计与业务状态同事务写入本地Audit Intent，再通过Outbox进入append-only、Hash Chain、签名Checkpoint和WORM归档的Audit Ledger。审计覆盖身份、授权、租户访问、Command、AI、Webhook、Replay、Secret、配置、发布、Break-glass、导出、删除和安全隔离，同时执行Payload最小化和敏感信息脱敏。高风险事务无法持久化Audit Intent时Fail Closed；Command和Break-glass安全审计至少保留7年，其他记录按版本化Retention Policy与Legal Hold治理。

平台以默认拒绝、最小权限、职责分离、分层限流、默认拒绝Egress、受控管理平面、签名供应链和最小容器权限运行。安全事件可以精确撤销Principal、Session、Workload、Grant、Secret、IntegrationInstance或工作流，并通过Kill Switch、Quarantine、Key轮换、证据保全和权威对账恢复。架构验收必须覆盖所有存储与消息路径的跨租户隔离、JWT/mTLS/Grant错误与撤销、Webhook重放、Secret泄漏、审计链、防旧Fence、Break-glass、限流、备份删除传播、供应链签名和Egress隔离；跨租户泄漏、未授权设备控制、Secret泄漏、旧Fence提交和未检测审计篡改的容忍值为零。
