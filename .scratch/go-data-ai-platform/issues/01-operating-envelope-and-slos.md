# 确定运行规模、SLO 与容量边界

Type: grilling
Status: resolved
Blocked by: none
Part of: ../map.md

## Question

Go 数据与 AI 平台在首版、三年规划和极端峰值下必须支持怎样的运行包络？需要明确设备数、Site 数、遥测峰值 events/s、单条消息尺寸、实时订阅连接与扇出、历史查询并发、报表和 AI 任务并发、命令延迟与可用性、数据保留期、RPO/RTO，并区分硬性要求、容量目标和暂不承诺项。

## Comments

- 规模输入：100–300 个 Site；每个 Site 500–2000 台设备；单设备 5–30 秒上报一次。
- 推导范围：约 5 万–60 万台设备；若每次上报是一个设备级批量消息包，则稳态入口约 1,700–120,000 messages/s，尚未计字段展开、集中重连、重试与峰值系数。
- 消息模型输入：典型 20–50 个遥测字段，最大 200 个字段；整包 JSON 上报；单包约 1–5 KB。
- 进一步推导：稳态约 3.4 万–2,400 万 field values/s；仅入口 JSON 体量约 1.7 MB/s–600 MB/s，未计协议、消息副本、标准化、索引和存储放大。
- 峰值与恢复基线：承受 5 倍稳态峰值持续 10 分钟；上游最长中断 1 小时；恢复后 2 小时内清空积压；不得静默丢失遥测，任何丢弃都必须可检测、可审计并触发告警。
- 数据保留基线：原始秒级遥测保留 90 天；1 分钟聚合保留 2 年；15 分钟/小时聚合保留 5 年；日报、月报和 KPI 长期保留；命令与安全审计至少保留 7 年。
- 查询范围基线：前端单次历史查询最多 1 年；AI 单次取证默认最多 90 天，扩大范围需经过平台授权或审批。
- 可用性基线：核心 API 99.95%；遥测摄取 99.99%；实时推送 99.95%；命令受理与状态查询 99.99%；报表与 AI 99.9%。
- 延迟基线：核心业务 API P95 ≤ 300 ms、P99 ≤ 1 s；最新遥测查询 P95 ≤ 500 ms；历史曲线 24 小时内 P95 ≤ 1 s、30 天内 P95 ≤ 3 s、1 年内 P95 ≤ 10 s。
- 实时链路基线：设备遥测到前端可见 P95 ≤ 3 s、P99 ≤ 10 s；命令受理 P95 ≤ 300 ms；平台下发至 ThingsBoard P95 ≤ 1 s；命令最终完成超时由设备类型定义。
- 离线任务基线：普通报表 5 分钟内；大型月报 30 分钟内；AI 首次响应 P95 ≤ 5 s；常规完整调查 5 分钟内，复杂任务允许异步执行。
- 控制边界：安全联锁、保护和 100–500 ms 级实时闭环留在 PLC、DDC、边缘网关或 ThingsBoard Edge；Go 平台只承担秒级业务控制、策略编排、审批、调度和审计。
- 并发容量基线：注册用户 10,000；同时在线用户 3,000；实时 WebSocket/SSE 连接 5,000；单连接正常订阅 ≤ 500 点位、硬上限 2,000；最新状态查询峰值 1,000 QPS；普通业务 API 峰值 2,000 QPS；历史曲线并发 200；一年范围大查询并发 20 且进入受控查询队列。
- 离线与 AI 并发基线：普通报表并发 100；大型月报并发 20；AI 在线会话 500；AI 调查并发 100；重型 AI 调查并发 20。
- 命令吞吐基线：持续 100 commands/s；突发 1,000 commands/s 持续 1 分钟；同一设备上的冲突命令必须串行化或依据命令类型执行冲突控制。
- 灾备范围：首版单地域、多可用区；暂不要求跨地域 active-active；保留异地备份或温备环境。
- RPO 基线：已确认接收的遥测为 0；设备命令及状态为 0；核心业务事务 ≤ 1 分钟；报表和派生指标 ≤ 1 小时；AI 运行中临时状态 ≤ 15 分钟。
- RTO 基线：命令受理与状态查询 ≤ 5 分钟；遥测摄取、核心 API 和实时推送 ≤ 15 分钟；历史查询 ≤ 1 小时；报表、分析和 AI 调查 ≤ 4 小时；整个地域不可用时 ≤ 4 小时恢复核心能力。
- 降级优先级：命令与安全审计 → 遥测可靠摄取 → Site、设备和权限查询 → 实时推送 → 历史查询 → 报表 → AI。
- 三年增长基线：按当前规模 3 倍规划；至少 2 倍增长只通过增加实例、分区和存储节点解决；3 倍规模允许扩展集群但不得重写核心架构；生产环境长期保留至少 30% 容量余量。

## Answer

平台按 100–300 个 Site、5 万–60 万台设备设计，稳态承载 1,700–120,000 个设备级 JSON 消息包/秒，并以 5 倍峰值、1 小时积压和 2 小时恢复为硬性容量边界。遥测摄取与命令链路分别采用 99.99% 可用性目标；核心 API、实时推送、历史查询、报表和 AI 按已确认的分级 SLO、RPO、RTO 和降级顺序建设。安全联锁与亚秒级闭环留在边缘控制层，Go 平台承担秒级业务控制。架构必须支持数据分层、持久化缓冲、背压、幂等、重放、在线与离线工作负载隔离，并在不重写核心架构的前提下扩展到三年 3 倍规模。
