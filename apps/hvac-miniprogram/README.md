# 微信小程序

冷站值班人员在手机上用的小程序（#664）：看节能、今天用能、冷站和告警，问 AI 助手。和网页共用平台网关、账号和权限。设计稿在画布「值班小程序界面」，规范在设计系统「泉来禾 HVAC 设计系统」的「小程序」一节。

## 现在做到哪

- 账号密码登录（账号开了验证码的再输验证码），登录后的会话放在请求的 `Authorization` 头里。
- 总览：本月节省和在统计的节能措施、还能再省、今天用能和昨天同时段比、正在发生的告警条数。
- 总览上的「冷站现在」：在运行还是停机、几台在转、功率、供水和室内温度，点进运行页。
- 运行：「实时运行」是冷站状态、功率、制冷量、能效、今天每小时能效和水系统读数；「设备」按运行、停机、需关注筛选，点进设备看全部读数和今天每小时用电。每 30 秒刷新一次（和网页没有实时推送时一样），下拉刷新还会重新读设备清单。
- 助手：底部导航里凸起的圆形按钮。新对话页有四个可以直接点的问题和最近的三个对话（最近一个对话还在回答或在等你回答时，打开助手直接到那个对话）；问了以后能看到助手正在查哪些数据（答完后收成一行，点开看明细）、回答一个字一个字出来，下面是结论卡片（有没有数据依据、关键数字、图、数据说明不了的地方）和「接着问」。助手反问时可以点选项或在输入框里回答；回答中可以停止。「历史对话」列出你在这个站点问过的对话，点一个接着看、接着问。
- 通知：这个站点的告警本身，上面是正在发生的（严重的在前），下面是最近恢复的 20 条，可以只看没确认的；底部「通知」上的红色数字是正在发生、还没人确认的告警条数。点进一条告警看它的经过，写一句说明后确认，或者「问助手」让助手解释这条告警。平台的通知收件箱要先配好通知规则才会有东西（现在服务器上没有配），所以通知页不读它，直接读告警。
- 通知页顶部的「微信提醒」：还能收到几条紧急和重要告警的微信提醒，「多收一条」弹出微信的订阅弹窗，允许了才加一条（`lib/reminders.ts`）。
- 我的：姓名、当前站点、绑定或解除微信（`wx.login` 拿一次性凭证交给平台，平台换成这个人的微信编号记在身份服务里；见 `docs/specs/miniprogram-wechat.md`）、退出登录；切换站点（从总览的站点名或「我的」进入，记住上次选的）。

还没做：每日运行结论的微信推送、微信一键登录。

## 打开和预览

1. 用微信开发者工具「导入项目」，目录选 `apps/hvac-miniprogram`（不是 `miniprogram/` 子目录），AppID 已在 `project.config.json`。
2. 开发者工具自己编译 TypeScript（`useCompilerPlugins`），不需要另外构建。
3. 小程序只连 `https://hvac.swayingwindmill.online`（`miniprogram/lib/platform.ts`）。真机预览前，管理员要在微信公众平台「开发管理 → 开发设置 → 服务器域名」把它加进 request 合法域名。

## 代码约定

照微信官方的开发和性能指引：

- 页面和组件都用 TypeScript；`lazyCodeLoading: requiredComponents` 按需注入组件。
- 底部导航是官方的自定义 tabBar（`custom-tab-bar/`），每个标签页在 `onShow` 里标出自己。
- 能用微信自带的就不自己写：页面标题用微信的导航栏（只有登录页不要），筛选用 `switch`，横条用 `progress`，下拉刷新和提示用微信的。底部导航自己画，是因为中间凸起的助手按钮和 SVG 图标原生 tabBar 做不到（它只认 PNG 图标）。
- 助手结论卡片里的折线图拼成一张 SVG 图片显示（`lib/line-image.ts`），不用 `canvas`：开发者工具里 `canvas` 会浮在页面上，回答往上滚时折线留在原处、盖住输入框和底部导航。
- 只通过 `lib/gateway.ts` 访问平台：带上会话、401 时回到登录页、失败给出平台的问题代码。
- `setData` 只传页面要显示的内容；总览只在显示时每分钟刷新，切到后台就停。
- 站点列表每次登录只读一次，切换站点页和下拉刷新时再读，页面定时刷新不重读（`lib/site.ts`）。
- 不靠手机的时区：今天从哪一刻开始、本月是哪几天，都从平台按站点时区切好的「天」里推出来（`lib/today.ts`、`lib/savings.ts`）。数字格式也自己写（`lib/format.ts`），不用 `toLocaleString`。
- 冷站的分类、运行状态和读数规则和网页「实时运行」一致（`lib/plant.ts` 对照 `apps/hvac-web/src/features/operations/realtime/plant-model.ts`）。点位的中文名、单位和小数位从网页的 `src/domain/centralPlantTelemetry.ts` 复制到 `miniprogram/shared/`（微信只编译 `miniprogram/` 里的文件）：改了网页那份后跑 `npm -w @hvac/miniprogram run sync`，测试会检查两份是否一致。
- 助手的对话整理规则（`thread-model.ts`）、查询步骤的名称（`tool-labels.ts`）和加粗结论的修正（`answer-markdown.ts`）也这样从网页的 `src/features/assistant/` 复制过来；对话数据的类型由小程序自己写（`lib/agent-types.ts`），测试检查它和网页按接口生成的类型一致。
- 助手的回答是一个字一个字推过来的。微信没有 `EventSource` 和 `TextDecoder`，所以用 `wx.request` 的分块接收（`enableChunked`），自己拼字、拆事件（`lib/utf8.ts`、`lib/agent-stream.ts`）。回答里的 Markdown（加粗结论、段落、列表）转成 `rich-text` 的节点，表格单独画成能左右滑动的表（`lib/answer-nodes.ts`）；都按数据拼，不拼 HTML，所以回答里的文字不会变成标签。没有引入第三方 Markdown 组件：要在开发者工具里另外「构建 npm」，而助手的写法是规定好的那几种。结论卡片不带网页上的「依据」链接（那些是网页的页面）。
- 时间按站点的钟点和日期显示，也是从站点「今天」的起点推出来的（`lib/today.ts`）：比如那个起点是 UTC 16:00，站点就在 UTC+8，10 月 1 日 01:26 UTC 写成「10/1 09:26」。
- AppSecret、会话密钥都不进小程序。

## 测试

```bash
npm run miniprogram:check
```

先做两份类型检查（小程序代码只用微信的类型、测试只用 Node 的类型），再跑 `test/` 里的测试：今天和昨天同时段的计算、本月节省、请求封装和登录结果、数字格式、总览显示什么、运行页显示什么、读设备当前值时怎么分批、助手的事件流怎么读（按任意字节切开也读得对）、回答怎么显示、对话怎么显示；还有一条拿网页浏览器测试录下的设备数据，让小程序和网页各算一遍冷站，逐台设备、逐个读数比对。助手的测试用网页浏览器测试里模拟的助手产生的事件流。页面在开发者工具和真机上看。
