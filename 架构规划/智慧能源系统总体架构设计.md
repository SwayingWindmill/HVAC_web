# 智慧能源系统总体架构设计

智慧能源系统整体规划可以拆分为四个相互关联的核心架构：

**1. 系统架构：解决“整个系统如何分层、各系统之间如何协作”。**

**2. 数据架构：解决“能源数据如何定义、组织、存储、流转和治理”。**

**3. 功能架构：解决“智慧能源系统具体提供哪些业务能力”。**

**4. 技术架构：解决“系统最终采用什么技术实现”。**

四者之间的关系可以概括为：

**系统架构定义骨架，数据架构建立底座，功能架构承载业务，技术架构负责实现。**

---

# 一、系统架构

## 1.1 系统总体目标

智慧能源系统不是单一软件，而是一套覆盖：

**设备感知 → 数据采集 → 数据管理 → 能源分析 → AI预测 → 优化决策 → 自动控制**

的完整数字能源平台。

总体形成七层架构：

```text
┌─────────────────────────────────────┐
│             用户与应用层              │
│ Web / App / 大屏 / 报表 / API         │
├─────────────────────────────────────┤
│             能源业务层                 │
│ EMS / 能耗 / 电费 / 告警 / 碳 / 运维   │
├─────────────────────────────────────┤
│             智能决策层                 │
│ 预测 / AI / 优化 / 调度 / 策略         │
├─────────────────────────────────────┤
│             能源数据层                 │
│ 资产 / 测点 / 时序 / 拓扑 / 指标 / 标签 │
├─────────────────────────────────────┤
│             IoT平台层                  │
│ 设备管理 / 协议 / 数据采集 / 指令       │
├─────────────────────────────────────┤
│             边缘计算层                 │
│ 网关 / 缓存 / 协议转换 / 本地控制       │
├─────────────────────────────────────┤
│             现场设备层                 │
│ 电表 / 光伏 / 储能 / HVAC / 充电桩等   │
└─────────────────────────────────────┘
```

主要职责：

- 协议转换
    
- 数据采集

- 数据缓存
    
- 断点续传
    
- 本地计算
    
- 本地告警
    
- 本地控制
    
- 云边协同
    

例如：

```text
Modbus RTU
BACnet
OPC UA
IEC 104
DL/T 645
厂商私有协议
       ↓
    Edge Gateway
       ↓
MQTT / HTTPS / Kafka
       ↓
     云平台
```

必须考虑：

**即使云平台断网，关键能源系统仍然能够安全运行。**

因此储能、配电、HVAC 等重要控制不能完全依赖云端。

# 2.3 Device 与 Point 分离

这是系统设计中非常重要的一点。

Device 是：

**设备。**

Point 是：

**设备产生的数据。**

例如：

```text
Device：
ElectricMeter001

Points：
Voltage_A
Voltage_B
Voltage_C
Current_A
Current_B
Current_C
ActivePower
ReactivePower
PowerFactor
EnergyImport
```

不能把设备和测点混为一谈。

对于：

**负荷预测、光伏预测、异常检测**

传统机器学习往往已经非常有效。

# 4.7 优化引擎

优化问题建议单独设计 Optimization Engine。

```text

        ↓

        ↓

```

算法可以逐步采用：

- 规则算法
    
- 线性规划 LP
    
- 混合整数规划 MILP
    
- 动态规划
    
- 启发式算法
    
- MPC
    
- 强化学习
    

实际能源项目中建议优先：

**规则 + 数学优化。**

而不是一开始就使用强化学习。

因为数学优化更加：

- 可解释
    
- 稳定
    
- 可验证
    
- 可审计

# 七、系统真正的核心

如果把整个智慧能源系统进一步压缩，可以认为核心只有五个平台：

## 1. IoT平台

解决：

**设备怎么接进来。**

## 2. 能源数据平台

解决：

**数据是什么、属于谁、有什么关系。**

## 3. EMS平台

解决：

**能源现在使用得怎么样。**

## 4. 智能决策平台

解决：

**未来会发生什么、应该怎么运行。**

## 5. 控制平台

解决：

**如何安全地执行优化结果。**

因此最终形成：

```text
IoT
 ↓
Energy Data Platform
 ↓
EMS
 ↓
AI / Optimization
 ↓
Control
```

智慧能源系统最终不是一个单纯的“能源管理软件”，而应该逐渐演化成为企业的：

# 能源数字操作系统

它向下连接各种能源设备，向上支撑 EMS、光伏、储能、充电、碳管理、微电网、需求响应和虚拟电厂等不同业务。

整个系统最重要的设计思想是：

**设备可以变化，业务可以增加，算法可以升级，但底层统一的数据模型和能源模型必须保持稳定。**

所以从零开始实施时，建议按照：

**系统架构 → 数据架构 → IoT接入 → 基础EMS → 智能分析 → 优化控制**

逐步建设，而不是首先开发大屏和 AI。
