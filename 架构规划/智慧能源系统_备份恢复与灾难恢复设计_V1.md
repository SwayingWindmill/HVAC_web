# 智慧能源系统备份恢复与灾难恢复设计

> 版本：V1.0  
> 技术基线：PostgreSQL + ClickHouse + Redis + MQTT + Object Storage + Edge Gateway  
> 适用对象：架构、研发、DBA、SRE、运维、Edge研发、实施、发布管理  
> 核心目标：在数据库故障、节点故障、误操作、机房故障、对象存储异常、边缘离线等场景下，保证关键数据可恢复、关键控制可追溯、系统可按明确优先级恢复

---

## 1. 设计目标

智慧能源系统的灾备不是简单的：

```text
每天做一次数据库备份
```

而是要回答：

```text
哪些数据绝不能丢？
允许丢多少？
多久必须恢复？
谁先恢复？
恢复到哪里？
恢复后如何证明数据是正确的？
```

最终建立：

```text
Backup
→ Verify
→ Replicate
→ Restore
→ Reconcile
→ Validate
→ Resume
```

完整闭环。

## 4. RPO / RTO 定义

### RPO

Recovery Point Objective：

```text
最多允许丢失多少时间的数据
```

### RTO

Recovery Time Objective：

```text
故障后多久必须恢复服务
```

---

## 5. 推荐 RPO/RTO 分级

### P0：控制与审计

包括：

```text
Command
Command Log
Safety Policy
Audit
Control Approval
```

目标：

```text
RPO = 0 或接近0
RTO <= 15~30min
```

核心原则：

```text
Persist Before Dispatch
```

---

### P1：主数据与业务配置

包括：

```text
Tenant
Site
Asset
Device
Point
Template
Metric Definition
Alarm Rule
Tariff
Config Version
```

目标：

```text
RPO <= 5min
RTO <= 30~60min
```

---

### P2：实时与近期 Telemetry

目标：

```text
RPO <= 5~15min
RTO <= 1h
```

实际数据仍可通过：

```text
Edge Replay
```

补回。

---

### P3：历史时序与聚合

目标：

```text
RPO <= 1h
RTO <= 4h
```

部分数据可：

```text
Replay
Recalculate
Restore from Backup
```

---

### P4：缓存

包括 Redis Latest。

目标：

```text
RPO = 可接受丢失
RTO <= 10~30min
```

因为：

```text
可从Telemetry / Edge / DB重建
```

## 61. DR Site 模式

三种模式：

```text

```

---

## 62. Cold Standby

备用环境：

```text
平时不运行
```

```text
Provision
Restore
Start
```

成本最低，RTO最长。

---

## 63. Warm Standby

备用：

```text
基础服务运行
数据库部分同步
```

RTO中等。

---

## 64. Hot Standby

接近：

```text
实时同步
```

RTO最低，成本最高。

---

## 65. 第一阶段推荐 DR 模式

## 135. 最终恢复原则

智慧能源系统灾备最终必须坚持：

```text
Control Safety
优先于
Analytics Availability
```

```text
Metadata / Audit
优先于
Derived Metric
```

```text
Realtime
优先于
Replay
```

```text
Raw
优先于
Derived Aggregate
```

```text
Verified Restore
优先于
“Backup显示Success”
```

```text
Single Control Authority
优先于
快速双活
```

最终目标不是：

```text
“有备份文件”
```

而是：

```text
当数据库损坏、
节点故障、
机房不可用、
配置误删、
历史数据丢失、
MQTT中断、
Gateway离线时，

团队知道恢复什么、
从哪里恢复、
按什么顺序恢复、
多久恢复、
恢复后如何证明系统和数据可信。
```

只有这些问题都有明确答案并经过演练，智慧能源系统的灾难恢复体系才算真正完成。
