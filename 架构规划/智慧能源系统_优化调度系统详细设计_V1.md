# 智慧能源系统优化调度系统详细设计

> 文档编号：SE-AI-002  
> 版本：V1.0  
> 状态：CURRENT  
> 适用范围：储能优化调度、需量控制、峰谷套利、PV 消纳、负荷平滑、柔性负荷调度  
> 技术基线：Python Optimization Service + Go Backend + PostgreSQL + ClickHouse + Redis + MQTT + Control Service  
> 上位设计：总体架构、预测系统详细设计、能源指标体系、能源拓扑、计量结算与对账、安全与控制架构、Control Command 规范  
> 核心目标：建立“预测 → 优化 → 安全校验 → 控制执行 → 实际反馈 → 再优化”的闭环调度体系，同时保证优化算法不能绕过 Safety 和 Control

---

# 1. 系统定位

优化调度系统回答：

```text
在已知未来负荷、PV、电价、设备状态和约束的前提下，
未来一段时间应该如何调度可控资源？
```

典型输出：

```text
ESS充放电计划
需量控制计划
PV消纳策略
柔性负荷启停/功率计划
EV充电计划
```

优化系统：

```text
不能直接控制设备
```

标准链路：

```text
Forecast
   ↓
Optimization
   ↓
Dispatch Plan
   ↓
Control Service
   ↓
Safety
   ↓
Edge
   ↓
Device
```

冻结原则：

```text
Optimization decides best

Safety decides allowed

Control reliably executes
```

# 241. 最终冻结原则

第一：

```text
优化永远不直接控制设备
```

第二：

```text
Safety永远高于Optimization
```

第三：

```text
所有优化输入必须版本可追溯
```

第四：

```text
所有Plan必须有有效期
```

第五：

```text
旧Interval不能在恢复后补执行
```

第六：

```text
优化无解时必须明确INFEASIBLE
不能制造假可行解
```

第七：

```text
必须从Shadow开始
```

第八：

```text
Expected Saving不能当Actual Saving
```

第九：

```text
执行结果必须Readback验证
```

第十：

```text
任何时候无法保证状态和控制权一致时
关闭自动调度比继续执行更正确
```

最终平台必须能够回答：

```text
为什么这个时段让ESS充电？

为什么下一个时段让ESS放电？

当时使用了哪个Load Forecast？

使用了哪个PV Forecast？

哪个Tariff版本？

SOC和功率限制是多少？

计划是否考虑了需量？

预期收益是多少？

实际收益是多少？

设备为什么没按计划执行？

是Forecast误差、Safety拒绝、网络问题还是设备限制？

如果算法失败，系统会退到哪一层？

人工能否随时接管？

三个月后还能不能复现当时那次优化？
```

这些问题都能准确回答，并且优化系统无法绕开 Safety / Control 时，智慧能源系统才具备进入自动优化调度阶段的工程基础。
