# 智慧能源系统设备接入与工业协议适配规范

> 版本：V1.0  
> 技术基线：Edge Gateway + Device Template + Standard Point + MQTT  
> 适用对象：设备接入研发、Edge 开发、实施工程师、现场调试人员、测试人员  
> 目标：建立统一、可复用、可验证、可追溯的设备接入流程，避免厂家协议差异污染平台核心数据模型

---

# 1. 规范目标

本规范解决以下问题：

```text
不同厂家
不同型号
不同协议
不同寄存器
不同单位
不同枚举
不同字节序
不同倍率
不同状态码
```

最终必须统一成：

```text
Standard Device
+
Standard Point
+
Standard Quality
+
Standard Command
```

云端不应该感知：

```text
40001
FC3
ns=2;s=Voltage
ObjectType=AnalogInput
Vendor Alarm Word
Vendor Power Sign
```

云端只感知：

```text
active_power
voltage_a
soc
running_status
fault_status
set_power
```

# 3. 接入原则

## 3.1 先标准化，再接设备

禁止：

```text
厂家字段
→ 直接发云端
```

必须：

```text
厂家字段
→ Standard Point
→ Cloud
```

---

## 3.2 设备协议差异只存在于 Edge

Vendor Specific：

```text
Register
Node ID
Object ID
Enum
Bit
Endian
Multiplier
```

只能存在于：

```text
Device Template
Protocol Adapter
```

不能进入：

```text
REST API
Metric
Alarm
React
```

---

## 3.3 Point Code 语义稳定

Point Code：

```text
active_power
soc
energy_import
```

必须长期稳定。

不能因为厂家不同出现：

```text
vendorA_active_power
vendorB_active_power
```

---

## 3.4 标准单位稳定

平台标准单位固定。

例如：

```text
W
→ kW

Wh
→ kWh

Pa
→ kPa
```

模板负责转换。

# 16. Multiplier / Offset

统一公式：

```text
standard_value
=
(raw_value × multiplier + offset)
× unit_factor
```

例如：

```text

multiplier = 0.01
→ 123.45 kW
```

# 23. Alarm Word

如果厂家提供：

```text
Fault Word
Alarm Word
Warning Word
```

不要只上传：

```text
32768
```

必须：

```text
解析
→ 标准状态 / Event
```

Raw Word 可作为：

```text
diagnostic raw field
```

保留，但不作为业务主语义。

# 24. Dimensions

高通道设备使用：

```text

string
mppt
rack
pack
cell
connector
```

例如：

```text

  rack=1
  pack=2
  cell=15
```

不要创建：

```text

```

---

# 25. Physical Range

每个关键 Point 应定义：

```text
physical_range
```

例如：

```text
voltage_a:
0~500V
```

超范围：

```text
OUT_OF_RANGE
```

不能自动截断。

---

# 26. Alarm Threshold 与 Physical Range 区别

```text
Physical Range
= 数据是否合法

Alarm Threshold
= 业务是否异常
```

例如：

```text
Voltage Physical:
0~500V

High Alarm:
> 440V
```

二者不能混。

---

# 27. Sampling Interval

采样周期按业务重要度。

典型：

```text
Power / Voltage / Current:
1~5s

State:
1~5s

Counter:
30~60s

Temperature:
10~60s

Slow Environment:
60~300s
```

---

# 28. Poll Group

不要每 Point 单独轮询。

按：

```text
realtime

```

分组。

# 33. Modbus Register Address

必须明确协议文档是：

```text
0-based
```

还是：

```text
1-based
```

例如厂家写：

```text
40001
```

真正 PDU Address 可能是：

```text
0
```

必须在 Adapter / Template 中统一处理。

---

# 34. Modbus 连续读取

尽量：

```text
合并连续寄存器
```

避免：

```text
1 Point
= 1 Request
```

---

# 35. Modbus 最大读取长度

必须考虑：

```text
协议上限
设备实现限制
厂家限制
```

不能单纯按照协议理论最大值。

---

# 36. Modbus Timeout

现场初始建议：

```text
500~2000ms
```

根据：

```text
LAN
RS485
设备性能
```

调整。

---

# 37. RS485 总线规范

同一串口：

```text
一个 Scheduler
```

串行访问。

不能多个 goroutine 同时抢：

```text
/dev/ttySx
```

---

# 38. RTU 站号

```text

```

重复：

```text

```

# 39. RTU 波特率

整条总线一致：

```text

parity

stop bits
```

```text

```

# 55. Readback



# 56. 设备 ACK 不等于成功

例如：

```text
Modbus FC16 Success
```

只表示：

```text
寄存器写成功
```

不表示设备已经按目标运行。

必须：

```text
Readback
```

---

# 57. 动态控制范围

PCS：

```text
最大充放电功率
```

可能由：

```text
SOC
Temperature
BMS Limit
```

动态决定。

因此：

```text
Device Template Range
```

只表示静态物理边界。

动态边界由：

```text
Safety Policy / Edge Runtime
```

决定。

# 132. 冻结原则

设备接入必须遵守：

```text
Vendor Specific
只能存在于Edge
```

```text
Standard Point
必须跨厂家稳定
```

```text
Unit / Sign / Quality
必须统一
```

```text
控制必须Readback
```

```text
Template必须版本化
```

```text
现场修改必须回到配置管理体系
```

```text
没有Golden Test和Commissioning
不得Release
```

最终目标不是：

```text
“能读到厂家数据”
```

而是：

```text
任何设备
→ 可标准化
→ 可验证
→ 可升级
→ 可替换
→ 可追溯
→ 可规模化复制
```

这才是智慧能源系统设备接入体系的完成标准。
