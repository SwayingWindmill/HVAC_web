# 智慧能源系统标准 Point 字典 V1.0

> Point 是平台对设备数据的标准语义。厂商寄存器、Tag、Object、Property 必须先映射为 Standard Point，再进入上层业务。

## 1. 命名与类型

统一使用 `lower_snake_case`。Point Code 不编码设备编号、位置、单位、厂商或项目名。

Point Type：

| 类型 | 含义 | 典型聚合 |
|---|---|---|
| TELEMETRY | 连续测量量 | AVG/MIN/MAX/LAST |
| COUNTER | 累计量 | FIRST/LAST/DELTA |
| STATE | 离散状态 | LAST/DURATION |
| SETTING | 可设置参数 | LAST |
| COMMAND | 动作型控制 | 不做时序聚合 |

## 10. 单位与 Quality

平台优先单位：kW、kWh、kvar、V、A、Hz、°C、kPa、m³/h、%。百分比统一 0~100。

转换：

```text
standard_value = (raw_value * multiplier + offset) * unit_factor
```

Quality：

| code | quality |
|---:|---|
| 0 | GOOD |
| 10 | BAD |
| 20 | TIMEOUT |
| 30 | OFFLINE |
| 40 | MISSING |
| 50 | STALE |
| 60 | OUT_OF_RANGE |
| 70 | PARSE_ERROR |
| 80 | ESTIMATED |
| 90 | MANUAL |

## 11. V1.0 冻结原则

- point_code 语义不得改变
- 单位不得静默改变
- 功率方向不得静默改变
- COUNTER 不得静默变 TELEMETRY
- 语义变化通过新 Point Code 或新标准版本完成

## 11. V1.0 冻结原则

- 同一 metric_code 只有一个标准业务语义
- 算法变化必须升级 version
- Tariff、Carbon Factor、Baseline 必须带有效期
- 结算指标必须支持 Snapshot
- Late Data 必须支持 Recalculation

# 智慧能源系统数据库物理模型设计

> 基线：PostgreSQL + ClickHouse + Redis。本文定义第一阶段核心物理模型。

## 1. Schema 与职责

建议逻辑 Schema：iam、core、iot、energy、ops、control、analytics。第一阶段可暂用 public，但领域边界保持清晰。

PostgreSQL：元数据、资产、设备、权限、规则、告警、控制、电价、指标定义。  
ClickHouse：Telemetry 与 Metric Series。  
Redis：Latest、状态、实时规则状态、缓存。  
Object Storage：报表、OTA、模型、归档。

## 2. 核心关系

```text
Tenant
 └─ Site
    ├─ Space
    ├─ Asset
    │  └─ Device
    │     └─ Point
    └─ Energy Topology
```

## 3. 核心表 DDL 骨架

```sql
CREATE TABLE tenant (
  id BIGSERIAL PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  tenant_code VARCHAR(64) NOT NULL UNIQUE,
  name VARCHAR(128) NOT NULL,
  status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE',
  timezone VARCHAR(64) NOT NULL DEFAULT 'UTC',
  currency VARCHAR(16) NOT NULL DEFAULT 'CNY',
  country VARCHAR(8),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

```sql
CREATE TABLE site (
  id BIGSERIAL PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  tenant_id BIGINT NOT NULL REFERENCES tenant(id),
  site_code VARCHAR(64) NOT NULL,
  name VARCHAR(128) NOT NULL,
  site_type VARCHAR(32),
  timezone VARCHAR(64) NOT NULL,
  latitude NUMERIC(10,7),
  longitude NUMERIC(10,7),
  area_m2 NUMERIC(18,2),
  status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE',
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (tenant_id, site_code)
);
```

```sql
CREATE TABLE space (
  id BIGSERIAL PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  tenant_id BIGINT NOT NULL REFERENCES tenant(id),
  site_id BIGINT NOT NULL REFERENCES site(id),
  parent_id BIGINT REFERENCES space(id),
  space_code VARCHAR(64) NOT NULL,
  name VARCHAR(128) NOT NULL,
  space_type VARCHAR(32) NOT NULL,
  area_m2 NUMERIC(18,2),
  sort_order INT NOT NULL DEFAULT 0,
  status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE',
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
  UNIQUE (site_id, space_code)
);
```

```sql
CREATE TABLE asset (
  id BIGSERIAL PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  tenant_id BIGINT NOT NULL REFERENCES tenant(id),
  site_id BIGINT NOT NULL REFERENCES site(id),
  space_id BIGINT REFERENCES space(id),
  parent_id BIGINT REFERENCES asset(id),
  asset_type VARCHAR(64),
  asset_code VARCHAR(64) NOT NULL,
  name VARCHAR(128) NOT NULL,
  manufacturer VARCHAR(128),
```

# 智慧能源系统 MQTT 消息规范 V1.0

> Topic 用于路由，不承载过多业务语义；业务语义放 Payload。

## 1. Topic

```text
energy/v1/{tenant}/{site}/{gateway}/telemetry
energy/v1/{tenant}/{site}/{gateway}/state

```

## 2. 通用 Envelope

```json
{
  "schemaVersion":"1.0",
  "messageId":"01J...",
  "gatewayId":"gw_001",
  "timestamp":1786197600000,
  "sequence":123456,
  "traceId":"optional",
  "payload":{}
}
```

## 3. Telemetry

```json
{
  "schemaVersion":"1.0",
  "messageId":"01J...",
  "gatewayId":"gw_001",
  "timestamp":1786197600000,
  "sequence":123456,
  "payload":{
    "devices":[{
      "deviceId":"dev_meter_001",
      "deviceTimestamp":1786197599000,
      "points":[
        {"code":"active_power","value":126.4,"quality":0},
        {"code":"energy_import","value":182736.5,"quality":0}
      ]
    }]
  }
}
```

保留 Device Time / Gateway Time / Cloud Receive Time。Event Time 优先使用可信 Device Time，否则 Gateway Time。

## 4. State / Heartbeat / Event

State：online、state、controlMode。  
Heartbeat：uptime、CPU、Memory、Disk、Temperature、SoftwareVersion、ConfigVersion、ConnectedDevices、OfflineDevices、PendingMessages。建议 30s。  
Event：eventType、sourceType、sourceId、eventTime、severity、data。

## 5. Command

```json
{
  "schemaVersion":"1.0",
  "messageId":"01J...",
  "commandId":"CMD-01J...",
  "traceId":"tr_xxx",
  "issuedAt":1786197600000,
  "expireAt":1786197630000,
  "deviceId":"dev_pcs_001",
  "commandCode":"set_power",
  "params":{"powerKw":300},
  "policy":{"requiresReadback":true,"verificationWindowMs":30000}
}
```

Reply：RECEIVED / VALIDATING / REJECTED / WRITING / DEVICE_ACK / EXECUTED / VERIFIED / FAILED / TIMEOUT / EXPIRED。

## 6. QoS / Retain

| 消息 | QoS | Retain |
|---|---:|---|
| Telemetry | 0/1 | false |
| State | 1 | 谨慎使用 |
| Event | 1 | false |
| Heartbeat | 0/1 | false |
| Command | 1 | false |
| Command Reply | 1 | false |

Command 绝不 Retain，避免旧命令重放。

## 7. 幂等与 Replay

Telemetry 幂等依据：gatewayId + sequence + messageId。  
Command 幂等依据：commandId。Edge 保存近期执行结果，重复 Command 返回历史结果。

Replay 数据增加 `replay=true` 或 `payload.mode=REPLAY`，Realtime 与 Replay 分别统计吞吐，Replay 限速。

## 8. 安全

- TLS
- Gateway 独立证书
- Topic ACL
- Cert Rotation / Revocation
- Broker 不信任 Topic 内自行声明的 tenant 身份

## 9. 版本

Envelope 必须带 schemaVersion。新增字段保持兼容，Breaking Change 升 major version。

# 智慧能源系统 Device Template 规范

> Device Template 把厂商协议世界转换为 Standard Point / Standard Command。

## 1. 模型

```text
Device Product
→ Device Template Version
  ├─ Point Mapping
  ├─ Enum/Bitset Mapping
  ├─ Command Mapping
  └─ Connection Profile
```

## 2. Metadata

```yaml
manufacturer: VendorA
product_code: METER_X100
product_name: 三相智能电表X100
device_type: ELECTRIC_METER
model: X100
protocol: MODBUS_TCP
template_version: "1.2.0"
status: RELEASED
```

## 3. Connection Profile

```yaml
connection:
  protocol: MODBUS_TCP
  default_port: 502
  unit_id: 1
  timeout_ms: 1000
  retry_count: 2
  byte_order: BIG_ENDIAN
  word_order: NORMAL
```

设备实例可 Override IP、Port、Unit ID、串口、Baud Rate。

## 4. Point Mapping

```yaml
points:
  - vendor_code: P_TOTAL
    point_code: active_power
    protocol_address: "40001"
    function_code: 3
    raw_data_type: INT32
    standard_data_type: FLOAT64
    byte_order: BIG_ENDIAN
    word_order: NORMAL
    multiplier: 0.01
    offset: 0
    raw_unit: W
    standard_unit: kW
    sampling_interval_ms: 5000
    access: READ
```

转换顺序：Raw Register → Decode → Endian → Raw Type → Multiplier → Offset → Unit Conversion → Range Validation → Standard Point。

## 5. Enum / BITSET

```yaml
enum_mapping:
  "0": STOPPED
  "1": RUNNING
  "2": FAULT
```

BITSET：bit0=OVER_VOLTAGE、bit1=UNDER_VOLTAGE、bit2=OVER_TEMPERATURE 等。业务层不处理原始数字魔法值。

## 6. Channel / Index

多通道使用 dimensions：

```yaml
point_code: cell_voltage
dimensions:
  rack: 1
  pack: 2
  cell: 11
```

## 7. Poll Group

```yaml
poll_groups:
  - name: realtime
    interval_ms: 5000
    points: [active_power, voltage_a, current_a]
  - name: counters
    interval_ms: 60000
    points: [energy_import, energy_export]
```

Template 应支持连续地址信息，让 Gateway 合并 Modbus 请求。

## 8. Range 与 Alarm 边界

Template 的 min/max 是物理合法范围，不是业务告警阈值。告警阈值由 Alarm Rule 管理。

## 9. Command Mapping

```yaml
commands:
  - command_code: set_power
    risk_level: 2
    write:
      protocol_address: "40100"
      function_code: 16
      raw_data_type: INT16
      multiplier: 10
    params:
      - name: powerKw
        type: FLOAT64
        unit: kW
        min: -500
        max: 500
    readback:
      point_code: target_power
      tolerance:
        absolute: 5
      timeout_ms: 5000
```

Start 示例：写 40010=1，Read Back `running_status == RUNNING`。

## 10. 版本生命周期

```text
DRAFT → TESTING → RELEASED → DEPRECATED
```

生产 Device 只能绑定 RELEASED。

## 11. Certification

发布前必须验证 Connection、Address、Function Code、Type、Endian、Scale、Unit、Enum、Range、Command、Read Back，通过后标记 CERTIFIED。

# 智慧能源系统 Control Command 规范 V1.0

> 所有真实设备控制必须经过 Control Service。

## 1. 标准 Command

第一版：start、stop、reset、set_power、set_mode、set_temperature、enable、disable、open、close。避免 toggle/increase/decrease 这类非幂等语义。

## 2. Source / Risk

Source：MANUAL、SCHEDULE、RULE、OPTIMIZATION、EMERGENCY、EXTERNAL。

Risk：1低风险；2运行控制；3高风险启停；4关键安全操作。

## 3. 状态机

```text
CREATED
→ VALIDATING
→ WAITING_APPROVAL
→ APPROVED
→ SENDING
→ SENT
→ EXECUTING
→ SUCCESS
```

异常：REJECTED / FAILED / TIMEOUT / CANCELLED / EXPIRED。

## 4. 控制链

```text
Request
→ Persist
→ Authorization
→ Safety Validation
→ Approval
→ Dispatch
→ Edge Validation
→ Device Write
→ Read Back
→ Verification
→ Final Result
```

## 5. 必填信息

command_id、tenant_id、site_id、device_id、command_code、source_type、requested_at、expires_at、status。人工命令增加 requested_by/reason；算法命令增加 strategy_id/version/optimization_run_id。

## 6. Safety Validation Pipeline

```text
Identity
→ Permission
→ Scope
→ Capability
→ Control Mode
→ Device Online
→ Writable
→ Parameter Type
→ Static Range
→ Dynamic Range
→ Device State
→ SOC/Temperature
→ Interlock
→ Rate Limit
→ Approval Policy
```

默认 DENY。

## 7. Control Mode

| Mode | 人工远程 | 自动策略 |
|---|---|---|
| LOCAL | 否 | 否 |
| REMOTE_MANUAL | 是 | 否 |
| REMOTE_AUTO | 是 | 是 |
| MAINTENANCE | 特定权限 | 否 |
| LOCKED | 否 | 否 |

## 8. 动态限制

例如 Rated 500kW、Site Limit 450kW、BMS Limit 180kW，最终允许 180kW。

`set_power` 统一：>0 放电，<0 充电。必须验证 Rated、BMS Limit、SOC、Temperature、Mode、Fault、Ramp Rate。

## 9. Approval

建议：Risk1无需；Risk2可选；Risk3必须；Risk4双人审批 + Step-up MFA。Site Policy 可 Override。

## 10. Command Preview

Preview 可返回 allowed、riskLevel、requiresApproval、allowedRange、currentState、checks；仅用于 UX，执行时必须重新校验。

## 11. Edge二次校验

Edge 检查 command_id 重复、expireAt、本地控制模式、设备状态、动态限制、本地联锁。Cloud Allow 不代表 Edge 强制执行。

## 12. Read Back 与结果

结果分层：ACCEPTED / SENT / DEVICE_ACK / EXECUTED / VERIFIED。`mqtt.publish success != device success`。

Verification 支持 absolute/relative tolerance 和 verification window。

## 13. Manual Override / Kill Switch / Arbitration

人工接管必须有 valid_until 与 reason。Kill Switch 支持 GLOBAL/SITE/ASSET，停止自动策略下发但不等同硬件急停。

策略优先级参考：EMERGENCY > SAFETY > GRID_CONSTRAINT > DEMAND_CONTROL > OPTIMIZATION > SCHEDULE。

同一 device + control_dimension 同时只允许一个 Control Owner，可使用 Control Lease。

## 14. 标准错误码

```text
CONTROL_PERMISSION_DENIED
DEVICE_LOCAL_MODE
DEVICE_OFFLINE
DEVICE_FAULT
COMMAND_NOT_SUPPORTED
VALUE_OUT_OF_RANGE
SOC_TOO_LOW
```

```text
├── service.go

```

不要全局按 handler/service/repository 平铺。

## 3. 分层职责

Handler：HTTP parsing、Auth Context、Validation、DTO、Response。  
Service：Domain Rule、Authorization、Transaction Orchestration。  
Repository：领域数据访问接口。  
PostgreSQL 推荐 pgx + sqlc；ClickHouse 使用独立 Go Client 与批量写入边界。CTE、Window Function、Batch Write 按各自数据库能力实现。

## 4. Context / Middleware

Context 携带 request_id、trace_id、user_id、tenant_id、roles。

Middleware：RequestID、Recover、Logging、Metrics、Tracing、Authentication、Authorization、RateLimit。

tenant_id 不从普通业务 body/query 作为安全来源。

## 5. 错误模型

统一 AppError：Code、Message、HTTPStatus、Details。业务只返回标准 Code，例如 DEVICE_OFFLINE。

## 6. Telemetry Worker

```text
MQTT/Event Input
→ Decode
→ Normalize
→ Quality
→ Dedup
→ Redis Latest
→ ClickHouse Batch Writer
→ Alarm Trigger
→ Metric Trigger
```

Writer 使用 batch_size + flush_interval 双阈值。

## 7. Device / Energy / Metric

Device Service：Product、Device、Point、Template Binding、Gateway、Capability。  
Energy Service：Overview、Consumption、Flow、Balance、Demand、Cost。  
Metric Service：Definition、Dependency、Engine、Series、Recalculation。

上层业务只依赖 Standard Point / Metric，不理解 Vendor Register。

## 8. Alarm 模块

```text
alarm/
├── rules/
├── engine/
├── lifecycle/
├── notification/
└── repository/
```

早期可同进程，逻辑边界保持独立。

## 9. Control 模块

```text
control/
├── command/
├── policy/
├── validator/
├── approval/
├── dispatcher/
├── verification/
└── audit/
```

Validator 第一版：Permission、Mode、Online、Capability、Range、SOC、State、Interlock、Expiry。

Dispatcher 只负责 Command → IoT/MQTT，不负责判断业务是否允许。

## 10. Transaction 原则

创建关键 Command：

```text
insert command
insert command_log
commit
→ publish MQTT
```

禁止数据库提交前控制真实设备。

## 11. Realtime / Observability

WebSocket 第一阶段可基于 Redis PubSub / Internal Event。后期再拆独立 Realtime Gateway。

统一 `pkg/observability` 提供 logging/metrics/tracing/context；业务 Metrics 在各 Domain 定义。

## 12. 服务部署

第一阶段：energy-api、iot-service、telemetry-worker；Python 独立 optimization-service。

拆微服务条件：独立团队、独立容量瓶颈、独立发布周期、数据边界成熟。不要“一张表一个微服务”。

## 13. 测试

每个 Domain：Unit + Repository Integration + Handler Integration。Control 必须重点覆盖 Negative Safety Test。

# 智慧能源系统 Device Simulator 设计

> Simulator 是正式测试基础设施，不是临时脚本。

## 1. 目标

用于 IoT 接入、MQTT、Telemetry E2E、Alarm、Control、容量测试、故障注入和 CI/Staging。

第一版模拟：Gateway、Electric Meter、PV Inverter、PCS、BMS。第二版扩展 EV、Chiller、Pump、Environmental Sensor。

## 2. 架构

```text
Scenario Engine
├─ Virtual Gateway
│  ├─ Device
│  └─ Device
├─ Telemetry Generator
├─ State Machine
├─ Fault Injector
├─ MQTT Client
└─ Command Handler
```

## 3. Scenario YAML

```yaml
scenario:
  name: ess-basic
  duration: 3600s

gateway:
  id: sim-gw-001
  heartbeat: 30s

devices:
  - id: sim-meter-001
    type: ELECTRIC_METER
  - id: sim-pcs-001
    type: PCS
  - id: sim-bms-001
    type: BMS
```

## 4. 数据生成

支持 CONSTANT / RAMP / SINE / RANDOM / STEP / FILE_REPLAY / EXPRESSION。

Meter 示例：active_power 使用 SINE；energy_import 对 active_power 做积分。

ESS：PCS 维护 ess_power/target_power/running_status；BMS 维护 soc/soh/temperature/max charge/discharge power；SOC 根据功率积分变化。

## 5. Command Handler

支持 set_power/start/stop/reset，可配置 SUCCESS / DELAYED_SUCCESS / REJECT / TIMEOUT / READBACK_FAIL。

## 6. Fault Injection

支持 DEVICE_OFFLINE、GATEWAY_OFFLINE、MQTT_DISCONNECT、MODBUS_TIMEOUT、BAD_QUALITY、MISSING_POINT、OUT_OF_RANGE、DUPLICATE_MESSAGE、OUT_OF_ORDER、DELAYED_MESSAGE、CLOCK_DRIFT。

示例：300s Meter 离线 120s；600s BMS soc 强制变为 8% 60s。

## 7. MQTT / Store & Forward

必须支持 TLS、QoS、Sequence、MessageId、Reconnect、Backoff、Replay。

Cloud Disconnect → Local Buffer → Restore → Replay；Replay 限速，Realtime 优先。

## 8. 大规模模式

参数：gateway_count、devices_per_gateway、points_per_device、sampling_interval、batch_size、payload_size。输出 messages/s、values/s、bytes/s。

支持 Reconnect Storm 与 Alarm Storm 场景。

## 9. 控制安全场景

例如 Cloud 发送 set_power 300kW，而 BMS max_discharge_power=180kW，Edge/Simulator 应按策略拒绝或限制并返回明确错误码。

Duplicate Command：同 commandId 执行一次。Expired Command：延迟接收后拒绝。

## 10. Golden Scenario

```text
meter-normal.yaml
meter-counter-reset.yaml
gateway-offline-replay.yaml
ess-low-soc.yaml
ess-control-success.yaml
ess-command-timeout.yaml
alarm-storm.yaml
reconnect-storm.yaml
```

## 11. CI / Staging

CI 使用 1 Gateway + 3 Devices + 20 Points 跑完整 Telemetry/Metric/Alarm/Command E2E。  
Staging 可模拟 100~1000 Gateways 做 Load/Replay/Reconnect/Alarm Storm。

## 12. 技术实现

建议使用 Go：并发连接、MQTT、单二进制、部署简单。Scenario 用 YAML：

```text
simulator run scenario.yaml
```

第一版验收：Meter/PCS/BMS、Telemetry、Heartbeat、Command/Reply、Offline、Duplicate、Delay、Replay 全部可模拟。
