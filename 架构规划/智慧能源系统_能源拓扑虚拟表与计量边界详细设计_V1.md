# 智慧能源系统能源拓扑、虚拟表与计量边界详细设计

> 文档编号：SE-BIZ-004  
> 版本：V1.0  
> 状态：CURRENT  
> 上位设计：总体架构、数据架构、ER模型V2、能源指标体系设计、计量结算与对账规则详细设计  
> 技术基线：PostgreSQL + ClickHouse + Redis + Go  
> 核心目标：建立统一、可追溯、可版本化的能源拓扑模型，使 Meter、PV、ESS、Load、Virtual Meter、Metric、Settlement 使用同一套能源边界和流向语义

---

# 1. 设计目标

本设计解决以下问题：

```text
一个Site里有哪些能源节点？

电从哪里来？
流向哪里？
谁是父表？
谁是子表？

一个Building的总能耗到底怎么算？

一个Virtual Meter由哪些真实Meter组成？

Grid Import / Export如何确定？

PV自用、上网、储能充电如何划分？

ESS充电到底算负荷还是储能流？

同一个Meter能不能被多个Metric重复汇总？

Meter换表后拓扑如何延续？

拓扑变化以后历史指标怎么算？
```

目标不是画一张静态单线图，而是建立：

```text
可计算
可版本化
可校验
可查询
可审计
```

的能源业务拓扑。

---

# 2. 核心原则

## 2.1 物理资产和能源拓扑分离

```text
Asset
```

表示：

```text
这是什么设备/设施
```

例如：

```text
Transformer
PV Inverter
Battery
Chiller
Meter
```

而：

```text
Energy Topology
```

表示：

```text
能源从哪里流向哪里
```

二者不能混为一张树。

---

## 2.2 Device 和 Meter 分离

```text
Device
```

是采集对象。

```text
Meter
```

是能源计量角色。

一个 Device 可以：

```text
提供多个Point
```

其中某个 Counter Point 才可能成为 Settlement Meter。

---

## 2.3 Topology 和组织树分离

```text
Tenant
→ Site
→ Space
→ Asset
```

属于管理结构。

```text
Grid
→ Transformer
→ Bus
→ Building
→ Load
```

属于能源流结构。

不能强行要求两者完全一致。

---

## 2.4 Topology 必须版本化

现场会发生：

```text
新增回路
改接线
换表
新增PV
新增ESS
新增Building
```

所以拓扑必须有：

```text
effective_from
effective_to
version
```

历史数据必须使用当时有效的拓扑版本。

# 18. Topology Graph

能源拓扑使用：

```text
Directed Graph
```

不是普通 Tree。

原因：

```text
ESS双向
Grid进出口双向
多个电源汇流
多个母线
备用线路
```

---

# 19. 不允许普通有向环

正常配电拓扑原则上：

```text
不能形成无解释循环
```

但某些闭环供电结构允许物理环网。

因此模型需区分：

```text
PHYSICAL_CONNECTION
ENERGY_ACCOUNTING_FLOW
```

结算计算使用：

```text
ENERGY_ACCOUNTING_FLOW
```

# 168. 最终冻结原则

第一：

```text
Asset Tree
不等于
Energy Topology
```

第二：

```text
Meter
通过Binding计量Energy Edge
```

第三：

```text
父表/子表
由Topology决定
不是Meter ID硬编码
```

第四：

```text
所有结算Boundary
必须有明确Authoritative Source
```

第五：

```text
Virtual Meter必须版本化、可解释、无循环
```

第六：

```text
Topology变更不能重写历史
```

第七：

```text
PV / ESS / Grid / Load
使用统一方向语义
```

第八：

```text
多能源来源无法直接测量时
必须标记Attribution Quality
不能假装是Measured
```

第九：

```text
Metric和Settlement必须知道使用哪个Topology Version
```

第十：

```text
任何一个能源数字
最终都能追溯到
Boundary → Edge → Meter → Point → Device
```

当系统能够准确回答：

```text
这个Site的电从哪里来？

当前负荷由哪些能源供给？

这块表到底计量哪条边界？

Building总能耗为什么是这个数？

有没有重复计量？

PV发电有多少上网、有多少本地消纳？

ESS的充放电边界在哪里？

为什么这个Metric使用这些Meter？

拓扑改造后为什么历史账单没变化？
```

这些问题时，智慧能源系统的能源拓扑与计量边界模型才算真正完成。
