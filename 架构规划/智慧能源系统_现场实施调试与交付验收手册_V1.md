# 智慧能源系统现场实施、调试与交付验收手册

> 文档编号：SE-OPS-007  
> 版本：V1.0  
> 状态：CURRENT  
> 适用范围：现场实施、Edge Gateway 部署、设备接入、联调、试运行、验收、项目交付  
> 适用对象：实施工程师、现场电气工程师、Edge 研发、后端研发、测试、运维、项目经理、客户代表  
> 上位设计：Edge Gateway 详细设计、设备接入与工业协议适配规范、配置中心与版本发布设计、测试与验收体系、生产 Runbook、Golden Dataset  
> 核心目标：将“设备接入到平台并完成验收”标准化为可重复执行、可记录、可签字、可追溯的现场工程流程

---

# 1. 手册定位

本手册不讨论系统为什么这样设计，而是直接回答：

```text
设备到现场以后先做什么？

Gateway 安装在哪里？

网线和 RS485 怎么检查？

Modbus 连不上先查什么？

CT/PT 倍率怎么确认？

设备点位怎么逐项核对？

平台数据和现场表计怎么比？

断网补传怎么验？

什么时候算联调完成？

控制功能怎么做安全验收？

客户最终签字前必须交哪些东西？
```

现场实施必须做到：

```text
有计划
有步骤
有记录
有证据
有验收
```

# 171. 常见现场问题快速索引

| 现象 | 首查 |
|---|---|
| Modbus连不上 | IP/Slave/Port/RS485 |
| 值差10倍 | Multiplier/CT/PT |
| 功率方向反 | Wiring/Sign |
| Counter下降 | Reset/Rollover/换表 |
| 多设备同时Timeout | RS485 Bus |
| Cloud无数据 | MQTT/Worker |
| Redis无Latest | Worker/Out-of-order |
| History无数据 | ClickHouse |
| Daily Energy不对 | Counter/Timezone |
| 断网后Latest变旧 | Replay Latest规则 |
| 控制写成功但设备没变 | Readback/Mode/Limit |

# 174. 冻结原则

第一：

```text
没有现场资料确认
不猜协议语义
```

第二：

```text
没有现场值对比
不认为Point正确
```

第三：

```text
CT/PT、方向、Counter
必须独立核验
```

第四：

```text
一条数据必须验证完整E2E
```

第五：

```text
断网补传必须现场验证
```

第六：

```text
控制必须先做Negative Test
```

第七：

```text
没有72h稳定性
不建议正式验收
```

第八：

```text
P0/P1未关闭
不得Final Acceptance
```

第九：

```text
生产版本和交付文档必须一致
```

第十：

```text
验收完成以后
所有变更仍必须回到版本管理和审批体系
```

最终标准不是：

```text
“页面上已经有数据了”
```

而是：

```text
设备身份正确，
通信稳定，
点位语义正确，
倍率和方向正确，
Counter正确，
断网可补传，
平台全链路可验证，
告警正确，
控制安全，
版本可追溯，
运行稳定，
客户和运维都知道系统现在是什么状态。
```

达到这些条件，Site 才真正具备正式 Go-Live 和长期生产运行资格。
