# 智慧能源系统文档基线、版本与交付物总目录

> 文档编号：SE-DOC-001  
> 版本：V1.0  
> 状态：CURRENT  
> 适用范围：智慧能源系统架构、研发、测试、实施、发布、运维与交付  
> 核心目的：建立唯一文档基线，明确“哪份文档当前有效、哪份已被替代、研发应该以什么为准、不同文档冲突时如何裁决”。

---

# 1. 本文档的定位

随着智慧能源系统设计持续深化，文档已经覆盖：

```text
总体架构
详细设计
数据模型
数据库
IoT / Edge
设备接入
能源指标
计量结算
安全控制
告警
配置治理
CI/CD
灾备
生产运维
研发契约
第一阶段工程实施
```

当前最大的文档风险已经不是“缺设计”，而是：

```text
同一主题存在 V1 / V2
历史数据库方案仍可能出现在旧文档中
架构文档与研发契约可能存在时间差
新成员不知道应该先看哪份文档
开发实现无法判断哪份文档具有最高约束力
```

因此建立正式文档控制面：

```text
Document Baseline
+
Version Control
+
Authority
+
Superseded Relation
+
Delivery Set
```

# 2. 文档状态定义

所有正式文档必须标记以下状态之一。

## CURRENT

```text
当前正式研发 / 测试 / 交付依据
```

---

## SUPERSEDED

```text
已被更新版本替代
```

保留历史，不作为新开发依据。

---

## REFERENCE

```text
仅供背景、设计历史或思想参考
```

不得覆盖 CURRENT 文档。

---

## DRAFT

```text
正在编写 / 评审
```

不得直接作为 Production 开发依据。

---

## PLANNED

```text
已计划但尚未完成
```

---

## RETIRED

```text
不再适用且不建议继续引用
```

---

# 3. 文档权威等级

当两份文档出现冲突时，按以下顺序裁决：

```text
L0 ADR / 冻结决策
        ↓
L1 研发契约 / Schema / OpenAPI / MQTT Contract
        ↓
L2 当前详细设计
        ↓
L3 当前总体架构
        ↓
L4 工程实施设计
        ↓
L5 测试 / 运维 / Runbook
        ↓
L6 历史版本 / Reference
```

注意：

```text
实际可执行 Contract
优先于
历史说明性文字
```
