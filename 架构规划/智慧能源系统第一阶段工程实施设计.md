# 智慧能源系统第一阶段工程实施设计

> 版本：V1.0  
> 技术基线：Go + React + PostgreSQL + ClickHouse + Redis + MQTT  
> 阶段目标：跑通第一条真实 Meter Vertical Slice，并建立可持续扩展的工程基线  
> 本阶段原则：不追求“大而全”，只验证一条完整、可观测、可测试、可扩展的数据闭环

---

# 1. 第一阶段目标

第一阶段不是完成整个智慧能源平台，而是完成：

```text
真实电表
→ Edge Gateway
→ Modbus
→ Standard Point
→ MQTT
→ Go Telemetry Worker
→ Redis Latest
→ ClickHouse Raw
→ 1min Rollup
→ Go API
→ React
```

并同时具备：

```text
IAM
Tenant
Site
Asset
Device
Point
Observability
Simulator
E2E Test
Performance Test
```

第一阶段结束后，平台必须能回答：

```text
这台电表是谁？
属于哪个Site？
它有哪些标准Point？
最新值是什么？
过去24小时趋势是什么？
数据质量怎么样？
如果断网，能否补传？
如果出现重复数据，是否污染结果？
系统在10k~20k values/s下是否稳定？
```

# 15. Edge数据转换

完整流程：

```text
Modbus Register
→ Raw Bytes
→ Decode
→ Endian
→ Raw Type
→ Multiplier
→ Offset
→ Unit Conversion
→ Range Check
→ Standard Point
→ Quality
```

例如：

```text
40001
Raw = 12640
Multiplier = 0.01
Standard = 126.4 kW
```

Cloud 永远不应该看到：

```text
40001 = 12640
```

而应该看到：

```text
active_power = 126.4 kW
```

# 63. 第一阶段核心原则

第一：

> 不追求设备种类，追求第一条链路正确。

第二：

> 不追求页面数量，追求数据可信。

第三：

> Redis负责最新，ClickHouse负责历史，PostgreSQL负责业务事实。

第四：

> Vendor Protocol 到 Cloud 后必须消失，只留下 Standard Point。

第五：

> Replay 数据不能影响 Realtime 最新状态。

第六：

> COUNTER 必须按累计量语义处理，不能当普通 Telemetry。

第七：

> 任何性能测试都必须是写入 + 查询 + 聚合混合负载。

第八：

> 第一阶段通过以后，再扩 PV 和 ESS。
