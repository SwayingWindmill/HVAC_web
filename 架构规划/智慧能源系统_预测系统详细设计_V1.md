# 智慧能源系统预测系统详细设计

> 文档编号：SE-AI-001  
> 版本：V1.0  
> 状态：CURRENT  
> 适用范围：负荷预测、光伏预测、能源需求预测、预测结果评估与服务化  
> 技术基线：Python Forecast Service + Go Backend + PostgreSQL + ClickHouse + Redis + Object Storage  
> 上位设计：总体架构设计、数据架构设计、能源指标体系设计、能源拓扑与计量边界详细设计、数据生命周期治理规范  
> 下游系统：Dashboard、告警分析、需量管理、优化调度、能源运营分析  
> 核心目标：建立可版本化、可评估、可回退、可解释、可复现的能源预测能力，并确保预测系统与设备层、Metric、Topology 和后续 Optimization 解耦

---

# 1. 系统定位

预测系统解决：

```text
未来会发生什么？
```

主要输出：

```text
未来负荷
未来光伏
未来购电需求
未来净负荷
```

预测系统：

```text
不直接控制设备
```

也：

```text
不直接向MQTT发送Command
```

标准链路：

```text
Telemetry / Metric / Weather / Calendar
                ↓
          Forecast Service
                ↓
        Forecast Result
                ↓
       Optimization Service
                ↓
          Control Service
```

冻结原则：

```text
Forecast predicts
Optimization decides
Safety allows
Control executes
```

# 4. 进入预测系统的前置 Gate

以下能力应稳定：

```text

PV数据稳定

Metric Standard
```

建议至少具备：


对于明显季节性业务：

```text
更长历史
```

更有价值。

# 6. SITE_LOAD

表示：

```text
站点真实负荷需求
```

推荐基于明确的：

```text
Load Boundary
```

而不是简单等于：

```text

```

---

# 7. SITE_NET_LOAD

定义可按项目固定：

```text
Net Load
=
Load
-
PV
-
Other Local Generation
```

ESS 是否包含在 Net Load 中：

```text
必须明确
```

优化调度场景通常希望区分：

```text
Uncontrolled Load
PV
ESS
```

因此不建议把 ESS 行为混进基础 Load Forecast Target。



# 62. Forecast Evaluation 指标

至少：

```text
MAE
RMSE
WAPE
MAPE
Bias
```

---

# 63. MAE

```text
mean(abs(actual - forecast))
```

直观稳定。

---

# 64. RMSE

更惩罚：

```text
大误差
```

---

# 65. MAPE

```text
abs(error / actual)
```

但实际值接近：

```text
0
```

时不稳定。

---

# 66. MAPE 使用规则

必须设置：

```text
minimum_actual_threshold
```

低于阈值：

```text
不纳入MAPE
```

或改用：

```text
WAPE / MAE
```

---

# 67. WAPE

```text
sum(abs(error))
/
sum(abs(actual))
```

对能源预测更稳健。

---

# 68. Bias

```text
mean(forecast - actual)
```

可识别系统性：

```text
高估
低估
```

---

# 69. Peak Error

负荷预测额外评价：

```text
peak_value_error
peak_time_error
```

因为需量控制非常关心：

```text
峰值和峰值时刻
```

---

# 70. PV 特殊评价

增加：

```text

```

```text
PV = 0
```

不应让总体误差看起来虚假地很好。

# 192. 最终冻结原则

第一：

```text
Forecast必须基于Standard Point / Metric
不能绑定厂家寄存器
```

第二：

```text
Forecast Target必须有明确Energy Boundary
```

第三：

```text
模型必须版本化
```

第四：

```text
训练数据必须可复现
```

第五：

```text
必须有简单Baseline
```

第六：

```text
复杂模型不优于Baseline
不得上线
```

第七：

```text
Forecast Vintage必须保留
```

第八：

```text
缺失Feature必须Fallback
不能伪造正常预测
```

第九：

```text
Topology / Metric语义变化
必须触发模型Compatibility Review
```

第十：

```text
Forecast永远不直接控制设备
```

最终平台必须能够回答：

```text
这个预测预测的到底是什么边界？

什么时候生成的？

预测未来哪个时间？

用了哪个模型？

用了哪些数据？

当时天气数据是什么版本？

这个模型最近准确率怎么样？

比Yesterday Baseline好吗？

模型坏了以后系统退到哪里？

为什么优化系统采用的是这组预测？

三个月后还能不能复现当时的预测过程？
```

只有这些问题都有明确、可查询、可验证的答案，智慧能源系统的预测能力才具备进入生产和后续优化调度的资格。
