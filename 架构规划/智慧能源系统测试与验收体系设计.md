# 智慧能源系统测试与验收体系设计

## 一、设计目标

智慧能源系统的测试不能只回答：

```text
页面能不能打开？

API 能不能返回 200？

设备数据能不能显示？
```

还必须验证：

```text
设备断网以后数据会不会丢？

重复数据会不会重复入库？

乱序数据是否正确处理？

错误点位是否会污染指标？

Gateway 重启后能否恢复？

告警是否会抖动？

高风险控制是否会被错误执行？

Cloud 故障时 Edge 是否仍然安全？

历史数据补传后指标能否重算？

数据库损坏以后是否真的能够恢复？
```

因此测试目标是验证整个：

```text
Device
 ↓
Edge
 ↓
MQTT
 ↓
IoT
 ↓
Telemetry
 ↓
Metric
 ↓
EMS
 ↓
Alarm
 ↓
Optimization
 ↓
Control
 ↓
Device
```

完整闭环。

最终需要做到：

# 功能正确 + 数据可信 + 性能可控 + 故障可恢复 + 控制安全 + 结果可验收

---

# 二、测试体系总体架构

建议测试体系划分为八层：

```text
1. Unit Test

2. Component Test

3. Integration Test

4. Protocol / Device Test

5. End-to-End Test

6. Performance / Capacity Test

7. Reliability / Security / Safety Test

8. UAT / Production Acceptance
```

可以理解为：

```text
                 Production Acceptance
                         ▲
                         │
                 End-to-End Test
                         ▲
                         │
          Integration / System Test
                         ▲
                         │
              Component Test
                         ▲
                         │
                    Unit Test
```

越靠下：

```text
数量多
执行快
成本低
```

越靠上：

```text
数量少
覆盖完整
更接近真实系统
```

---

# 三、测试原则

整个智慧能源系统建议遵循以下原则。

## 1. 自动化优先

可以自动化的测试：

```text
API

数据处理

Metric

Rule

MQTT

Device Simulator
```

尽量自动化。

---

## 2. 真实设备测试不能完全替代模拟测试

真实设备很重要。

但如果所有测试都依赖：

```text
真实 PCS

真实 BMS

真实电表
```

测试效率会非常低。

因此应该：

```text
Simulator Test
+
Real Device Test
```

结合。

---

## 3. 正向测试和反向测试同等重要

例如控制测试不能只验证：

```text
允许时可以控制成功。
```

更需要验证：

```text
不允许时一定不能执行。
```

---

## 4. 故障属于正常测试场景

必须主动模拟：

```text
网络断开

数据库重启

MQTT故障

设备离线

数据缺失

Gateway断电
```

而不是等生产发生以后再验证。

---

## 5. 验收必须量化

不能只写：

```text
系统性能良好。
```

应该定义：

```text
Telemetry P95 < 5s

Latest API P95 < 300ms

Data Completeness ≥ 99.9%

Command Success Rate ≥ 99%
```

# 一百七十九、最核心的验收思想

智慧能源平台不能只证明：

# “系统能够工作。”

还必须证明：

# “系统在错误、故障、断网、异常数据和错误操作下仍然按照预期工作。”

特别是控制系统：

```text
正常控制成功
```

只是最基础的一条测试。

真正重要的是：

```text
没权限不能控制

Local模式不能控制

设备故障不能控制

安全边界超限不能控制

重复命令不能重复执行

过期命令不能执行

云端错误Edge仍能拒绝
```

这些场景全部通过以后，控制链路才具备真正进入生产的条件。

# 一百八十、最终设计原则

整个测试与验收体系建议坚持十条原则：

**第一，测试覆盖整个 Device → Edge → Cloud → Control 闭环。**

不能只测试 Web 和 API。

**第二，Simulator 是平台基础设施。**

没有大规模设备模拟，很难真正验证智慧能源平台。

**第三，数据正确性优先于页面正确性。**

页面漂亮但能源方向、单位或累计量错误，是严重问题。

**第四，Point、Metric、Alarm 和 Control 都必须有 Golden Test Case。**

保证标准语义长期不被破坏。

**第五，必须主动测试异常和故障。**

断网、重复、乱序、Timeout 都属于正常工业环境场景。

**第六，控制安全采用负向验收。**

“不该执行时绝不执行”与“该执行时成功”同等重要。

**第七，性能测试必须包含持续负载和混合负载。**

不能只跑几分钟峰值 QPS。

**第八，Backup 必须通过 Restore 才算有效。**

备份文件存在不代表灾难恢复能力存在。

**第九，每一个关键需求必须能追溯到测试结果。**

建立 Requirement → Test Case → Result 链路。

**第十，生产上线必须设置硬性 Gate。**

存在 P0/P1 安全、数据、控制问题时不能带病上线。

# 一百八十一、最终结论

智慧能源系统最终应该建立：

```text
Automated Test
+
Device Simulator
+
Hardware Lab
+
Performance Test
+
Failure Injection
+
Security Test
+
Safety Test
+
UAT
```

八类能力。

其中最需要长期投入的是：

```text
设备模拟

数据正确性

故障恢复

控制安全
```

因为这四项决定的不是系统“看起来能不能用”，而是：

# 平台的数据能不能信。

# 系统故障时能不能恢复。

# 现场设备能不能安全控制。

最终测试体系应该保证：

```text
正常情况
系统正确运行

异常情况
系统正确处理

故障情况
系统能够恢复

危险情况
系统能够拒绝
```

做到这四点，智慧能源平台才真正具备生产级交付和验收基础。
