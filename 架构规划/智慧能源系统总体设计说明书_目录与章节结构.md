## 0.4 核心设计原则

1. 标准先于代码。
2. Device 与 Point 分离。
3. Point 与 Metric 分离。
4. Asset 与 Device 分离。
5. 空间拓扑与能源拓扑分离。
6. 厂商协议与平台标准语义分离。
7. 数据质量是数据的一部分。
8. 所有关键控制必须可审计、可验证。
9. Optimization 不直接控制设备。
10. Edge 负责实时、安全和现场自治，Cloud 负责复杂业务与优化。
11. Security、Testing、Observability 是横向能力。
12. 架构复杂度随真实规模逐步演进。

# 第一篇 系统总体设计

# 1. 项目概述

## 1.1 项目背景

说明建设智慧能源系统的业务背景、能源管理现状及存在问题。

建议描述：

- 多能源、多设备、多协议
- 数据分散
- 设备厂家标准不统一
- 能耗无法精细化分析
- 能源成本缺乏实时管理
- 光伏、储能、充电设施独立运行
- 缺少统一预测、优化和控制能力

## 1.2 建设目标

总体目标：

```text
Sense
→ Collect
→ Understand
→ Analyze
→ Predict
→ Optimize
→ Validate
→ Control
→ Verify
→ Improve
```

能力成熟度：

```text
Connected
→ Visible
→ Managed
→ Optimized
→ Autonomous
```

## 1.3 系统定位

智慧能源系统定义：

> 工业 IoT + 能源数据平台 + EMS + 智能决策 + 安全控制平台。

区别于普通 IoT：

- IoT 解决设备连接与采集。
- 智慧能源系统解决能源理解、计算、预测、优化与控制。

## 1.4 建设范围

包含：

- 电力
- 光伏
- 储能
- HVAC
- EV 充电
- 水
- 气
- 蒸汽
- 冷热量
- 碳排放
- 能源费用
- 预测优化

## 1.5 非建设范围

第一阶段建议不包含：

- 完整 VPP
- 强化学习自动控制
- 大规模数字孪生
- 复杂数据湖
- 全量 Kubernetes 微服务化
- 超复杂 AI 平台

## 1.6 角色与用户

建议定义：

- 系统管理员
- 能源管理员
- 运维人员
- 设备工程师
- 财务人员
- 管理层
- 算法工程师
- 安全管理员

# 总结

整个智慧能源系统总体设计可以最终浓缩为三条主线。

## 数据主线

```text
Device
→ Point
→ Telemetry
→ Metric
→ KPI
```

## 能源主线

```text
Grid / PV / ESS / Load
→ Energy Topology
→ Energy Balance
→ Cost / Efficiency / Carbon
```

## 智能控制主线

```text
Observe
→ Analyze
→ Predict
→ Optimize
→ Validate
→ Authorize
→ Control
→ Verify
→ Audit
```

同时由以下横向能力贯穿：

```text
Security
Observability
Testing
Deployment
Data Governance
```

最终平台目标不是简单完成“设备接入 + Dashboard”，而是构建一套稳定的：

> **工业 IoT + 能源数据平台 + EMS + 智能决策 + 安全控制系统。**

总体设计完成以后，下一阶段应从“架构设计”进入“详细设计”，优先固定：

```text
Point Dictionary
Metric Dictionary
Database Physical Model
API Contract
MQTT Contract
Device Template Contract
Control Command Contract
```

这些一旦稳定，Go 后端、React 前端、Edge Gateway 和算法服务就可以在同一套工程语言下并行开发。
