# Maintain a verification skill

On Antigravity, read [`../poteto-mode/references/agy-tools.md`](../poteto-mode/references/agy-tools.md) before following this skill. Remember any updates under `.agents/skills/verify/` MUST be mirrored byte-for-byte to `.claude/skills/verify/` and pass `npm run repo:check`.

A feature map rots the moment the app changes. This skill is the upkeep loop for a project-local verification skill (`verify`) generated by `create-verification-skill`. Cover every feature file from source and exercise every feature live, keeping changes strictly proven.

## Outcomes

Pick one and state which:

- **clean** — every feature received source and live coverage; zero drift found. No branch or PR needed.
- **changed** — one focused PR ships proven doc, harness, or feature-map corrections.
- **blocked** — coverage could not finish or a proven fix could not ship safely; state exact blocker.

## Edit scope

Edit ONLY the verification skill's own files (`.agents/skills/verify/` mirrored to `.claude/skills/verify/`). Never edit product code inside this maintenance pass: if live behavior contradicts the map because product code regressed, report a product defect rather than softening the feature map to pass. Preserve the four-heading feature structure and e2e coverage enforced by `scripts/check-repository-governance.ts`.

## Pass

0. **Locate the target.** Locate `.agents/skills/verify/` (mirrored at `.claude/skills/verify/`). If missing, stop and run `create-verification-skill` first.
1. **Index hygiene.** Read `.agents/skills/verify/features/README.md` and list sibling `.md` files plus `apps/hvac-web/e2e/*.spec.ts`. Fix missing, extra, duplicate, or dead entries cleanly.
2. **Source wave.** Launch one parallel read-only subagent (`TypeName: "research"`, or `"self"` read-only if checking commands) per feature group. Each traces "how does this user-facing feature actually work right now from source?", flags doc/selector/route drift with `file:line` citations, and returns one concise live-verification recipe. Subagents do not drive the browser or edit files.
3. **Reconcile.** Collect every feature summary, combine overlapping recipes into efficient app journeys, spot-check cited drift, and sweep recent UI/route diffs for newly added user-facing screens missing from `verify/features/`.
4. **Live pass.** Required even when source looks clean. The lead coordinator drives Playwright at `1440x900` following `verify/SKILL.md`:
   - Hold three invariants continuously:
     1. Run `npm run verify:doctor` before driving and after any unexpected failure; reset/relaunch wedged sessions rather than retrying blind.
     2. Preserve captured proof in `.scratch/verify/` across every cleanup step and confirm artifacts exist after teardown.
     3. Clean up every process/scratch residue launched by the run when done.
   - Doctor failures caused by skill drift are fixed under edit scope and re-run once before marking `blocked`. Features gated by external prerequisites become `verified-unreachable` only with the exact prerequisite and route attempted (update `Gotchas` if the map omitted that prerequisite).
5. **Triage.** Wrong route/selector/user-POV description -> fix doc drift. Harness helper fails on working app -> fix harness under `verify` rules and re-drive live. Broken product behavior -> log as product bug, do not edit app code here.
6. **Verify & ship.** Mirror `.agents/skills/verify/` <-> `.claude/skills/verify/` cleanly, run `npm run repo:check` + `npm run check`, open one clean PR if **changed**, and store temporary run notes strictly in `.scratch/` (uncommitted).
