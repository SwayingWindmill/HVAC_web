### Investigation

**You own the answer. Plan, route, write.**

Investigation requests are read-only. They deliver a cited explanation or recommendation with tradeoffs, never unsolicited code changes.

1. Route through `how` (and `why` for design rationale, historical thresholds, or regression causes).
2. Checklist throughput note stays one line: `throughput checkpoint: n/a, read-only investigation`.
3. Produce a structured answer (`Overview`, `Key Concepts`, `How It Works`, `Where Things Live`, `Gotchas`) or a concrete tradeoffs comparison table if deciding between options.
4. Apply `unslop` and follow `AGENTS.md` prose rules (concise Chinese plain prose for user/repo replies, real verified paths and line citations only).

Do not open a PR or invoke `architect` unless pivoting to implementation (if pivoting, switch to Bug fix or Feature first).

**Reply:** the investigation findings directly. Push back candidly with evidence if the premise is flawed.
