## 5. UI/UX 审计

严重度：**P0** 功能错误或误导；**P1** 明显影响专业感或效率；**P2** 打磨项。

### 5.1 信息层级与密度

- **P1 KPI 条泛滥**：18 页里有 13 页的第一屏是 4~5 格 MetricGrid，结构一模一样：标签 → 大数字 → 两行灰字。所有页面第一眼都像同一页；真正的主角（系统图、主图、主表）被压到第二位。
- **P1 指标卡底部两行说明文字太满**：每格底部固定两行 12px 灰字，常常是解释性文案，例如“越高越省电”“按设备最近一次上报判断”“确认表示已有人跟进”。这正是 DESIGN.md §6.5 要删的说明文字，结果 20 多张卡的底部都是同样的灰色噪声。
- **P1 同一个数反复出现**：实时运行页的总功率、制冷量、COP、供回水温度在指标卡、系统图、工况卡、快照表里出现 3~4 次；需量页“今日最大需量”和“本月最大需量”在月初并排显示同一个值 230.7。
- **P1 空数据时整屏空白**：告警页在 0 条时有 3 个空状态叠在一起（柱图、设备排行、表），首屏几乎没有信息；工单、通知、节能项目页 60% 以上是白面板。空状态说明了“没有”，但没有给出正向信息，例如“上次告警 x 天前”“近 30 天恢复率”。
- **P2 信息密度偏低**：表格行高约 45~48px，指标卡高约 140px。对值班人员的扫读型工作台，同屏可见行数偏少（设备表 1440×900 下首屏只露 7 行）。

### 5.2 布局与栅格

- **P1 1280 宽度降成单列**：`@5xl/main`（1024px）是 3 列断点，而 1280 下主区约 860px，总览、能耗等页全部堆成单列，页面长约 2000px，像移动端。DESIGN.md 声称支持 1280–1920，实际 1280 体验最差。
- **P1 1920 没有利用宽度**：主区 `max-w 1600` 两侧留白，但卡片内部仍是 1440 的比例。热力图每格被拉成宽长方形，指标页签图横向稀疏。
- **P2 卡片高度不齐**：控制指令页设备卡高低不一（冷机两项设定、其它一项）；优化建议页左右两列底边不齐；总览节能卡中部大段留白。
- **P2 卡片套卡片**：控制指令页“设备卡 → 设定项卡 → 输入组”是三层边框；报告页“灰底卡 → 白底节”是两层。

### 5.3 排版

- **P1 中文字体由回退决定**：`--font-sans` 以 Geist 开头，中文落到 PingFang / 微软雅黑。数字、拉丁字母是 Geist，汉字是雅黑，同一行里字重、x 高度和基线明显不一致（截图里“232.5 kW”和中文标签对比明显）。Windows 下中文 `font-medium` 和 `font-semibold` 几乎没有区别，层级主要靠字号撑。
- **P1 字号阶梯不收敛**：除了 Tailwind 的 xs / sm / base / lg / 2xl / 3xl，还有 `text-[11px]` ×14、`text-[1.75rem]` ×4、`text-[0.8rem]` ×4、`text-[10.4px]` ×2、`text-[10px]` ×1。大数字有 28px（MetricCard）、30px（总览实时卡 `text-3xl`）、18px（FactTile）、14px（页签图）四种，同一种“主数值”在不同卡片里大小不同。
- **P2 h1 24px 和面包屑重复**：Header 面包屑写“能源 › 能耗分析”，正下方 h1 又是“能耗分析”。DESIGN.md 允许这样，但加上描述行“中央机房 · …”，页面顶部 120px 只表达了一件事。
- **P2 描述行承担了太多解释**：例如“服务器投递给你的告警与工单通知；标记已读不会改变告警或工单状态”“同一站点同一时间只核算一项措施；点击查看基线检验与逐日核算”。这些是帮助文本，不是页面身份。

### 5.4 间距

- 主节奏 `gap-6`（24px）统一，这一点做得好。
- **P2** 卡片内边距不统一：MetricCard `px-5 py-4`，shadcn Card `px-6 py-6`，报告页 `px-10`，表格单元 `px-4`。
- **P2** 页头到首块内容 24px，块与块之间也是 24px，节奏没有分组感：所有块等距，无法区分“这三块是一组”。

### 5.5 配色

- **P1 品牌色身份不清**：主按钮、焦点环、排名徽标、“建议 8.2”、节能卡图标用青绿 primary；图表主色是蓝 `chart-1`；`information` 状态也是青绿。青绿既是品牌，又是信息状态，又是“推荐值”，语义重叠；蓝色才是数据主色。整体像“shadcn 默认 + 换了个主色”。
- **P1 语义色挪作他用**：
  - 需量页“本月每日最大需量”用 `destructive` 红色标出最大那天（不是故障）；
  - 分时电价“峰时段”用 warning 琥珀褐色；
  - 诊断规则卡的偏离轨道是粉红底。

  值班人员习惯把红色读成故障，DESIGN.md §6.2 也写了状态色只表达状态。
- **P1 两套状态色**：`StatusBadge`（`components/common`）硬编码 Tailwind 的 emerald / amber / sky / red 色阶，`Status`（`components/ui/status.tsx`）走 `--success` 等 token；工单优先级、诊断严重度、节能措施状态又各自硬编码一套。共 11 个文件约 90 处原生色阶类，深色模式和对比度没法统一管。
- **P2 告警态动画**：`StatusBadge` 的 `alarm` tone 默认 `animate-ping`，持续动画会和“实时刷新不能分散注意力”的原则冲突，也没有尊重 `prefers-reduced-motion`。

### 5.6 视觉层级与图表

- **P0 时间轴按分类处理，压缩了缺失区间**（Missing ≠ Zero / 真实性）：
  - 能耗分析“本月”的 X 轴把 10/6 直接连到 10/12，中间 5 天缺失被压没了，曲线看起来是连续下降再回升；
  - 总览“今日”的 X 轴是 00:00…10:00、22:00、23:00 的分类轴，昨日的 22–23 时贴在今天 10 时旁边；
  - 月度报告 COP 折线跨过缺失日直连。

  这些都会被读成真实趋势。
- **P0 不完整时段当真实值画**：10/6 只有 2.0 kWh（重建前的残段），以正常数据点出现在曲线和表格里，曲线因此“跌到 0”。能耗页“今日”07:00 的 41.4 kWh 同理。需要明确标注“不完整”或剔除。
- **P1 平滑曲线制造假波形**：图表普遍用 monotone 平滑，07:00 的低谷被渲染成一道 U 形弧，暗示了中间并不存在的连续过程。能耗是逐小时累计量，应当用柱状或阶梯线。
- **P1 1920 下总览主图只剩散点**：同一页面 1440 下有连线，1920 下只剩孤立圆点（截图 54），需要在下一阶段复现确认。
- **P2 图例和标题重复**：几乎每张卡都是“标题 + 一整句描述 + 图例”，图例项又和标题同义。
- **P2 深色主题热力图**：空格是近黑描边方块，有值的格子对比过高；深色下 Sheet 和面板分层不明显。

### 5.7 组件一致性

- **P1 表格三种做法**：
  - 设备、实时快照、预测逐时、对标排名、诊断发现用 shadcn `Table` 手写；
  - 告警、能耗明细、通知、集成、系统管理用 `DataTable`；
  - 报告用裸 `table`。

  表头底色、行高、数值对齐、分组行样式各不相同。设备页明明是台账，却没走 DataTable，因此没有排序、列设置和分页。
- **P1 视图切换三种做法**：告警用带计数的分段按钮（ToggleGroup），工单和通知用 Tabs 风格的胶囊，能耗 / 分项 / 对标的期间切换又是另一种胶囊，系统管理用下划线 Tabs。
- **P1 下拉选择两种宽度和风格**：设备页类型 / 状态 Select、集成页站点 Select、报告页月份 Select 的高度和宽度都不一致。
- **P2 “刷新”按钮**：几乎每页右上角都有一个“刷新”，可页面本身已有实时推送或定时刷新。它暗示数据可能不新，却又不告诉用户数据是哪个时间点的（数据时间在别处）。
- **P2 主按钮图标不统一**：生成建议、立即诊断、登记措施、新建工单、登记网关、导出 PDF 各用不同图标，位置有的单独、有的与“刷新”并列。

### 5.8 交互状态

- **P0 系统管理两个 Tab 直接打开就崩溃**：`/system?tab=registry`、`/system?tab=rules` 刷新或直接打开时，`registerUnsavedDraft` 在没有活动站点时抛出 “Protected Site scope is not active”，整页变成英文的 “Something went wrong!”，应用壳也消失了。
- **P1 每次整页加载都有路由守卫报错**：每个站点页首次加载时控制台抛出数次 `RouteAccessError: SITE_DISCOVERY_UNAVAILABLE` / `PLATFORM_UNAVAILABLE`，随后自行恢复。用户看不到，但它说明 beforeLoad 早于运行时就绪，属于脆弱时序。
- **P1 首次加载失败后不会自行恢复**：第一次打开总览时能耗接口返回 503，主图和热力图显示“今日能耗暂不可用”的灰字白卡。卡内没有重试按钮，只能点页头“刷新”或重新加载。
- **P1 启动态是无样式文本**：接口慢时，整屏左上角只有一行衬线体“正在加载系统”，没有品牌、骨架或进度，是全产品最不像商业产品的一屏。
- **P1 高后果操作确认偏弱**：“停止冷水机”的确认弹窗主按钮是品牌青绿“确认下发”，没有危险样式，也没有影响说明（会停多少冷量、依赖设备、预计恢复）和风险等级。弹窗背景是很重的模糊（`backdrop-blur`），整页都看不清。
- **P2 设备 Sheet**：右侧 480px 非模态，没有遮罩，却完全盖住了台账右侧的列（功率、点位、数据时间），和“不影响主表”的约定冲突；Sheet 内是一长列读数，没有分组。
- **P2 表单**：新建工单弹窗的标签和输入之间没有说明和必填提示；聚焦环是双层青绿光晕，比 shadcn 默认更重。
- **P2 键盘与可达性**：Ctrl K、跳到主内容、`aria-live` 实时状态都有，基础不错。表格行的点击区域是整行 `onClick`，需要确认是否可以用键盘聚焦。

### 5.9 响应式

按 2026-10-12 的决定只做桌面端（验收宽度 1440）。实测：

- 1440 正常，无横向滚动（18 页 `scrollWidth` 都没有溢出）；
- 1280 主要页降为单列（P1，见 5.2）；
- 1920 留白偏多、图表稀疏（P1）；
- 侧栏折叠到图标态正常，提示完整。

## 6. 模板感从哪里来

按影响从大到小：

1. **每页同一副骨架**：`h1 + 小标签 + 一行灰字描述 → 4 格 KPI 条 → 2/3 + 1/3 卡片 → 表`。shadcn dashboard-01 的构图被套到了 13 个任务完全不同的页面上，监视、分析、决策、台账、操作台看起来都一样。
2. **KPI 卡的“大数字 + 两行灰字”**：数字 28px、中文标签 14px、底部两行 12px 灰字，几十张卡的形状完全一致，没有主次。
3. **所有内容都装在白色圆角描边卡里**：说明、空状态、只有 3 行字的规则卡也是一张卡。卡片标题下几乎总有一行“这个卡是干什么的”灰字。
4. **shadcn 原样默认值没有被产品化**：Geist + 雅黑回退、`rounded-xl`、`shadow-xs`、ghost 按钮“查看全部 ↗”、Empty 组件的圆角图标框 + 一行字，这些都和 shadcn 示例像素级一致。
5. **品牌只体现在主按钮颜色**：左上角 logo 和青绿主按钮之外，产品没有自己的视觉签名（数据色、数值排版、状态语言、图表风格都是默认值）。
6. **图表全是 Recharts 默认皮肤**：平滑曲线 + 浅色面积渐变 + 底部圆点图例 + 浅灰网格，是最常见的 AI 生成 dashboard 外观。
7. **空状态千篇一律**：圆角方框里一个对勾，下面一行“当前没有……”，同一页最多出现 3 次。
8. **文案的说明腔**：大量“点击设备查看详情”“按站点当地时间统计”“越高越省电”一类句子，读起来像教程，而不是给专业值班人员的工具。

## 8. 必须保留的业务行为 vs 允许重新设计的部分

### 8.1 必须保留（重设计时只能换外观，不能改行为）

**数据真实性与语义**（PRODUCT.md / DESIGN.md §16）

- Offline ≠ Fault，Stale ≠ Offline，Missing ≠ Zero，Unknown ≠ Healthy，ACK ≠ Cleared，Expected ≠ Verified，Approved ≠ Executed，Delivered ≠ Read。
- 运行、连接、新鲜度、质量、诊断、告警、维护、控制保持独立显示，不合成健康分。
- 过期或降级读数置灰并说明（`MetricValue stale`、`ReadingValue`）；缺失显示“暂无数据 / —”，不显示 0。
- 没接入的能力明确写“未接入”；示例数据只在 `HVAC_WEB_FRONTEND_REVIEW=true` 构建出现。
- 费用一律标“估算”，正式电费以结算为准；节能“核算值”和建议“预计值”分开显示（IPMVP 选项 C）。
- 界面不出现 UUID、trace、原始枚举。

**URL 与状态契约**

- `?site=`（站点范围，缺省重定向）、`?inspect=<id>`（对象 Sheet）、`?metric=`、期间参数、`/system?tab=`，这些都可以分享和恢复；e2e 夹具依赖它们。
- 站点切换时有未保存草稿的确认（`DraftConfirmation`），以及切换失败时停止显示的安全行为（`TransitionSurface`）。
- 能力门控（`requireCapabilities` / `requirePlatform` / `requireSite`），没有权限的入口不显示。

**操作安全**

- 控制指令：风险评估 → 中高风险审批 → 下发 → 回执核对；“按建议下发”只生成指令，不会自动执行。
- 告警的确认、认领、搁置，工单状态机（OPEN / IN_PROGRESS / BLOCKED / …），节能措施的登记 → 实施 → 结束时间点。
- 退出、站点切换、草稿丢弃的确认流程。

**实时与可达性**

- Centrifugo 推送 + 快照降级（`LiveIndicator`：实时推送 / 快照）；实时刷新不抢焦点、不重置筛选和分页、不关闭浮层。
- 跳到主内容、Ctrl K、`aria-live` 实时状态、`role=region` / `aria-label`；`data-testid` 和 `data-route-state` 等测试钩子（e2e 依赖）。
- 冷站系统图的工程规则：按设备类别排布，测点读数只标在所在管段，水泵运行时才有流动动画并遵守减少动态效果，图注说明“不代表实际管路”。
- 月度报告的 A4 打印版式和打印时隐藏应用壳。
- 告警排序（严重度优先、其次最近），工单排序（优先级优先、其次最近），总览列表各取前 5。

### 8.2 允许重新设计

- **整体视觉语言**：主色和品牌签名、中性色阶、数据色板、圆角、阴影、边框策略、深色主题。
- **字体**：中文字体选择（可以自托管思源黑体 / HarmonyOS Sans 等，或明确系统字体栈），字号阶梯，数值排版（等宽数字、单位样式）。
- **应用壳**：侧栏分组和条目顺序、平台功能入口、Header 内容、站点切换器形态、命令面板能搜什么。
- **每个页面的构图**：去掉统一的 KPI 条模板，按页面原型（监视 / 分析 / 决策 / 台账 / 操作台 / 文档）重新设计；卡片的使用和分组。
- **组件实现**：合并重复组件（表格、视图切换、状态徽标、指标卡），删除未使用的组件和依赖。
- **图表**：图型（累计量改柱或阶梯）、时间轴（连续时间轴并留出缺口）、配色、图例和提示样式；必要时换图表库（仍要遵守“不制造趋势”）。
- **空、加载、错误状态**的样式和文案；启动屏；错误页。
- **文案**：删除说明腔的辅助文字，统一术语。
- **详情 Sheet 的宽度、分组和是否带遮罩**，在保持 `?inspect=` 契约的前提下自由调整。
- **1280–1920 各宽度下的栅格策略**。
