# 重设计约束

日期：2026-10-13 · 阶段：设计研究（第二阶段）· 配套：[CURRENT-AUDIT.md](CURRENT-AUDIT.md)、[COMPONENT-INVENTORY.md](COMPONENT-INVENTORY.md)、[DESIGN-RESEARCH.md](DESIGN-RESEARCH.md)、[DESIGN-DIRECTIONS.md](DESIGN-DIRECTIONS.md)

无论最后选哪个设计方向，这份文档都适用。它分三部分：

- **必须保留**：业务功能和行为，重设计只能换外观，不能改语义或流程；
- **可以彻底重设计**：视觉和布局；
- **技术与流程边界**：交付时必须遵守。

来源：`PRODUCT.md`（产品事实与安全边界）、`CLAUDE.md`（工程原则）、第一阶段审计 §8。

## 1. 必须保留的业务功能

### 1.1 页面与能力（功能清单）

重设计可以调整页面的位置、分组和构图，但下列能力不能丢，也不能降级为“未接入”。

| 领域 | 必须保留的能力 |
| --- | --- |
| 总览 | 今日用电 / 供冷量 / 综合能效 / 估算电费，以及和昨日同期的对比；冷站实时功率、制冷量、COP、关键温度；主要设备运行与在线台数；未结告警、近 7 天诊断发现、待办工单各取前 5 条，可直达详情；本月已核算节能与最新优化建议；近 7 天逐时用电 |
| 实时运行 | 冷站两环路系统示意（工程规则见 §1.5）；水侧与室内外工况；按系统分组的设备快照；点设备打开详情；实时推送 / 快照降级的状态 |
| 设备 | 按系统分组的设备台账：名称、位置、运行 / 连接状态、功率、点位正常数、未完成工单、数据时间；按名称或位置搜索，按类型、状态筛选；设备详情：当前读数、最近 24 小时趋势（可切换测点）、通信 / 最近数据 / 登记时间 |
| 能耗分析 | 今日 / 近 7 天 / 本月 / 本年；用电、供冷量、综合能效三个指标切换；本期与上期同期对比；期间概况（最高时段、平均、计量质量）；分时电费估算（峰平谷占比、电价时段）；明细表；导出明细 |
| 分项能耗 | 总表与各设备分表的用电和占比；能流（含“未分项”）；设备用电排行；逐时分项用电 |
| 需量分析 | 当前 15 分钟需量（标出进行中）；今日 / 本月最大需量及出现时间；需量电费估算；负荷率；需量曲线（今日与昨日、本月最大参考线、计收峰时段）；本月每日最大需量 |
| 负荷预测 | 预测峰值 / 谷值及时间、未来 24 小时用电、更新时间；实际与预测曲线（含预测区间、“现在”分界）；逐时预测表 |
| 优化建议 | 生成建议；建议内容（当前 → 建议供水温度）、风险等级、预计节电 / 节省 / 室温 / 舒适余量（标“预计”及置信范围）；安全与舒适约束；计算依据（冻结输入）；验证与回退规则；“按建议下发”只生成控制指令 |
| 节能项目 | 登记措施、确认实施时间、结束；基线检验（CV(RMSE)、NMBE、小时覆盖）；逐日核算节电量与节省电费；IPMVP 选项 C 口径说明 |
| 站点对标 | 授权站点按综合能效排名；与整体加权值相比；空调用电、日均、供冷量；每日 COP；未接入的对标维度明确写“未接入” |
| 月度报告 | 选月份；概要、用能与能效、电费构成、节能成效、运行与维护；本月进行中的标注；A4 打印 / 导出 PDF |
| 告警 | 活动 / 未确认 / 已恢复 / 全部视图；严重度优先、其次最近的排序；搜索、严重度筛选、列设置；近 14 天告警分布、告警最多的设备；平均恢复时长；告警详情中的确认、认领、搁置和时间线；从告警建工单 |
| 故障诊断 | 立即诊断；诊断规则说明（阈值、设计值、节流规则）；诊断发现列表（时间、问题、设备、测量值 / 阈值、偏离程度）；发现详情 |
| 工单 | 进行中 / 我负责的 / 已结束 / 全部；按优先级、其次最近排序；待处理 / 处理中 / 受阻 / 我负责的计数；新建工单（标题、优先级、说明）；工单详情中的指派、状态流转和进展 |
| 控制指令 | 按设备的启动 / 停止 / 复位故障；设定值调整（当前值、可设范围、步进）；风险评估与中高风险审批；执行中 / 待核对 / 成功率；指令记录与回执核对 |
| 通知中心 | 未读 / 全部；标记已读（不改变告警或工单状态）；未读计数显示在应用壳 |
| 集成管理 | 按站点列出现场网关；登记网关；接入凭据（接入码只显示一次）；吊销 |
| 系统管理 | 系统概览、用户与角色、站点与租户、资产与点位（模板、导入导出）、数据接入、自动化规则、审计日志、设计系统展示 |
| 应用壳 | 站点切换（带搜索）；全局搜索 Ctrl K（页面和设备）；主题切换（浅 / 深 / 跟随系统）；通知入口；用户菜单与退出；侧栏折叠 |

### 1.2 数据真实性（不可妥协）

1. **不伪造事实**：设备状态、告警、诊断、遥测值、数据质量、权限、控制结果、能流分配、节能量与收益、模型置信度都不能为了构图而编造。示例数据只出现在 `HVAC_WEB_FRONTEND_REVIEW=true` 的评审构建中，并明确标识。
2. **未知不是零**：缺失、未知、不可用、未接入显示为“暂无数据 / — / 未接入 / 暂不可用”，不能显示 0 或“正常”。
3. **状态维度独立**：运行、连接、数据新鲜度、数据质量、诊断、告警、维护、控制分开显示，不合成健康分。以下各对必须区分：
   - Offline ≠ Fault，Stale ≠ Offline；
   - ACK ≠ Cleared，ACK ≠ 目标已实现；
   - Expected ≠ Verified，Approved ≠ Executed，Delivered ≠ Read；
   - 超时 ≠ 确认失败。
4. **过期 / 降级读数**要有视觉区分（目前是置灰 + 说明），不能和新鲜读数长得一样。
5. **估算要标注**：电费一律标“估算”，正式电费以结算为准；节能“核算值”和建议“预计值”分开显示。
6. **时间按站点时区**解释业务日、峰平谷时段和报表周期，并在相关位置标明。
7. **界面不出现**内部 UUID、trace / correlation ID、原始技术枚举、schema / revision 等内部字段。

### 1.3 图表真实性（审计 P0 的约束化）

重设计后的所有图表必须满足：

1. **时间轴连续**：X 轴是真实时间刻度；缺失区间留出空白，不能被压缩或跳过。
2. **缺口不连线**：缺失数据处断开（等价于 Grafana 的 “Connect null values: Never”），除非业务明确规定了可连接的最大间隔。
3. **不完整时段可辨认**：进行中的小时 / 天、残缺区间要用虚线、浅色或标注来区分，不能和完整时段画成一样。
4. **累计量不平滑**：逐时或逐日电量、供冷量用柱状图或阶梯线；瞬时量（功率、温度）用折线时不用平滑插值。
5. **语义色不挪用**：红色、琥珀色、绿色只表达状态。“最大值”“峰时段”这类非状态的强调用中性强调色或标注。
6. **图表要有单位、时间范围和数据质量说明**，并提供可访问的文本或表格替代。

### 1.4 URL 与状态契约

以下 URL 参数可以分享、刷新恢复，e2e 夹具依赖它们，参数名和语义都要保留：

- `?site=<id>`：站点范围。缺省时重定向到第一个可访问站点。
- `?inspect=<id>`：在当前页打开对象详情，不另开详情路由。
- `?metric=`、期间参数：当前指标和期间。
- `/system?tab=`：系统管理的子页。
- 表格的筛选、排序、分页状态：由 `use-data-table` 序列化到 URL 的部分。

其他保留项：

- 站点切换时如有未保存草稿要先确认；切换失败要停止显示，不能显示错站点的数据。
- 能力门控：`requireCapabilities`、`requirePlatform`、`requireSite`。没有权限的入口不显示，访问时给出明确的无权限页面。
- 服务端状态归 TanStack Query，URL 状态归 Router。组件不直接 fetch。

### 1.5 操作安全与工程规则

- **控制指令生命周期**：请求 → 风险评估 → 审批（中高风险）→ 下发 → 设备确认 → 结果核对。界面必须让用户在确认前清楚知道对象、当前状态、目标状态、参数变化和影响范围。
- “按建议下发”只生成指令，不会自动执行。
- 告警的确认、认领、搁置；工单状态机（OPEN / IN_PROGRESS / BLOCKED / …）；节能措施的登记 → 实施 → 结束时间点。
- 退出、站点切换、草稿丢弃、凭据吊销、控制下发都要有确认。
- **冷站系统图的工程规则**：
  - 按设备类别排布（冷却塔 → 冷却水泵 → 冷水机组 → 冷冻水泵 → 建筑负荷）；
  - 测点读数只标在所在管段，不在节点上重复；
  - 水泵运行时才显示流动，并遵守减少动态效果设置；
  - 图注说明“不代表实际管路”。
- 实时刷新不抢焦点、不重置筛选和分页、不关闭用户正在操作的浮层，也不让列表持续跳动。

### 1.6 排序与默认规则

- 告警：严重度优先，其次最近发生。
- 工单：优先级优先，其次最近创建。
- 诊断发现：诊断时间倒序。
- 总览列表各取前 5 条。
- 设备：按系统分组（冷水机组、冷冻水泵、冷却水泵、冷却塔、室内环境、计量、室外环境）。

### 1.7 可达性与测试钩子

- 跳到主内容、Ctrl K、`aria-live` 实时状态、`role=region` 与 `aria-label`、对话框焦点管理。
- 目标 WCAG 2.2 AA：正文对比度 4.5:1，状态不能只靠颜色区分，要配文字、图标或形状。
- 尊重 `prefers-reduced-motion`。
- 所有 `data-testid`、`data-route-state`、`data-business-state` 等测试钩子保留。改动接口调用时同步更新 `e2e/fixtures` 和 `e2e/gateway.ts` 的测试桩。

## 2. 允许彻底重设计的部分

| 范畴 | 可以改什么 | 边界 |
| --- | --- | --- |
| 品牌与色彩 | 主色、中性色阶、数据色板、状态色明度、深色主题；可以不再用青绿 | 状态色只表达状态；正文对比度达 AA |
| 字体 | 中文字体（自托管或系统字体栈）、字号阶梯、字重、数字排版 | 不依赖境外字体服务（DESIGN.md §1） |
| 形状与层级 | 圆角、边框、阴影、分隔线、背景层次 | |
| 应用壳 | 侧栏的分组、顺序、宽度、样式；是否加顶部全局时间 / 站点条；Header 内容；平台功能入口；命令面板的搜索范围 | 站点切换、搜索、通知、主题、用户菜单这些能力保留 |
| 信息架构 | 页面合并或拆分（例如把告警、诊断、工单合成一个“待处理”收件箱，或把能耗 / 分项 / 需量合成一页的多个视图）；导航命名 | §1.1 的能力不能丢；旧 URL 若变更，需同步 e2e 和文档。不加兼容跳转层（CLAUDE.md：不做向后兼容），一次改干净 |
| 页面构图 | 去掉千篇一律的 KPI 条；卡片还是平铺区块；栅格；首屏主角 | |
| 组件实现 | 合并重复组件，删除零引用组件和依赖；重写指标、状态、表格、视图切换、空状态、加载、错误等组件 | 仍基于 shadcn / Radix，见 §3 |
| 图表 | 图型、配色、坐标轴、图例、提示框；可以换图表库或引入 ECharts | 遵守 §1.3 |
| 详情交互 | Sheet 宽度、是否遮罩、内部分组；对象详情可以用侧栏、分栏或页内展开 | `?inspect=` 契约保留 |
| 交互反馈 | 加载骨架、乐观更新、Toast、确认弹窗样式、键盘快捷键（如 Space 预览、J/K 移动） | 不能削弱 §1.5 的确认 |
| 文案 | 标题、描述、按钮、空状态、错误提示；删除说明腔的辅助文字 | 遵守 `docs/product/content-design.md`，中文优先，术语一致 |
| 打印版式 | 月度报告的版式和视觉 | 保留 A4 打印、打印时隐藏应用壳 |

## 3. 技术与流程边界

- **技术栈不变**：React 19、Vite、TypeScript、Tailwind v4、shadcn/ui（Radix，`radix-nova`）、TanStack Router / Query / Table、react-hook-form + zod、Centrifugo。需要新依赖时，优先成熟库，固定版本，并在 `docs/architecture/` 记录采纳理由。
- **只做桌面**：验收宽度 1440，并在 1280 和 1920 下检查。不做移动端；但 1280 不能退化成单列长页。
- **中文优先**：行业缩写（COP、kW、kWh、IPMVP）保留。
- **不做向后兼容**：废弃的组件、样式、路由直接删除，不留兼容层。
- **视觉验收用真实数据**：在 8443 本地环境用真实 owner 数据实际看过。构建通过不算验收。告警、工单这类当前没有数据的页面，用 e2e 夹具或评审构建补看有数据的状态。
- **文档同步**：
  - 用户可见的变化记入 `CHANGELOG.md`，进度记入 `docs/HANDOFF.md`；
  - 方向选定后改写 `DESIGN.md`，解决审计里列出的三处文档和代码冲突；
  - 采纳的外部模式在 `docs/architecture/` 简短记录。
- **门禁**：新增的检查或测试要登记进 `scripts/domain-task-matrix.mjs`。设计 token 的对比度检查（`scripts/test-real-design-tokens.mjs`）随新色板一起更新。
