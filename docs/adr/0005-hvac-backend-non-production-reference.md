# ADR 0005：旧的 NestJS 后端不是平台的一部分

状态：已采纳（2026-07-26）。

## 背景

仓库里曾经有一个 NestJS 写的旧后端 `hvac-backend`，实现过早期的部分功能。Go 平台是重新设计的，身份、登记、遥测、指令、自动化和 AI 都有自己的负责服务。旧后端从没成为正式的数据来源，把它当迁移来源、兜底或架构模板，只会增加复杂度。

## 决定

- 旧后端最多只是一个非正式的行为参照，不是：Go 服务边界、数据模型或部署的模板；正式的接口负责方或请求兜底；身份、权限或数据归属的依据；必须导入数据库或 Redis 数据的迁移来源；控制、调度或指令结果的负责方；正式上线、备份、恢复或灾难恢复的依赖。
- Go 代码不依赖 NestJS 的模块、DTO、表、Redis 键、凭据，也不照搬它直接调 ThingsBoard 的做法。
- 所有对外接口都由 Go 服务负责。接口归属表里不能有旧后端作为负责方或兜底（`npm run ownership:check` 检查）；登记和遥测当前状态的接口都没有退回旧系统的路径。
- 需要历史读数时，由 Go 提供查询，或者明确显示「不可用」，不能悄悄依赖旧后端。
- 去掉旧系统迁移，不等于去掉上线要求：容量、安全、回滚、恢复、租户隔离和指令安全照样必须满足。

旧后端的代码现在已经不在仓库里。
