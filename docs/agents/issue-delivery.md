# 问题单的交付流程

用户在 2026-10-05 要求 #407 及以后的问题单都按这个流程交付。

1. **读清楚要做什么。** 读问题单、上级规格、评论、依赖的单子是否完成、`GLOSSARY.md` 和相关的 ADR。记下从哪个提交开始做；手头已有的无关改动单独提交。已经写成可以直接开工的单子，直接实现，不再重新分诊。
2. **参照外部项目时先读源码。** 决定要借鉴外部项目时，先看固定版本的官方源码、测试和文档，按 `AGENTS.md` 记下采纳、改造或拒绝了什么。产品文档和设计文档比旧的实现更有说服力。
3. **一个行为一个行为地做。** 在规格约定好的公开接口上，每个行为先写一个会失败的测试，再写代码让它通过；每一步都要打通真实的产品路径，例如从页面一直到数据库。测试只保护当前的接口约定、安全边界、数据规则和出现过的回归；用已有的 `scripts/domain-task-matrix.mjs`，不新增重复的门禁。
4. **在真实环境里验收。** 在 WSL 里、在主目录上构建、测试和运行。改了网页的，要在真实数据和 1440px 桌面宽度下用浏览器看过；用录制数据跑的测试和真实运行的结果分开记录。
5. **审查后再交付。** 对起点以来的改动做两方面审查：是否符合仓库的规范，是否符合规格。改完发现的问题，再开关联问题单的 PR，逐条列出验收的证据和还没做到的地方。验收没完成，不关问题单。

这个流程本身不授权发消息、重置数据或合并 PR；这些仍然按当前会话里用户的授权和 `AGENTS.md` 来。
