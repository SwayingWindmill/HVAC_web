# 问题单的交付流程

每张问题单按这五步交付，每一步做到「完成」那一句才进下一步。

1. **读清楚要做什么。** 读问题单、上级规格、评论、依赖的单子、`GLOSSARY.md` 和相关的 ADR；记下从哪个提交开始做，手头无关的改动单独提交。已经写成可以直接开工的单子，直接实现。
   完成：能用 `GLOSSARY.md` 的词说出要交付的每个行为和它的验收方式。
2. **参照外部项目时先读源码。** 借鉴外部项目时，看固定版本的官方源码、测试和文档，按 `AGENTS.md` 在 `docs/architecture/` 里记下采纳、改造或拒绝了什么。
   完成：每个借来的设计都有固定版本的出处和取舍理由。
3. **一个行为一个行为地做。** 在规格约定的公开接口上，每个行为先写一个会失败的测试，再写代码让它通过；每一步都打通真实的产品路径，例如从页面一直到数据库。
   完成：规格里的每个行为都有一个先失败、后通过的测试，并且在产品里能走通。
4. **在真实环境里验收。** 在 WSL 里构建、测试、运行。改了网页的，在真实数据和 1440px 宽度下用浏览器看过；录制数据的测试结果和真实运行的结果分开记录。
   完成：每条验收标准都有真实环境里的证据。
5. **审查后交付。** 对起点以来的改动做两方面审查（`code-review` 技能：是否符合仓库规范、是否符合规格），改完再开关联问题单的 PR，列出验收证据和还没做到的地方。
   完成：两方面审查的问题都已处理或写进 PR；验收全部完成后才关问题单。

发消息、重置数据、合并 PR 仍要当前会话里用户的授权。
