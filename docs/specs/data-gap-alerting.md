# 读数中断：及时提醒和页面上的数据缺口

问题单 #795（子单 #796–#800）。依赖点位数据质量（`docs/specs/telemetry-data-quality.md`）。

2026-11-08 16:13（北京时间）起，松雅轩网关不再上传 UID 2 电表自己的功率、累计电量和运行状态，也不再上传它算出来的「空调总电表」。复制来的温度还在往 UID 2 上送。平台当时：

- UID 2 的「读数长时间没有更新」从 11-01 起一直开着没恢复（它盯着整台设备的所有点位，有一个点位一直没回来，就恢复不了），所以 11-08 没有新告警；
- 「空调总电表读数长时间没有更新」是警告，不推送，没人看到；
- UID 2 因为还收到复制的温度，一直显示在线；总表的在线状态停在 11-08，没有人再去算它；
- 全站用电只读网关加出来的总表，总表一停，总览、能耗分析、报告全部显示「—」，也不说为什么。

四天后才有人发现。下面每一条都对着这四件事中的一件（业务名词见 `GLOSSARY.md`「读数中断」「关键点位」「合成总表」「跨缺口电量」「数据缺口」）。

## 定下来的做法

| 问题 | 状态 | 做法 |
| --- | --- | --- |
| 中断按什么粒度判断 | 已实现（#796） | 每个关键点位（站点文件里点位写 `"critical": true`）一条规则：15 分钟（`ageSeconds: 900`）没有设备自己的新读数就产生「<设备>：<点位>读数中断」，读数回来就恢复。不是关键点位的仍按设备合成一条「<设备>读数长时间没有更新」，但只看设备自己的点位，不看复制来的、停用的。这样一个长期没回来的点位只占它自己那一条，不会盖住别的点位新的中断 |
| 级别和推送 | 已实现（#796） | 关键点位的读数中断是「重要」（`MAJOR`），按现有规则推到小程序微信提醒；其余是「警告」，不实时推送 |
| 长期没处理 | 已实现（#800） | 每天站点时间 8 点汇总还开着的读数中断告警（哪块表、从什么时候起、开了几天），走每日运行结论同一条推送；超过 24 小时没人确认的读数中断升一级（警告升重要，重要升紧急），升级时按新的级别再推一次 |
| 在线怎么算 | 已实现（#797） | 复制来的读数不再算这台设备的在线信号；没有自有启用点位的设备不判断在线（`NOT_APPLICABLE`）。遥测每分钟复查一次在线状态，超过离线时限没有信号的设备变成离线并推送状态变化，不再停在最后一次收到读数时的结论 |
| 全站用电 | 已实现（#798） | 站点文件的能耗写 `"totalMeter": {"kind": "sum-of-sub-meters"}` 时，平台用合成总表作为站点总量：各分表电量相加。某个小时有分表缺读数时，这个小时照样显示已有分表的和，同时标明「不完整，缺 <表名>」，缺的部分不当成 0 也不估算。网关算的总表保留为一块普通的表，只用来核对 |
| 恢复后的跨缺口电量 | 已实现（#798） | 累计读数前后两条相隔超过 1 小时，这一段电量记为跨缺口电量：总量里照算，但不摊到中间每个小时，也不放进恢复后的第一个小时；逐时图、小时能效和每日用电曲线不显示它，月度和报告里单列「跨缺口电量」 |
| 页面上怎么说 | 已实现（#799） | 平台网关新增 `GET /api/v1/sites/{siteId}/data-gaps`，列出当前读数中断的关键点位（设备、点位、从什么时候起、影响的站点数字）。总览、能耗分析、实时运行和能源报告用同一个提示条，例如「D 机组电表 11/8 16:13 起没有读数，今日空调用电不含这台」，点开到集成管理的电表数据核对 |

## 不做

- 网页上手工补录或改写中断期间的读数。
- 按功率积分估算中断期间的电量（以后要做也走单独的修补流程）。
- 企业微信自建应用发设备告警（ADR 0026）：要企业微信的企业 ID、应用凭据，拿到后另做。

## 验收

1. 告警模块测试：复现 11-08——同一台电表的复制温度照常到达、自己的累计电量 15 分钟没来，产生一条「重要」的读数中断；同一台设备另一个点位早已中断时，新的中断照样产生并推送；读数回来后恢复。
2. 遥测测试：只收到复制读数的设备，超过离线时限后变成离线；完全没有信号的设备，定时复查后变成离线。
3. 能耗测试：合成总表等于各分表之和；缺一块分表的小时标不完整并列出缺的表；前后相隔 3 天的累计读数生成一段跨缺口电量，不进任何一个小时。
4. 浏览器测试（1440px）：总览在总表中断时照常显示各分表之和，并显示数据缺口提示；点开到电表数据核对。
5. 服务器：部署并对松雅轩 `apply` 后，用 11-08 起中断的 UID 2 验证——数据缺口接口列出它，总览显示 A、B、C 三台之和并标明缺 UID 2 对应的机组。
