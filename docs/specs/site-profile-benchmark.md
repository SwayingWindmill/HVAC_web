# 站点档案与单位面积用电对标

问题单 #485 后半部分。2026-10-13 和用户确认（全部按建议），两版都已上线。

站点对标最初只按冷站综合能效（COP）排名。规模不同的站点要比较用电水平，需要建筑面积；比较气候不同的站点，需要知道气候区。两者都由注册中心作为站点档案管理。

## 第一版：站点档案和单位面积用电

| 问题 | 做法 |
| --- | --- |
| 范围 | 站点档案（建筑面积、气候区）和单位面积用电对标；气候修正见第二版；行业基准仍为「未接入」 |
| 面积 | 只记建筑面积（m²），可不填；GB/T 51161 的单位面积能耗按建筑面积计算 |
| 气候区 | GB 50176 五个热工分区之一（严寒、寒冷、夏热冬冷、夏热冬暖、温和），可不填；只用于展示，气候差异用第二版的度日数修正 |
| 对标页 | 新增单位面积用电一列（期间空调用电 ÷ 建筑面积，kWh/m²），建筑面积以小字显示在同一格，气候区以小字显示在站点名下；排名可在「按综合能效」与「按单位面积用电」之间切换，默认按综合能效；没有建筑面积的站点不参与按单位面积用电的排名 |
| 行业基准 | 继续显示「未接入」，不编造数字；有可信来源（如地方公共建筑能耗限额标准）时再接入 |
| 编辑 | 沿用系统管理 → 注册中心的站点表单与权限（`site.write`），不新增权限 |
| 本地种子 | 两个模拟站点填示例档案：站点 A 32,000 m²、夏热冬冷；站点 B 18,000 m²、夏热冬暖；种子只在两项都为空时写入，不覆盖页面上的修改 |

### 怎么运作

1. `core_registry.sites` 新增 `floor_area_m2`（> 0）与 `climate_zone`（五个取值之一），都可为空。
2. 站点读取（`Site`）总是带这两个字段，未登记时为 `null`。站点写入（`SiteMutation`）是整体替换：不带这两个字段即清空。
3. 单位面积用电 = 所选期间（近 7 天或本月）的空调用电 ÷ 建筑面积（面积按 GB/T 51161 的算法，但这个数本身不是该标准里的建筑能耗指标）；用电或面积缺失时不计算。按单位面积用电排名时数值越低越靠前。

## 第二版：按度日修正气候差异

| 问题 | 做法 |
| --- | --- |
| 气象数据 | 用站点现场气象站的室外干球温度（遥测历史，注册中心里 `weather.ambient_dry_bulb_temperature` 点位）；站点没有该点位时气候修正显示「未接入」；不接外部气象服务 |
| 度日数 | 冷却度日 CDD26 = Σ max(0, 日平均干球温度 − 26 °C)，26 °C 是国内空调度日数的常用基准；不折算到典型气象年（需要外部典型年数据） |
| 计算位置 | 对标页按天读取气象站干球温度的平均值（设备历史聚合，`DAY`），在页面模型里计算；以后报告或节能统计也要用度日数时，再改成指标引擎每天算的指标 |
| 对标页 | 新增「单位度日用电」一列（kWh/m²·℃·d），同一格以小字显示期间度日数；排名可切换为「按度日修正用电」，越低越好 |
| 本地数据 | 历史回放同时回放气象站的干球温度（按每个站点的日场景生成），并补回放 08-25 至 10-06 的温度（本地已回放的全部区间） |

### 怎么运作

1. 单位度日用电 = 期间内既有空调用电又有日平均温度的那些天的用电 ÷ 建筑面积 ÷ 这些天的度日数之和。
2. 没有建筑面积、没有气象站点位、或这些天的度日数为 0 时不计算，也不参与「按度日修正用电」的排名；格内分别显示「未登记建筑面积」「未接入气象站」「无供冷度日」。
3. 某个站点的气温读取失败时，该站点这一格显示「气温暂不可用」，不参与按度日修正用电的排名；其他站点和其余对标照常显示。
