# 站点档案与单位面积用电对标

Issue #485 后半部分。2026-10-13 与用户确认（全部按建议）。本文是实现契约。

站点对标第一版只按冷站综合能效（COP）排名。规模不同的站点要比较用电水平，需要建筑面积；比较气候不同的站点，需要知道气候区。两者都由注册中心作为站点档案管理。

## 决定

| 决策 | 结论 |
| --- | --- |
| 范围 | 只做站点档案（建筑面积、气候区）和单位面积用电对标；气候修正与行业基准仍为「未接入」 |
| 面积 | 只记建筑面积（m²），可不填；GB/T 51161 的单位面积能耗按建筑面积计算 |
| 气候区 | GB 50176 五个热工分区之一（严寒、寒冷、夏热冬冷、夏热冬暖、温和），可不填；本轮只用于展示，不做气候修正（需要逐日气象数据，平台目前没有气象数据的 owner） |
| 对标页 | 新增气候区、建筑面积和单位面积用电（期间空调用电 ÷ 建筑面积，kWh/m²）；排名可在「按综合能效」与「按单位面积用电」之间切换，默认按综合能效；没有建筑面积的站点不参与按单位面积用电的排名 |
| 行业基准 | 继续显示「未接入」，不编造数字；有可信来源（如地方公共建筑能耗限额标准）时再接入 |
| 编辑 | 沿用系统管理 → 注册中心的站点表单与权限（`site.write`），不新增权限 |
| 本地种子 | 两个模拟站点填示例档案：站点 A 32,000 m²、夏热冬冷；站点 B 18,000 m²、夏热冬暖；种子只在档案为空时写入，不覆盖页面上的修改 |

## 行为

1. `core_registry.sites` 新增 `floor_area_m2`（> 0）与 `climate_zone`（五个取值之一），都可为空。
2. 站点读取（`Site`）总是带这两个字段，未登记时为 `null`。站点写入（`SiteMutation`）是整体替换：不带这两个字段即清空。
3. 单位面积用电 = 所选期间（近 7 天或本月）的空调用电 ÷ 建筑面积；用电或面积缺失时不计算。按单位面积用电排名时数值越低越靠前。
