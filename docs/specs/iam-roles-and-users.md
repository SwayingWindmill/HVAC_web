# 角色指派与用户管理

问题单 #537。2026-10-14 和用户确认，已上线。参照项目的取舍见 `docs/architecture/iam-rbac-source-review-2026-10-14.md`，模型决定见 ADR 0022。

## 以前的问题

- 给一个人开通一个站点，要往六张表里各写一份动作清单：`site_bindings`、`telemetry_scope_bindings`、`telemetry_key_bindings`（每个点位一行）、`alarm_permissions`、`work_order_permissions`、`command_permissions`（每台设备 × 每种指令一行）。每新增一台设备或一个点位，都要给所有人补授权。
- 系统管理里的「用户与角色」只列出当前登录的人。新建账号、重置密码只能在服务器上跑 `identity-admin`，授权只能导入 JSON 清单（`identity-reconciler`）或手写 SQL。

## 定下来的做法

| 问题 | 做法 |
| --- | --- |
| 权限模型 | 角色是一组权限（capability）；角色指派是「人 × 角色 × 范围」，范围是整个租户（含以后新增的站点）或一个站点。权限只做加法。显式拒绝（`explicit_denies`）保留但不在界面上出现 |
| 角色 | 4 个内置角色，内容随迁移发布，租户不能修改：管理员、运维主管、运维人员、只读。暂不做自定义角色 |
| 管理员范围 | 管理员只能指派到整个租户；其余角色可以指派到整个租户或单个站点 |
| 唯一的授权记录 | 删除上面六张按领域划分的权限表。资产、遥测、告警、工单、指令、分析六类判定都只读角色指派 |
| 遥测粒度 | 按站点授权，不再按设备和点位授权 |
| 指令 | 角色给出「可下发」和「可审批」两类指令的风险上限（低/中/高/紧急），对站点内所有设备、所有指令类型生效 |
| 工单指派给人 | 被指派的人在该站点有「开始工单」权限即可，不再需要逐人登记的指派目标。指派给班组仍按 `work_order_ownership_targets` |
| 开通用户 | 管理员在页面上新建用户并直接设定密码，用户可以一直使用这个密码 |
| 密码 | 至少 8 位，最长 512 位，不要求字符组合，不强制定期更换；拒绝与用户名相同的密码和常见弱密码 |
| 两步验证 | 用户管理不再要求最近一次两步验证 |
| 改自己的密码 | 用户在右上角菜单里修改自己的密码，需要输入当前密码 |
| 停用 | 停用后立即失去所有权限（租户成员身份暂停）并且不能再登录（账号停用），已登录的会话在下一次请求时失效 |
| 部署 | 用户管理由 energy-api 在进程内调用 identity-service 的管理包，使用已有的 `identity_admin` 数据库角色；不新增服务、端口或证书 |

## 怎么运作

1. `iam.role_templates.tenant_id` 可为空，为空的是内置角色，按 `role_key` 唯一；租户自己的角色模板（目前只给后台服务用，例如 `energy-projection`）照旧。
2. `iam.role_bindings` 新增 `site_id`（可为空，空表示整个租户），唯一键为（租户、人、角色、站点），空站点视为同一个值。
3. 只认本组织的站点：指派里写了组织以外的站点，不产生任何权限。权限 *c* 在站点 *s* 生效，当且仅当：人和租户成员身份都有效；存在一条有效的指派，其角色包含 *c*，范围是整个租户或 *s*；且没有覆盖 *s* 的显式拒绝。租户级权限（`Action.TenantScoped()`、`iam.admin`、`api-credential.manage`、`session.revoke`、`audit.read`、`rule.manage`、`template.manage`）只由整租户的指派给出。
4. 遥测判定要求目标设备所属站点上有对应的遥测权限；不再检查设备和点位级授权。
5. 指令判定：权限名为 `command.submit.<风险>` 或 `command.approve.<风险>`，风险取 `low`、`medium`、`high`、`critical`。判定结果的风险上限取该站点上已授予的最高一级；设备必须属于请求中的站点。
6. 当前用户的权限列表（`principal/current`）是各站点生效权限的并集。
7. 管理接口（网关 `/api/v1/iam/...`，要求 `iam.admin`）：
   - 列出租户成员：显示名、用户名、邮箱、状态、最近登录、角色指派。
   - 新建用户：用户名、显示名、邮箱、密码、至少一条角色指派。用户名已存在时拒绝，不接管已有账号（2026-10-14 代码审查后改定：接管会改动别的组织的账号）。角色和范围在创建账号之前校验。
   - 修改资料、指派或撤销角色、重置密码、停用与启用。重置密码不能用于自己，自己的密码只能用当前密码修改。
   - IAM 的每次修改递增租户授权修订号并写 IAM 审计；身份目录的修改（密码、资料、启用停用）写身份安全审计，并记下操作的管理员。
8. 不能停用自己，也不能撤销自己最后一条管理员指派。
9. `POST /api/v1/me/password`：当前密码正确且新密码符合规则时更新密码；输错计入现有的登录失败锁定。
10. 本地种子与验收脚本只通过角色指派授权：本地管理员是整租户的管理员，模拟器和验收用的后台服务用租户自己的角色模板。
