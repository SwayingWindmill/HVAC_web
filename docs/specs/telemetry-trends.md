# 历史趋势：多点位同步曲线与排障跳转

问题单 #766（路线图 #757，决策单 #758、#759）。2026-11-11 已实现（PR #772）。

参照项目一手源码比对（ThingsBoard `v4.4`、OpenEMS `2026.9.0`、Grafana `v13.3.1`、MyEMS `v6.9.0`）见 `docs/architecture/telemetry-trends-source-review-2026-11-11.md`。页面视觉与三级信息分层基线见 Figma v3 精简分层版 `01 · 历史趋势`（`https://www.figma.com/design/6niU3GeCn8iim5sAwF2XRR?node-id=1-18`）。

以前排查一次跳闸或供水温度偏高，只能去「实时运行」看近 6 小时固定小图，或点开某一台「设备」抽屉看最近 24 小时每小时均值；既不能把冷站总功率、供回水温度、各冷机出水温度、水泵流量和启停状态放在同一根时间轴上对齐看，也看不清 15 分钟以内的短时跳变，断联缺数的时段还会在折线图上被直接连成斜线。

## 定下来的做法

| 问题 | 做法 |
| --- | --- |
| 谁提供历史读数 | 继续由遥测模块负责，页面按设备分组并发调用 `device-series:aggregate`（校验 `telemetry.history.read` 和站点范围）；不新增跨模块聚合服务，也不开放秒级原始值接口 |
| 时间跨度与聚合粒度 | 新增 `MINUTE`（`1 分钟`）和 `FIVE_MINUTE`（`5 分钟`）两档聚合。默认档位：`1 小时 → 1 分钟`（60 桶）、`6 小时 → 5 分钟`（72 桶）、`今日`（站点本地零点至今）按已过时长自动取 `1 分钟`（不超过 2 小时）/ `5 分钟`（2 至 8 小时）/ `15 分钟`（超过 8 小时）、`7 天 → 1 小时`（168 桶），并提供 `自定义` 起止时段选择器。`1 分钟` / `5 分钟` 单点位单次最多 **720 桶**，`15 分钟` 及以上保留单点位最多 **1000 桶**（兼容用电负荷与月报 10 天分块拉取），同屏最多选 **8 个点位**，单设备单次总桶数 `点位数 × 时段数 <= 5760` |
| 设定值与运行状态 | 数值型的遥测点位与数值型的设定值点位（`SETTING`）返回数值桶（均值、最小值、最大值、样本数）；状态型点位（`STATE`）及登记为字符串或布尔型的遥测/设定点位返回含 `stateCounts` 的离散状态计数桶（页面按桶内频次最高状态着色并按 `RUNNING` 样本占比计算运行比例），修掉松雅轩 `*.run_state` 聚合返回空桶的问题 |
| 缺数留白 | 前端按起止时间、站点时区和聚合粒度生成完整时间槽，没读数的槽位填 `null`（绝不填 `0`），关闭跨空值连线；同步修复「实时运行」和「设备」详情抽屉在断联时把首尾连成斜线的问题 |
| 怎么分栏展示 | 连续模拟量按物理单位自动拆成上下对齐的独立分栏（如 `kW` 一栏、`°C` 一栏、`m³/h` 一栏，每栏只用一个纵轴），画均值实线 + 最小至最大值浅色包络带，设定值画 `stepAfter` 阶梯虚线；离散运行状态单独放在底部紧凑的「设备启停状态」条；事件窄轨、模拟量曲线与启停状态条共用统一像素绘图边界、毫秒数值时间轴与双向同步光标 |
| 内置预设与 URL | 不建自定义视图数据库表。按当前站点实际处于启用状态的点位动态推导最多 4 组预设：① `冷站功率与供回水`（默认首屏）、② `各冷机运行对比`、③ `水泵流量与温差`、④ `室外环境与供冷负荷`；缺对应点位的预设不生成，预设内未接入的参考点位标「未接入」。点位选择器勾选后点「应用」生效，全部筛选状态编码进 URL 查询参数，复制链接即可分享 |
| 同比与统计表 | 支持勾选「对比昨日同时段」（跨度超过 1 天时为「对比上周同时段」）虚线参考；右上角支持 `[曲线 \| 统计表]` 同页切换，统计表列出最新值、平均值、最小值及发生时刻、最大值及发生时刻、有效覆盖率 |
| 告警与控制指令叠加 | 告警列表接口 `GET /api/v1/alarms` 新增向后兼容的可选参数 `activeFrom` / `activeTo`（返回 `首次发生时间 <= activeTo` 且 `未恢复 或 恢复时间 >= activeFrom` 的交集告警）；控制指令复用 `GET /api/v1/commands`（校验 `site.read` 站点可见性）。页面提供开关按真实发生时刻叠加所选设备的告警浅色区间与控制指令竖线，时间轴窄轨对邻近事件做折叠，点开告警事件可查看详情或带入趋势时段与排查点位创建工单；无对应读取权限时平滑禁用开关 |
| 跨页面排障入口 | 在「告警」详情抽屉和「诊断」结论详情增加「查看当时趋势」，点击后携带故障前后时间窗、关联设备点位与来源标识跳入 `/operations/trends`，顶部展示简洁来源提示条 |
| 不做 | 自定义视图落库、人工手写图上批注表、低于 1 分钟的秒级原始值拉取、CSV/PDF 导出 |

## 验收与测试接缝

1. **后端遥测聚合与告警查询接缝（Go 测试）**：
   - `device-series:aggregate` 支持 `MINUTE` 与 `FIVE_MINUTE`；`1 分钟`/`5 分钟` 单点位超过 720 桶或任意粒度总桶数 `点位数 × 时段数 > 5760` 在参数校验阶段拒绝，同设备 8 点位 × 360 桶正常返回；`SETTING` 数值点位返回数值桶，登记为字符串或布尔型的运行状态点位返回含 `stateCounts` 的状态桶；无权限明确拒绝。
   - `GET /api/v1/alarms?activeFrom=&activeTo=` 准确命中窗口前触发且跨越窗口的长告警、窗口内触发告警，排除窗口外告警。
2. **前端趋势模型纯函数接缝（`npm run web:model:test`）**：
   - 验证模拟冷站与松雅轩不同启用点位下的动态预设生成、完整时间槽补 `null` 断线、按物理单位自动分栏、同比时间平移对齐、统计表极值与覆盖率计算。
3. **浏览器 1440px 端到端与真实环境验收（`npm run web:e2e` + 真实数据）**：
   - 验证侧栏进入默认首屏（L1 轻文字、无英文点位编码堆砌）、切换时间窗与 `1 分钟` 粒度、勾选对比昨日、切换 `[曲线 | 统计表]`、底部设备启停状态同步光标，以及从告警详情点「查看当时趋势」跳入并显示告警区间色带。
