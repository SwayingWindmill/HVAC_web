# AI 运维助手第一版：能耗异常解释

2026-10-16 上线，已在松雅轩验收（见下面「验收」）。之后加的功能见文末。设计稿：https://claude.ai/artifact/82pT6p4fGqPp2cVh5Q9Vtu 。运行方式和边界：ADR 0014（pi）、ADR 0023（Cube）。

## 目标

值班人员在「能耗分析」上看到某天、某个时段用电偏高，点「解释」或在右侧助手面板里提问，助手读取平台数据，给出带依据的结论：多出的电在什么时段、哪台设备，供冷量和能效是否同步变化，以及数据不足以下结论的地方。助手只读数据，不操作设备。

## 范围

| 项目 | 第一版 |
|---|---|
| 入口 | 页头「AI 助手」按钮开关右侧面板（420px，推开内容；打开时左侧导航收成图标，1440 宽度下内容区约 960px，关闭后恢复）；能耗分析：图上点选一根柱子（默认用电最高的一根）后点标题栏的「解释」，或明细表某一行的「解释」，打开面板并把那一时段的日期、用电量和对比值写进预填问题；进行中的时段不提供「解释」 |
| 面板 | assistant-ui（`ExternalStoreRuntime` 接我们的会话事件），组件复制进仓库、改用设计系统颜色和中文：消息流、逐字输出、查询过程（默认折叠）、结论卡、接着问、补充信息提问、停止 |
| 结论卡 | 关键数字（`keyFigures`，最多 4 个）、局限说明、依据标签（按依据来自的工具点回能耗分析或系统与设备页面，打开页面默认期间）；项目自己的组件。结论本身写在回答正文里（#591 起卡片上不再重复一句结论） |
| 会话 | 每个站点的会话由服务端保存；面板打开时继续当前站点最近的会话，「新对话」开新的；第一版不做历史列表 |
| 模型 | DeepSeek（`deepseek-flash`），服务器配置 `DEEPSEEK_API_KEY` 后启用 |

## 工具

已有：资产清单、当前读数、能耗曲线（站点总表）、两个时段的能耗对比。第一版新增：

| 工具 | 说明 | 数据来源 |
|---|---|---|
| 分设备用电 | 一个时段内各设备分表的用电（逐时 / 逐日 / 合计），只含有分表的设备 | 查询服务 Energy Series，`breakdown: device`（经 Cube） |
| 设备清单（`equipment_list`） | 各设备的名称、所属机组和在用点位，其他工具据此传设备和点位 | 资产模型（Registry `asset-model.read`） |
| 供冷量（`energyType: cooling`） | 能耗曲线和时段对比可改查供冷量，用于算能效 | 查询服务 Energy Series |
| 设备读数历史（`telemetry_query_history`） | 一台设备最多 8 个点位在一个时段内的逐刻钟 / 逐时 / 逐日平均、最小、最大值（累计量给增量），例如室外温度、机组功率；点位数 × 时段数超过单次结果上限时直接拒绝，提示缩短范围或改用更粗的粒度 | 查询服务设备历史聚合（`telemetry_history.observations`） |

每次调用前，网关先按提问人对这个站点的权限，换一张数据负责方认的授权；新增的设备历史授权走 `telemetry.history.read`。时间范围最长一个月，单次结果的条数和字节数受每次回答的预算限制。

## 回答要求（系统提示）

- 用中文，面向值班人员，用词按设计系统的日常用语；先给结论，再给依据，数字带单位。
- 只依据工具返回的数据；数据缺失、可疑或不覆盖问题时，写进局限说明，不推测成事实。
- 站点由服务端固定，模型不能改；每次回答开始时服务读一次站点名称和时区，系统提示写明站点和站点本地的当前时间（带星期），模型据此换算日期（#593）。页面上下文（页面和期间）由「解释」写进预填问题，第一版不另设字段。
- 以 `investigation_complete` 结束（关键数字、依据、局限，`recommendedNext` 写成最多 3 个可以接着问的问题，面板显示为「接着问」），或用 `investigation_request_input` 向值班人员提一个问题。

## 验收

1. 在松雅轩真实数据上问「10/15 为什么比上周同日多用电？」：回答指出多出约 762 kWh、主要在晚市 18–21 点、B 机组当天开机、供冷量同步增加、能效接近；没有室外温度时说明局限。
2. 从能耗分析 10/15 柱上的「解释」进入，问题和期间已预填；回答过程逐字显示，查询步骤可展开，结论卡依据可点回能耗分析。
3. 选择不在授权范围内的站点或设备的请求被网关拒绝，助手如实说明读不到。
4. 浏览器测试、服务测试、网关测试全部通过；1440 宽度下用真实数据看过面板。
