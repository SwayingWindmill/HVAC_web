# 报告快照与年度报告

Issue #483 第二阶段。2026-10-13 与用户逐条确认（全部按建议，Q2 选方案 A）。本文是实现契约。

第一阶段的月度报告在浏览器里按需从各数据源现算，记录变了，已结束月份的报告也跟着变。第二阶段为已结束的月份生成并保存不再改变的快照，并新增年度报告。

参考平台比对见 `docs/architecture/report-snapshots-source-review-2026-10-13.md`。

## 决定

| 决策 | 结论 |
| --- | --- |
| 生成者 | 新服务 `report-service`（Go）：后台进程领取 `REPORT_GENERATE` 定时任务，生成快照存入注册中心库 `core_registry.report_snapshots`（按租户、站点行级隔离）；内部 HTTP 接口供网关读取 |
| 快照内容 | 月度用电、供冷、综合能效、分时电度电费；峰平谷各时段用电与电费；逐日用电、供冷、能效、电度电费；诊断发现数量（按类型）；当月已核算的节电量与节省电费。需量电费、最大需量、告警、工单不进快照（告警、工单属于独立的数据库），月报页现算并标「未存档」 |
| 生成时间与版本 | 每月 1 日 03:00（站点时区）生成上月快照。快照不再修改；需要重算时生成新版本，旧版本保留，页面读最新版本。第一版没有页面上的「重新生成」，由运维脚本补发任务，不新增权限 |
| 月报页 | 已结束且有快照的月份读快照，标「已存档 · 生成于 X」，与上月的对比用上月的快照，上月没有快照时标「上月未存档」，读取失败时标「上月存档暂不可用」。当月和没有快照的月份照旧现算，标「实时」，与上月同期现算对比 |
| 年度报告 | 报告页新增「年度」视图：1 月至站点当前月份（往年为 12 个月）逐月用电、供冷、能效、电度电费，全年合计；未来月份没有数据，不列出。已存档月份用快照，当月和未存档月份现算并标注。另合计已存档月份的节能核算与诊断发现数（快照内容，不现算）。PDF 导出与月报相同 |
| 不完整月份 | 快照记录有计量数据的天数，页面显示「覆盖 X / N 天」，不补数、不外推 |

## 行为

1. 数据来源与月报页现算一致：
   - 用电、供冷：站点总量的有效能耗事实（`analytics.energy_interval_facts_visible`，`SITE` 范围、`VALID`），按站点时区的小时与日汇总；
   - 电度电费：逐小时用电 × 该小时生效的导入电价（`libs/tariffmodel`，与指标引擎、M&V 同一条规则）；有电价但某小时无电价覆盖时，该月电费不出；
   - 诊断发现：`core_registry.fdd_findings` 中评估窗口结束于本月的发现，按类型计数；
   - 节能：`core_registry.savings_daily_results` 中本月的核算日。
2. 一天有任何用电读数就算「有计量数据」，只有供冷读数的日子不算（其供冷仍计入月合计）；综合能效 = 供冷 ÷ 用电，用电为零时为空。
3. 快照以 JSON 保存（`schemaVersion: 1`），带生成时间、调度任务 ID 与版本号。电费为空时，快照记下原因（`energyCostStatus`：`NO_TARIFF` 站点没有导入电价，`UNPRICED_HOURS` 有小时没有电价覆盖），页面据此说明。
4. 时段电价表的「单价」= 该时段电费 ÷ 该时段用电；月中调价时它是该时段的加权平均单价。
5. 存档与现算的电费口径：快照按每小时生效的电价、按小时起点所在时段计价；现算沿用月报页原有算法，按当前电价、一小时跨时段时按分钟拆分。时段边界在整点且月内未调价时两者一致。
6. 任务指定的月份格式不对或尚未结束时，任务直接失败、不重试；其他失败（数据源不可用等）按调度规则重试。
7. 网关接口：`GET /api/v1/sites/{siteId}/reports/monthly/{month}` 返回该月最新快照，没有时 404；`GET /api/v1/sites/{siteId}/reports/monthly?year=YYYY` 列出该年已存档月份的最新快照。读取需要站点读权限。
