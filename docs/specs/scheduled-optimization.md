# 优化建议定时运行

Issue #462 剩余部分。2026-10-13 与用户确认（全部按建议）。本文是实现契约。

预测和故障诊断已经按站点调度运行，优化建议仍只能在页面上手动生成，所以没人点时总览和优化建议页的建议会一直停在旧的状态。

## 决定

| 决策 | 结论 |
| --- | --- |
| 范围 | 补上优化建议的定时运行，完成后关闭 #462 |
| 实现 | 调度器发来的 `OPTIMIZATION_RUN` 不带运行引用；优化服务领取后按站点当前状态准备并封存输入快照、创建运行，再照常执行，结果与手动生成相同。手动生成入口保留 |
| 周期 | 每个站点每小时一次，第 20 分钟（错开第 7 分钟的负荷预测） |
| 用途 | 只更新「最新建议」并记入历史，不自动下发控制指令，不发通知；页面标明「定时生成」或「手动生成」 |

## 行为

1. 每个站点一条调度定义：`OPTIMIZATION_RUN`，cron `20 * * * *`（UTC），负载 `{}`；种子写入时下次触发时间为当下，所以本地重建后会立即运行一次。
2. 优化服务领取到带调度定义的任务时，把它当作一次「调度触发」：按站点准备运行（触发方式 `SCHEDULE`），排入该运行自己的任务后，调度触发任务即完成。
3. 准备失败时（最常见的是站点输入不全：最近一天的用电与电费、最新负荷预测、实时供水与室内温度），这次调度触发失败且不重试，下一个小时重新读取。
4. 已发布的建议带 `trigger`：`MANUAL` 或 `SCHEDULE`，取自该运行任务的触发方式。
5. 「最新建议」是最后准备的那次已发布运行（按运行创建时间），排在队里的旧运行晚完成也不会盖掉它。
