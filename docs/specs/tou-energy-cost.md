# 冷站日电度电费按分时电价计价

HANDOFF「下一步」第一项。2026-10-13 与用户逐条确认（全部按建议）。本文是实现契约。

现在的 `energy_cost` 指标是表达式 `daily_energy × 时间加权日均电价`，不论当天什么时段用电，单价都一样。优化建议用「日电费 ÷ 日用电量」折算节省金额，因此高峰用电多的日子会被低估。

参考平台比对见 `docs/architecture/tou-energy-cost-source-review-2026-10-13.md`。

## 决定

| 决策 | 结论 |
| --- | --- |
| 计价位置 | 指标引擎新增计算方式 `TARIFF_ENERGY_COST`：当天每个小时的用电量乘以该小时的电度电价，再求和 |
| 逐时用电来源 | 复用 M&V 的 `hourly_energy` 指标结果；日指标依赖逐时指标（引擎读取窗口内全部逐时结果） |
| 缺小时 | 窗口内任何一小时没有逐时用电结果、结果质量不是 GOOD，或者没有电价覆盖，这一天就不出电费（明确失败，不出偏低的数） |
| 电价版本与时区 | 每个小时按当时生效的导入电价版本计价，时段按电价版本自己的时区和日类型判断（与 M&V、结算一致）。电价调整后，已发布的日电费不自动重算 |
| 计价范围 | 只算电度电费，不含需量电费。指标名改为「冷站日电度电费」 |
| 代码复用 | 「按日类型、时段查电价」抽成共享库 `libs/tariffmodel`，M&V 与指标引擎共用；电价数据各自从注册中心库读取 |
| 本地切换 | 不重置：本地库新增 `energy_cost` 指标版本 v2（`TARIFF_ENERGY_COST`，依赖 `hourly_energy`），v1 失效，再用 `--metrics-only` 重算历史。种子不保留旧算法：全新环境的 v1 就是 `TARIFF_ENERGY_COST` |

## 行为

1. `energy_cost`（全新环境为 v1，本地库为 v2）绑定站点、按天计算，唯一依赖是 `METRIC hourly_energy`。
2. 引擎计算一天时：
   - 读取窗口内每个整点小时的 `hourly_energy` 当前结果，必须 24 个（夏令时日按实际小时数）齐全且质量为 GOOD；
   - 读取窗口内生效的站点导入电价版本（电网进线结算边界上的分配；有多条进线时取边界编码最小的一条，与 M&V 一致），每小时按其起点所在的版本与时段取电度单价；
   - 结果 = Σ 小时用电 × 小时单价，单位 CNY；持久化的输入记录逐时依赖与所用电价版本，可复现。
3. 优化服务先取最近一个已出电费的日子，再取同一天的 `daily_energy`；两者不是同一天就拒绝生成建议。折算单价变为那一天按负荷加权的峰谷均价。
