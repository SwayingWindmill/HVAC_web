# 电费账单：月度电费预算进度与两部制结算电费单核对

问题单 #785（子单 #786、#787、#788；路线图 #757，调研 #762，决策单 #765）。2026-11-12 已实现。

参照项目一手源码比对（MyEMS `v6.9.0`、OpenEMS `2026.9.0`）见 `docs/architecture/schedule-and-billing-source-review-2026-11-11.md` 第二部分。

物业与冷站负责人在管电费时同时面对两条时间线：平时按站点自然月盯冷站估算电费有没有超月度电费预算；月末收到供电局开具的两部制结算电费单（常常是上月 25 日到本月 24 日这样的跨月抄表周期，且可能只计冷站专变，也可能包含公区照明电梯与租户用电的整栋总表），需要把票面的电度电费、基本电费、功率因数力调奖罚及代征附加拆清楚，再按同一抄表周期核对冷站电表偏差或折算冷站应分摊电费。

## 定下来的做法

| 问题 | 做法 |
| --- | --- |
| 数据归谁管 | 归登记模块（`core_registry` schema，迁移 `035-electricity-budgets-and-utility-bills.sql`）：每个站点按自然月（`YYYY-MM`）存一条「月度电费预算」（`monthly_electricity_budgets`），按供电局单据存「结算电费单」（`utility_bills`）。每次保存预算、录入或修改草稿、确认归档都写入 `core_registry.registry_audit_facts`；不去碰独立的命令行结算工具 `services/settlement-service` |
| 谁能看、谁能改 | `site.read` 可只读查看月度电费预算与结算电费单（具备 `analytics.energy-series.read` 时同时查看平台冷站估算电费与核对结果）；新增能力 `billing.manage`（授予 `site-manager` 与 `admin`，`CapabilitySetVersion = 14`，能力目录版本升至 `10`）可设置或调整月度电费预算、录入与编辑结算电费单草稿、以及确认归档 |
| 两部制四项电费与精度 | 金额一律用 `numeric(14,2)` 精确到分，前后端都按整分（`int64` / `Math.round(x * 100)`）校验四项恒等式：`应收总电费 = 电度电费 + 基本电费 + 力调电费 + 其他代征及附加`。其中基本电费支持「无基本电费（单一制）」「按变压器容量（kVA）」「按最大需量（kW）」三种口径；力调电费与代征附加支持负数（如功率因数达标获供电局减免 `-1,257.00` 元） |
| 草稿与确认归档 | 新录入的结算电费单为 `DRAFT`（草稿待确认），可反复核对修改；确认归档（`POST /api/v1/sites/{siteId}/utility-bills/{billId}/confirm`）后变为 `CONFIRMED`，记录确认人与确认时间并永久锁定不可再改（再改或重复确认回 `409 UTILITY_BILL_STATE_CONFLICT`）。数据库用事务咨询锁 `pg_advisory_xact_lock` 与 `BEFORE INSERT OR UPDATE` 触发器保证同一站点、同一账期、同一表计范围最多只有一张 `CONFIRMED` 结算电费单（冲突回 `409 REGISTRY_BINDING_CONFLICT`） |
| 跨月抄表周期怎么对齐 | 供电局抄表起止日期（`readingStartDate` 到 `readingEndDate`，站点本地日历日首尾都算：例如 `2026-09-25` 到 `2026-10-24` 就是 30 整天）转换成 `[siteMidnight(start), siteMidnight(end + 1 day))` 查询平台冷站电表按日能耗序列，彻底消除自然月（1 日–月末）与供电局抄表日错位带来的假偏差 |
| 冷站专变 vs 整栋总表怎么核对 | 按结算电费单的 `meterScope` 分成两条互斥口径：① **冷站专变（`CHILLER_PLANT`）**：直接比对同抄表周期「供电局抄表电量 vs 平台冷站计量电量」与「票面电度电费 vs 平台分时电价估算电度电费」偏差（基本电费、力调奖罚与代征附加单列占比，不混入电度电费误差）；② **整栋总表（`WHOLE_BUILDING`）**：绝不把整栋账单与冷站电费直接相减当成误差，而是展示同抄表周期平台冷站实测电量与分时估算电费、计算「冷站计量电量 ÷ 整栋抄表电量」（若有财务固定分摊口径则优先采用 `chillerShareOverrideRatio`）以及「整栋综合平均电度单价 = 电度电费 ÷ 抄表电量」与「含基本及力调综合结算单价 = 应收总电费 ÷ 抄表电量」，折算冷站应分摊总电费（并拆出分摊电度电费与非电度电费）；若冷站子表电量异常高于整栋总表电量且未填财务指定比例，显式告警并拒绝按超过 100% 自动分摊 |
| 页面怎么分层 | `/energy-analysis/billing`（侧栏「能源」分组）按 `?view=overview\|bills` 分两层页签，单张电费单核对收进右侧 `?inspect=<billId>` 抽屉：① 首屏「预算进度」顶部严格只放 3 张数字卡（累计估算电费、预计全月估算电费、月度电费预算，口径说明收进 `ⓘ`），若月内存在无电价覆盖的用电量则诚实提示缺电价电量、绝不把部分定价电费冒充整月总额；左侧 2/3 画逐日累计估算电费与预算均摊参考线，右侧 1/3 展示尖峰/峰/平/谷四段电费占比与当月结算电费单快捷卡；②「结算电费单核对」页签用 `DataTableBlock`（严格 5 列：账期与单据号、表计范围、供电局抄表周期、应收总电费、状态与操作）支持表计范围与状态筛选及分页 |
| 能源报告怎么联动 | 不改已冻结的月度报告快照表 `report_snapshots`；`/reports` 月报（含已存档月报与实时月报）第 3 节「电费构成」旁路查询该月已确认归档（`CONFIRMED`）的结算电费单，存在时展示表计范围、供电局抄表周期、应收总电费及一键跳转 `/energy-analysis/billing` 核对详情链接 |

## 验收与测试接缝

1. **数据库约束、登记模块与网关契约接缝（Go 测试 + 契约检查）**：
   - 验证月度电费预算新增与乐观锁更新（`409 REGISTRY_REVISION_CONFLICT`）、两部制四项金额分位恒等式校验（含负数力调电费减免）、确认归档后不可修改（`409 UTILITY_BILL_STATE_CONFLICT`）、同账期同表计范围重复确认归档拒绝（`409 REGISTRY_BINDING_CONFLICT`）、`billing.manage` 权限边界（`403`）与伪造身份请求头拒绝（`400 FORGED_IDENTITY_HEADER`）。
2. **前端账单与核对模型纯函数接缝（`npm run web:model:test`）**：
   - 验证过去月 / 进行中月 / 未来月 / 闰年窗口计算、逐日累计估算电费与月末线性外推、部分缺电价时不伪造整月总额、跨月抄表日期半开区间转换、冷站专变直接偏差核对、整栋总表电量占比与财务指定比例分摊（含子表超总表防呆拦截）、以及网关错误码中文映射。
3. **浏览器 1440px 端到端验收（`npm run web:e2e`）**：
   - 验证 1440px 零横向溢出、设置月度电费预算、录入跨月抄表周期且带负数力调减免的整栋总表结算电费单草稿、在右侧核对抽屉查看冷站分摊折算、编辑草稿并确认归档锁定、录入冷站专变结算电费单查看直接计量偏差、在 `/reports` 月报看到已确认归档的结算电费单摘要并联动跳转，以及只读账号隐藏全部写操作按钮。
