# 分项计量：按设备拆开实测的用电

问题单 #481 第二阶段。2026-10-12 和用户逐条确认（全部按建议），已上线。

参考平台比对（OpenEMS、MyEMS、ThingsBoard）见 `docs/architecture/metered-breakdown-source-review-2026-10-12.md`。

（2026-10-16 起分项能耗并入能耗分析页的「用电去向」和「分项趋势」，下文的「分项能耗页」指这两块。）第一阶段的分项能耗页用各设备功率按小时累加来估算，总表和估算之和的差额单列为「未分项」。第二阶段改为读每台设备自己的电表（分表）。

## 定下来的做法

| 问题 | 做法 |
| --- | --- |
| 分表来源 | 模拟器为冷机、冷冻泵、冷却泵、冷却塔各增加累计电量计数器（由各自功率积分）；空调总表不变 |
| 能源拓扑怎么画 | 每台设备一个能源节点（`LOAD`，关联设备），挂在「中央冷站」（`HVAC`）之下；新增边「冷站 → 设备」（`CONSUME`），每条边绑定该设备的分表为 `PRIMARY` |
| 站点总量和分项 | 每段用电记录带一个「计入范围」：边从非电网节点进入关联了设备的 `LOAD` 节点时记为分项（`BRANCH`），其余为站点总量（`SITE`）——电网直供站点负载的进线仍是总量。总量只统计 `SITE`，分项按设备统计 `BRANCH`。避免加了分表后总量被重复计算 |
| 接口 | 现有 `/api/v1/analytics/energy-series` 增加按设备拆分：返回各设备的时间序列；「未分项」= 总量 − 各分项之和，由页面计算并如实显示（可为负，负值说明分表合计超过总表） |
| 页面 | 分项能耗页读实测分表；没有分表的设备显示「未计量」；删除按功率估算的逻辑，不混用估算与实测 |
| 本地环境 | 已发布的拓扑版本不可修改：`local:reset` 后由新种子重建，再用历史回放补三周历史（含分表） |
| 当时不做 | 按单台设备统计节能（M&V 方法 B），后来作为单独的任务做了（见 `docs/specs/savings-verification.md`） |

## 怎么运作

1. 注册中心解析计量绑定（`meter-binding.resolve`）时返回 `accountingScope`：`BRANCH` 或 `SITE`；`BRANCH` 另返回 `loadDeviceId`，即负载节点关联的设备（分表可以是独立的电表设备）。
2. 把电表读数算成用电量时，把 `accounting_scope` 和 `load_device_id` 写进 `analytics.energy_interval_facts`。
3. 能耗查询：
   - 不拆分时，只汇总 `SITE` 的记录，结果和加分表之前一样；
   - 按设备拆分时，另外返回 `BRANCH` 的记录按 `load_device_id` 汇总的序列，时间段和总量的一致。
4. 分项能耗页：
   - 桑基图「空调总用电 → 设备 → （未分项）」与排行、逐时/逐日分项均来自实测；
   - 设备没有分表时标「未计量」，其用电计入未分项。
