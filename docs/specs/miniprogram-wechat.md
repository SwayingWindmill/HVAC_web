# 小程序的微信绑定、一键登录和订阅提醒

问题单 #664。2026-10-21 和用户定下：

- 告警提醒只发**紧急和重要的新告警**。
- 每日运行结论按**站点时间早上 8 点**发**昨天**的。
- **绑定微信**和**一键登录**这次一起做。

交付顺序是绑定微信 → 告警提醒 → 每日结论 → 一键登录，每一步一个 PR。每一步做完都能在真机上用。

## 定下来的做法

| 问题 | 做法 |
| --- | --- |
| 微信身份 | 微信给每个人在本小程序里一个固定编号（OpenID）。小程序调 `wx.login` 拿到一次性凭证，身份服务拿凭证和 AppSecret 去微信换编号（[code2Session](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html)）。微信同时返回的会话密钥 `session_key` 不保存，也不往外传 |
| 绑定记在哪 | 身份服务的 `identity.wechat_bindings`。一个账号只绑一个微信，一个微信只绑一个账号。权限照旧只归 IAM，绑定不带任何权限 |
| 谁连微信 | 只有身份服务。它保存 AppSecret 和微信编号，也只有它能上外网访问 `api.weixin.qq.com`（Compose 里单独的 `wechat-egress` 网络）。别的服务要给某人发微信消息，就告诉身份服务「发给这个账号」，微信编号不出身份服务 |
| 身份服务认哪个账号 | 只认网关签名的短期凭证（请求头 `X-Delegation-Grant`，30 秒内有效，写明是哪个账号、哪次登录）。请求里不能写账号编号：内网里别的程序拿不到网关的签名，就没法把自己的微信绑到别人的账号上。只有平台自己管理的账号能绑定，外部签发的账号回答 403 `WECHAT_FORBIDDEN` |
| AppSecret | 由管理员自己填在服务器的 `runtime/<环境>/identity/wechat-miniprogram-appsecret`（只读挂进身份服务），不进代码和提交。没有这个文件时，绑定、一键登录和提醒都明确回答「服务器还没有开通微信功能」（503 `WECHAT_NOT_CONFIGURED`），不悄悄跳过；文件在但是空的，身份服务拒绝启动，免得管理员以为填好了。AppID 不是秘密，Compose 里默认是本平台小程序的 `wx4b7b82bf0351c6f3`（环境变量 `IDENTITY_WECHAT_APP_ID`） |
| 订阅次数 | 个人主体只能用一次性订阅：用户在微信弹窗里点一次「允许」，服务器才能给他发一条，不限时间。平台按「人 × 提醒种类」记还能发几条，发一条减一条。微信回答「用户没有订阅」（错误码 43101）时，把次数清零 |
| 谁收告警提醒 | 在小程序里点过「允许」、还有次数、绑定了微信、现在仍有这个站点告警查看权限的人。不需要管理员配通知规则：平台原有的「通知规则 → 投递」到现在一条规则也没配，往外投递的那段也没有程序在运行 |

## 一、绑定和解除微信

1. 「我的」多一行「微信」：没绑定时右边写「没绑定」，下面一行小字「微信一键登录和告警提醒要先绑定微信」，点了就绑定；绑定了写「已绑定」，点了可以解除（要再确认一次）。读不到时写「读不到」，点了没反应。
2. 绑定：小程序调 `wx.login` 拿凭证，发 `POST /api/v1/me/wechat`，请求体是 `{code}`。网关核对小程序会话后，把账号和凭证交给身份服务；身份服务换到微信编号，写入绑定。
   - 这个微信已经绑了别的账号：回答 409 `WECHAT_ALREADY_BOUND`，页面写「这个微信已经绑定了另一个账号，先在那个账号里解除」。
   - 这个账号已经绑了另一个微信：换成新的（本人在登录状态下操作，等于换绑）。
   - 凭证无效或过期（微信错误码 40029、40163）：400 `WECHAT_CODE_INVALID`，页面写「微信这次没有确认成功，请再点一次」。
   - 微信不认这台服务器（AppID 错 40013、AppSecret 错 40125、服务器 IP 不在白名单 40164）：503 `WECHAT_NOT_CONFIGURED`，页面写「服务器还没有开通微信功能，请联系管理员」。
   - 微信别的错误（比如判定这次登录有风险的 40226）或连不上微信：503，页面写「暂时绑定不了，请稍后再试」。
   - 微信每次拒绝，身份服务都在日志里记下错误码（`wechat_refused`，字段 `wechat_errcode`），方便管理员查是哪一种。
3. 解除：`DELETE /api/v1/me/wechat`。解除后这个账号的订阅次数也清零。
4. 查看：`GET /api/v1/me/wechat`，回答 `{bound, boundAt}`。
5. 网页登录会话不能调这三个接口：网页里没有微信，绑定只在小程序里做。
6. 管理员停用账号时绑定保留：账号重新启用后照旧可用。停用期间一键登录被拒绝，提醒也不发。

## 二、告警提醒

模板是「监控告警通知」（模板 ID `E1fGHBeTTIC0bT2xd6Tb0S61UyvL5krxDZz12wkzkdE`，小程序代码和 `NOTIFICATION_WECHAT_ALARM_TEMPLATE_ID` 里都有）。

1. **攒次数**：通知页顶部有「微信提醒」一行，写「还能收到 3 条紧急和重要告警的提醒」，旁边是微信自带的小按钮「多收一条」。
   - 点一次就弹一次微信的订阅弹窗（[wx.requestSubscribeMessage](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)），弹窗必须由点击直接打开。
   - 点了「允许」，小程序发 `POST /api/v1/me/wechat/reminders`（`{kind: "ALARM"}`），次数加一。点「拒绝」不加。
   - 用户在弹窗里勾过「总是保持以上选择」时，再点按钮就不再弹窗，直接加一条。
   - 一条都没有时写「还收不到告警提醒：点『多收一条』，在微信里允许」。
   - 没绑定微信时写「先在『我的』里绑定微信，才能收告警提醒」，没有按钮。
   - 次数记在通知模块的 `notification_runtime.wechat_reminder_allowance`，按人（签发方 + 主体）、按租户计。网关只替登录的这个人加，请求里不能写别人。
2. **哪些告警发**：告警刚出现（`CREATED`）、严重程度是紧急或重要时，记一条待发的提醒。严重程度后来变化、恢复、被确认，都不再发；同一条告警只记一次。
3. **发给谁**：告警出现时，这个租户里还有次数的人，再问 IAM 他们这时能不能看这个站点的告警（每次最多问 200 人，人多就分几次问）（`/internal/v1/reminders/recipient-decision`，`kind: "ALARM"`，和登录的人看告警用同一条规则，每个人的判断都记审计）。被撤掉站点、停用、不认识的人不发。
4. **消息内容**：

   | 关键词 | 写什么 | 例子 |
   | --- | --- | --- |
   | 告警标题 `thing10` | 告警标题，最多 20 个字，超长的截到 19 个字加「…」 | 网关上报中断 |
   | 告警等级 `short_thing15` | 紧急 / 重要 | 重要 |
   | 监控设备 `thing9` | 告警现在都没有关联设备，写「未关联设备」（告警详情页也这样写） | 未关联设备 |
   | 告警地点 `thing4` | 站点名称，最多 20 个字 | 松雅轩 |
   | 告警时间 `time2` | 告警开始时间，按站点时区 | 2026年10月21日 16:00 |

   点开进入小程序的这条告警详情（`pages/alarm/index?id=…`）。站点名称和时区由通知模块向设备登记读：它跑在网关进程里，用网关的后台服务身份（ADR 0017），这个身份在每个租户上有一个只能读站点的角色（`wechat-reminder-site-read`，由 `scripts/phase1-bootstrap-local-foundation.mjs` 登记）。小程序还没正式发布，消息打开开发版（`IDENTITY_WECHAT_MINIPROGRAM_STATE=developer`），发布后改成 `formal`。
5. **怎么发**：发之前先从这个人的次数里扣一条，再请身份服务发（`/app/wechat/messages`，带网关后台身份签名的凭证，写明发给哪个账号）。
   - 发成功：这一条就用掉了。
   - 微信说这个人没有次数了（43101），或者这个人没绑定微信：把他的次数清零，不再发。
   - 网络出错或微信暂时出错：把扣掉的那条还回去，隔 1、4、9 分钟再试，最多发 4 次。
   - 告警开始超过 30 分钟还没发出去的就不发了，免得事后很久才收到旧告警。告警事件到的时候已经超过 30 分钟的，也不发。
   - 不知道微信收没收到的那一条（发到一半进程停了、身份服务或微信超时没回音、回的不是微信的正常回答）不再重发，这一条算用掉。
   - 一个人属于几个租户时，次数按租户分开记；解除微信只清当前租户的，别的租户的次数会在下次发送时因为没绑定或微信拒绝而清零。

## 三、每日运行结论

模板是「昨日能效数据查询提醒」（模板 ID `mc5IwpxxRkoDZUTyq7vWaPyVtrqlamTccAXaJ3Xkgsc`）。2026-10-21 和用户定下：「主机COP」一格填「-」。

1. **攒次数**：总览页最下面有「每日运行结论」一行，写「每天 8 点把昨天的用电、用冷和能效发到微信，还能收 3 天」，旁边是「多收一天」。
   - 次数的记法和告警提醒一样，单独计数（`kind: "DAILY"`）。
   - 点「多收一天」时，平台同时记下当时所在的站点：以后就发这个站点的结论。在别的站点点一次，就改成那个站点。
   - 这一行写清楚发的是哪个站点：「还能收 3 天（松雅轩）」。现在看的站点和发的站点不一样时，写「现在发的是 B 站点；点『多收一天』改成本站点」。一天都没有时写「每天 8 点把昨天的用电、用冷和能效发到微信：点『多收一天』，在微信里允许」。
   - 没绑定微信时，写「先在『我的』里绑定微信，才能收每日结论」。
2. **什么时候发**：每天站点时间 8 点以后，给有次数、绑定了微信、IAM 确认现在能读这个站点能耗的人，各发一条昨天的结论。
   - 每人每天一条（次数和告警提醒一样按租户分开记，一个人属于两个租户就各算各的）。
   - IAM 不同意的人，当天不再问；第二天重新问。
   - 发不出去时，隔 1、4、9 分钟再试；站点时间 12 点以后就不再发了。
   - 不知道微信收没收到的那一条不重发，和告警提醒一样。
3. **消息内容**：

   | 关键词 | 写什么 | 例子 |
   | --- | --- | --- |
   | 项目名称 `thing1` | 站点名称，最多 20 个字 | 松雅轩 |
   | 用冷量 `character_string2` | 昨天冷站的供冷量 | 7402kWh |
   | 用电量 `character_string3` | 昨天冷站的用电量 | 1691kWh |
   | 系统EER `character_string4` | 用冷量 ÷ 用电量，两位小数 | 4.38 |
   | 主机COP `character_string5` | 平台不单独算主机，写「-」 | - |

   - `character_string` 只能写数字、字母和符号，所以读不到的数写「-」，不写「暂无」。昨天还没算完（能耗分析标了 partial）也算读不到，写「-」，不把半天的数当成一整天。
   - 能耗分析暂时连不上时，按发送失败处理：隔 1、4、9 分钟再试。
   - 节能的数字（昨天省了多少钱、少用了多少电）放不进这个模板：公共模板库里没有带节能关键词的。点开消息进入小程序总览，第一眼就能看到本月节省。
4. **数据从哪来**：用电量和供冷量来自能耗分析，按站点自己切好的「天」取（和总览、网页的口径一样，数据质量只用「好」的）。
   - 通知模块用网关的后台服务身份读（ADR 0023）。站点名称和时区每小时最多向设备登记读一次。这个身份在租户上的角色同时能读站点和能耗：`site.read`、`analytics.energy-series.read`。
   - 问 IAM「谁能收」时，告警提醒按「能不能看这个站点的告警」判断，每日结论按「能不能读这个站点的能耗」判断（`/internal/v1/reminders/recipient-decision`，请求里写 `kind`）。

## 四、微信一键登录

1. 登录页在「登录」下面多一个「微信一键登录」按钮，下面一行小字「微信一键登录要先在『我的』里绑定微信」。小程序调 `wx.login`，发 `POST /api/v1/auth/app/sessions/wechat`，请求体是 `{code}`。网关在内网调身份服务的 `/app/wechat/login`（和 `/app/login` 一样带客户端、回调地址、state、nonce 和 PKCE 挑战），身份服务换到微信编号、查到绑定的账号后，和账号密码登录一样发授权码，网关换成会话。
2. 没绑定的微信：401 `WECHAT_NOT_BOUND`，页面写「这个微信还没有绑定账号，先用账号密码登录，再到『我的』里绑定」。平台没有自助注册，微信登录不会新建账号。
3. 账号停用、锁定：和账号密码登录一样被拒绝，并记一条登录失败。回答是 401 `ACCOUNT_UNAVAILABLE`，页面写「这个账号现在不能登录，请联系管理员」：能用这个微信登录，说明是本人，不用像密码登录那样含糊地说「账号或密码不对」。
4. 开了一次性验证码的账号，一键登录后还要输验证码（同一个第二步）。
5. 凭证无效、微信不认这台服务器：和绑定时的回答、页面文字一样。
6. 登录记录写明是微信登录：令牌里的登录方式（`amr`）是 `wechat`，再输了验证码是 `wechat` 加 `otp`；安全记录是「登录成功 · 微信登录」（`WECHAT_AUTHENTICATED`）。等验证码的那一步记住第一步是密码还是微信（`identity.authorization_requests.first_factor`，迁移 007）。
7. 下控制命令仍然要密码加验证码：微信登录后再输了验证码也不行。

## 管理员要在微信公众平台做的

- 「开发管理 → 开发设置」生成 AppSecret，填到上面那个文件里；同一页的「IP白名单」开着时，把服务器的公网 IP（现在是 139.199.58.47）加进去，否则微信回答 40164。
- 「功能 → 订阅消息 → 公共模板库」选两个模板：告警类（比如「设备告警通知」）、日报类（比如「运行日报」）。把模板 ID 和每个模板的字段告诉开发者，写进小程序和身份服务的配置。
- 「开发管理 → 服务器域名」里的 request 合法域名已经有 `hvac.swayingwindmill.online`，不用改。

## 不做

- 长期订阅：只开放给政务、医疗、交通、教育这类机构的小程序，个人主体用不了。
- 公众号模板消息、短信、邮件。
- 在网页上看或管理别人的微信绑定。
