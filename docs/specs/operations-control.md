# 运行控制：控制方式、单机锁定、机组启停与高风险确认

`/operations/control`（侧栏「运行控制」）。后端契约见 `cmd/energy-api/internal/gateway/control_exit.go`、`command.go` 和 `libs/commandmodel/model.go`。已实现。

## 页面上有什么

| 区域 | 做法 |
| --- | --- |
| 控制方式条 | 读 `GET /api/v1/sites/{siteId}/control-state`。大字写当前方式（● 远程自动控制 / ▲ 人工接管 / ◆ 安全退出），旁边写谁设的（自己显示「我」，别人显示「其他人员」，不显示人员编号）、几点、原因、锁定设备数和待处理指令数。右边三段选择，点另一种方式打开「切换到…？」，原因必填、最多 1000 字，带 `expectedRevision` 防止覆盖别人刚改的状态。没有 `schedule.manage` 权限时不能切换 |
| 机组列 | 每台 `CHILLER` 资产一列，列里是它的 `START` 点位 `interlocks` 里点名的冷冻泵、冷却泵、冷却塔（松雅轩 A–D 机组各 4 台）；没被任何冷机点名的设备放在最后一列「其他设备」。冷机有 `START_UNIT_SEQUENCE` / `STOP_UNIT_SEQUENCE` 点位时显示「一键启动」「一键停机」，确认框里列出执行顺序（启动：冷冻泵 → 冷却泵 → 冷却塔 → 主机；停机反过来） |
| 设备行 | 只给当前能做的一个按钮：运行中给「停止」，已停给「启动」，故障给「复位」。按顺序判断不能按的原因并写在悬停提示里：控制方式不是远程自动 → 已锁定 → 已有指令没结束 → 水路联锁不满足 → 读不到运行状态。联锁不满足时行内直接写「先开 1 号冷冻泵、1 号冷却塔」或「先停 A 机组主机」。有设定值点位的设备多一个「调整设定值」按钮，打开设定值对话框 |
| 锁定 | 行尾锁图标打开「锁定 …？」：手动锁定（现场临时手动操作）或检修锁定（长时间停用），原因必填；已锁定时可改锁定方式或解除。锁定后列出并撤回这台设备还没下发的指令 |
| 指令记录 | 右栏，筛选「全部 / 待审批 / 执行中 / 待现场确认」写进 `?status=`；待审批的可「批准」「撤回」，排队的可「撤回」，待现场确认的记「已生效 / 没生效」；点标题用 `?inspect=` 打开详情侧栏看经过 |

## 高风险确认

- `START`、`STOP`、`START_UNIT_SEQUENCE`、`STOP_UNIT_SEQUENCE` 的基础风险是高风险，确认框一开始就要 6 位动态口令（`verificationCode`）并勾选「我已和现场确认可以停/开」，两项都齐了「提交」才能点。
- 设定值的风险按变化幅度评估，确认框先不要口令；网关回 `STEP_UP_REQUIRED` 时确认框不关，补出口令输入框再提交。
- 批准高风险指令要求 10 分钟内做过两步验证。网关回 `STEP_UP_REQUIRED` 时弹「批准前要再验证一次身份」，「去验证身份」用 `assurance=high` 重新登录，`returnTo` 带上 `?inspect=<指令>`，回来后再点一次「批准」。

## 网关拒绝时说什么

`features/control/control-errors.ts` 把 `ProblemDetails.code` 换成中文，不显示网关英文原文；没登记的代码显示通用的「指令没有被接受，请刷新后再试」。例如 `COMMAND_INTERLOCK_BLOCKED` →「被水路联锁拦下：对应的水泵、冷却塔或主机状态不允许这样操作。」，`SAFE_SHUTDOWN_PRECONDITION_FAILED` →「还有指令正在下发或等现场确认，先处理完再安全退出。」。`REGISTRY_REVISION_CONFLICT` 时重新读取控制状态。

## 其他页面怎么配合

- 顶栏：站点不是远程自动时，所有站点页面在站点名旁边显示 ▲ 人工接管 / ◆ 安全退出，链到本页。
- 侧栏：「运行控制」角标是待审批加待现场确认的指令数。
- 实时运行：有锁定时头部显示「N 台锁定 ›」；「最近事件」加入今天的控制方式切换和锁定。
- 设备详情侧栏：锁定的设备显示锁定方式、谁、几点、原因和「去运行控制 ›」，只读。

## 不做

- 不显示人员姓名：网关只给人员编号，没有按编号查姓名的接口，按 `personLabel` 显示「我 / 其他人员」。
- 用户列表显示谁开通了两步验证要等后端返回这个字段（问题单 #831）。

## 验收与测试接缝

1. `npm run web:model:test`（`scripts/test-real-control-model.ts`）：按联锁把冷机和辅机分组、没点名的设备单列、读不到状态的联锁设备也算拦截。
2. `npm run web:e2e`（`e2e/control.spec.ts`）：设定值从设备行打开且输入法回车不提交；停泵要口令和现场确认、请求体带 `verificationCode`，批准时先提示重新验证身份；切到人工接管撤回待审批指令、按钮置灰、顶栏出现胶囊，有待现场确认的指令时不能安全退出；检修锁定撤回该设备指令，解锁后恢复。
