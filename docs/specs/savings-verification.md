# 节能项目与节能验证（M&V）规格

Issue #484. Decided with the user in three rounds on 2026-10-12. This spec is the contract for implementation.
Implemented on branch `feat/mv-service` (2026-10-12); live acceptance of verified days is pending enough local history (see `docs/HANDOFF.md`).
Terms follow IPMVP: 措施 (measure), 测量边界 (measurement boundary), 基线期 (baseline period), 报告期 (reporting period), 调整后基线 (adjusted baseline), 节能量 (avoided energy).

## 范围

| 决策 | 结论 |
| --- | --- |
| 措施来源 | 用户在"节能项目台账"登记；可关联一条已执行的优化建议或控制指令作为依据 |
| IPMVP 选项 | 选项 C：以冷站空调总电表为测量边界（无设备级电能表；有分表后再做选项 B） |
| 基线模型 | 逐时线性回归：冷站用电 = a + b × 供冷量（气象有变化时可加冷却度时项）；必须通过 ASHRAE Guideline 14 检验，否则显示"基线不可信"，不出节能数字 |
| 基线期 / 报告期 | 基线期默认实施前 14 天（最少 72 小时、数据覆盖率 ≥ 90%）；实施后头 24 小时为稳定期不计；之后持续核算，按日、按月汇总 |
| 计价 | 逐时节电量 × 该小时分时电度单价（站点当前生效电价）；需量电费节省第一版不计，并在界面注明 |
| Owner | 新建 `mv-service`，与 forecast、optimization、fdd 并列；保存措施台账、冻结的基线模型和每日核算结果；调度任务 `MV_EVALUATION` 每天核算一次 |
| 权限 | 新增 IAM 能力 `savings.manage`（登记、确认实施、结束、重拟合），默认授予管理员；读取沿用站点读取 |
| 生命周期 | 计划中 → 已实施 → 已结束 |
| 基线冻结 | 确认实施时，用实施前的基线期拟合并冻结；未通过检验可以换基线窗口重拟合，直到第一天核算结果发布为止；此后基线不可修改 |
| 重叠 | 同一站点边界上，报告期不得重叠；重叠登记被拒绝并说明原因，多项措施可合并为一个项目登记 |
| 界面 | 能源组新增"节能项目"页（台账、登记、详情侧栏：拟合质量、每日节电量图、逐日实际与调整后基线（表）、累计节能量与节省电费）；总览新增"节能成效"卡；月度报告增加节能成效一节 |
| 本地验收 | 模拟器增加配置驱动的日内负荷曲线与气象日变化，本地两个站点默认开启、参数略有差异 |

## 行为

1. 登记措施：名称、类型、计划实施时间、说明、投资额（可选）、预期年节电量（可选）、关联依据（可选）。状态为"计划中"。
2. 确认实施：给定实际实施时间。服务读取基线期（默认实施前 14 天）的逐时用电与供冷量，拟合模型，计算 CV(RMSE) 与 NMBE。
   - 通过检验：冻结系数、样本数、检验值与基线期，状态变为"已实施"。
   - 未通过检验：状态仍变为"已实施"，但标记"基线不可信"，记录检验值；可换基线窗口重拟合，直到第一天核算发布。
3. 每日核算（`MV_EVALUATION`）：对每个已实施且基线可信的措施，取报告期中已完整、且不在 24 小时稳定期内的每个小时：
   - 调整后基线 = a + b × 实际供冷量；
   - 节电量 = 调整后基线 − 实际用电；
   - 节省电费 = 节电量 × 该小时电度单价。

   按站点当地日汇总后写入日结果，不可修改。缺数的小时计入覆盖率，不补值。
4. 结束措施：给定结束时间，此后不再核算。
5. 读取：措施列表、措施详情（含基线检验与日结果）、站点本月汇总。

## 检验阈值（ASHRAE Guideline 14，逐时数据）

- CV(RMSE) ≤ 30%
- |NMBE| ≤ 10%
- 基线期样本 ≥ 72 个完整小时，覆盖率 ≥ 90%

## 不做（第一版）

选项 B、需量电费节省、非例行调整（静态因子变化）、多措施节能量分摊、节能项目审批流程。

## 第二版：选项 B（设备分表）

2026-10-13 与用户确认（全部按建议；数据来源改为设备逐时指标，以保持 ADR 0021「M&V 读已发布的指标结果」）。

| 决策 | 结论 |
| --- | --- |
| 范围 | 只做选项 B；需量电费节省、非例行调整、多措施分摊、审批流程仍不做 |
| 测量边界 | 登记时选「冷站总表（选项 C）」或「某台设备的分表（选项 B）」；只列出有分表计量的设备；登记后不可改 |
| 基线模型 | 设备用电 = a + b × 冷站逐时供冷量，与选项 C 同一检验（ASHRAE Guideline 14） |
| 数据来源 | 新指标 `device_hourly_energy`（设备逐时用电量，对象为设备，读该设备分表的计数器，DELTA），每台有分表的设备一条绑定，每小时计算；供冷量仍取 `hourly_cooling` |
| 报告期重叠 | 同一设备不重叠；不同设备可以重叠；冷站总表的措施与任何措施不重叠 |
| 汇总节能率 | 节电量 ÷（冷站同期实际用电 + 节电量）；同期 = 有核算结果的那些小时；各措施详情仍按各自边界：节电量 ÷ 调整后基线 |
| 本地验收 | 回放历史，站点 B 某日起调低冷冻泵频率，登记为冷冻泵分表的措施，核算结果录为 e2e 数据 |

### 行为

1. 登记措施时可带 `boundaryDeviceId`；不带即冷站总表。服务检查该设备在本站点有 `device_hourly_energy` 结果，没有则拒绝（「该设备没有逐时用电指标」）。
2. 设备边界的逐时样本：设备的 `device_hourly_energy`、站点的 `hourly_cooling` 与 `hourly_energy` 三者都为 GOOD 的小时。冷站总表边界不变（`hourly_energy`、`hourly_cooling` 两者为 GOOD）。
3. 每条日结果另记 `plantKWh`：所核算小时的冷站用电（`hourly_energy`）。冷站总表边界下等于实际用电。
4. 站点汇总（总览卡、节能项目页本月、月报、年报）把各措施的节电量与节省电费相加；`plantKWh` 同一天取各措施中最大的一条，不重复计算。
5. 确认实施时按上表的报告期重叠规则检查；数据库触发器执行同一规则。
