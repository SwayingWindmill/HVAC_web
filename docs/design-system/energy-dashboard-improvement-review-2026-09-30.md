用户上传的《商业建筑 HVAC 智慧能源节能运营平台：产品与前端 UI 设计方案》为本次目标输入。
结合 PRODUCT.md、当前页面架构、全局交互合同、03 站点总览规范、DESIGN.md 和 Dashboard 布局规范审查首页。

当前服务页面未出现 JavaScript pageerror；这不代表完成业务联调或交互验收。
截图可能捕获图表动画中间帧，不将环图瞬时形态判定为产品缺陷。

用户本次目标将首页重点转向节能经营成果。原 03 规范将首页定义为 attention router，9 月 30 日布局规范要求六张指标卡；两者与此次输入存在职责和构图差异。
实施时应以本次明确目标重写相应首页合同，并保留高后果异常的及时提示，不能并存两套相互冲突的首页结构。

## 主要判断

当前外壳、浅色背景、shadcn 控件与模块化组件可作为候选基础。主要问题是节能业务层级、可信事实与真实动作尚未闭合，而不是基础组件数量不足。
目标：首页让用户在 30 秒内回答实际耗能、合理耗能、节省结果、策略贡献、舒适度影响、下一步行动。

## 推荐首页结构

```text
站点 / 建筑范围    本月 / 自定义期间    基线口径    数据截至时间
高后果异常提示（仅在确有风险时出现）

节能成果带：实耗 | 调整后基线 | 节省量 + 节能率 | 节约费用 | 舒适合规

主要分析区（8:4）
  左：基线 vs 实际 + 节省区间
  右：节能结果摘要 + 验证状态 + 基线解释入口

来源与约束区
  已运行策略及收益证据 | 舒适度约束及超限区域

下一步行动区
  高价值机会（3–5 项） | 需要处理的异常 / 责任事项

系统效率摘要：冷站、输配、空气系统、末端按各自单位比较
次要入口：分项分析 / 数据质量 / 报告
```

五项成果合并到一个轻量 Surface，用间距和 Separator 区分；节省量与费用有更高视觉权重。
分项用能图有分析价值，但其首页位置不应挤占节能证据与舒适度。详细分项放能源分析，首页保留简洁入口或摘要。
正常舒适度作为常驻约束；高后果舒适/运行异常靠近页面上方，不受固定阅读顺序限制。
组合层与建筑层共享组件语法，但摘要内容按职责变化，不能只给相同数据乘比例系数。

## 基线与节能语义

显示期间、能源类型、计量边界、基线方法和验证状态。基线的方法说明与证据放快速详情，完整 M&V 调查进入可分享的详情页面。
简单节能关系为同一边界和期间的调整后基线耗能减去实际耗能；调整方法、覆盖率和不确定性由权威业务 owner 提供，前端不自行创建认证结论。
同比下降、模型估算、待验证收益、已验证收益分别标识，不能混为节能量。
电费节约与能量节约分开：削峰移时可能节约费用但未减少总用电。
多策略可能互相影响，不能直接相加策略估算并宣称等于全站已验证收益。
舒适合规率显示统计对象、占用时间、覆盖范围和缺测情况；缺数据不是 100% 合规。

DOE 官方 EMIS 资料支持用基线模型预测耗能与实耗比较，并强调 M&V 对措施或项目收益的量化和验证：
https://www.energy.gov/cmei/femp/energy-management-information-system-capabilities
https://www.energy.gov/cmei/femp/measurement-and-verification-activities-required-energy-savings-performance-contract

## 视觉与交互方向

- 延续中性浅色应用壳；实际曲线用蓝色、基线用灰色、节省用克制的绿色；告警色保留给风险。
- 主数值约 30–36px，模块标题约 16px；单位弱于数值但可读，数值采用 tabular-nums。
- 常规页面 24px 内边距、16–24px 模块间距；以实际桌面渲染校准，不机械套每个模块四段 Card。
- 主图默认仅两条权威曲线；Tooltip 清楚区分 kW 功率差和 kWh 期间能量；仅在有数据时加入天气/占用解释。
- 系统能效按 COP、kW/RT、输配指标等真实对象组织，不将不同单位映射成无来源的统一评分。
- 机会摘要呈现对象、损失/潜力、优先理由、责任与下一动作；模型置信度只有来源可追溯时展示。
- Sheet 用于短暂判断与少量动作；长证据、执行历史、持续工程调查进入 durable route。
- 时间、基线、范围等可恢复分析上下文由 TanStack Router search 负责，查询事实由 TanStack Query 负责。
- Loading、无数据、未接入、查询失败、过期、待验证分别表达；查询失败不能无限显示 Skeleton。

继续使用项目 shadcn/Radix primitives、tablecn/TanStack Table、shadcn Chart/Recharts 和既有领域组件，无新增组件体系的必要。
本评估没有采用新上游机制、引入依赖或批准架构变更。实施若采用外部 Block/机制，应按 AGENTS.md 对固定版本的官方源码、测试和文档做 source review；能源平台重叠能力必须比较 ThingsBoard/OpenEMS/MyEMS 的适用实现。

## 建议交付顺序与验收

1. 先统一首页职责和事实语义，清理写死数值、伪曲线、伪成功动作，明确演示模式。
2. 完成首页核心：成果带、基线对比、策略来源、舒适约束和机会入口；暂不扩展其它页面。
3. 接通关键业务链：机会→审批/派工→执行证据→收益验证，保留范围与时间上下文。
4. 统一排版、颜色、表格与详情语言，在目标桌面视口完成视觉和键盘 review。

验收重点：
- 30 秒内能回答用户定义的六个核心问题；没有数据的问题明确显示无法评估及原因。
- 范围/期间切换后，数值、曲线、口径一致；刷新、返回和分享恢复相同分析上下文。
- 页面不存在将示例、模型推断或局部状态变化表述成真实认证/派工/完成的行为。
- 首页可进入能源证据、策略历史、机会处置和舒适异常详情。
- 缺测、无基线、接口失败等状态下仍可理解并采取下一动作。
- 1440×900 与 1920×1080 桌面检查层级、可读性和几何；不引入移动验收。
- 只运行本次受影响的行为验证与窄范围 detector；构建或 detector 通过不等于视觉批准。

## 实施结果

已替换指标卡墙、主图及机会/关注结构，接入 URL 期间、显式示例/真实边界、非模态详情和真实 CSV。删除废弃首页模块，保留独立站点路由。当前合同见 dashboard-layout-specification.md 与 03-site-overview.md，源码取舍见 energy-dashboard-source-review-2026-09-30.md。

能源行为测试 16 项通过；Web 类型检查与生产构建通过；首页窄范围 detector 无发现；1440×900/1920×1080 桌面交互与视觉检查通过。真实平台仍缺集团/区域历史聚合、基线方法及核证证据，页面明确标记而不补造。
