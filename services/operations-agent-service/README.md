# Operations Agent service

The AI operations assistant behind the Platform Gateway. An operator asks a question about one
Site; the service runs a pi agent (`@earendil-works/pi-agent-core` / `pi-ai`, ADR 0014) with
read-only Tools over the platform owners and records the answer as an Agent Session.

```text
Gateway (BFF Session, CSRF, Site visibility, rate limit)
  -> mTLS -> transport-http   Agent Session routes, signed operator delegation
  -> application              Session lifecycle: create, run, cancel, submit input
  -> runtime-pi               one pi Agent per Run: system policy, model, Tools, budget
  -> tools                    site_get_context, assets_list, telemetry_get_current,
                              energy_query_series, energy_compare_periods
  -> persistence              agent_operations: sessions, runs, messages, tool executions, artifacts
```

Before every Tool read the service asks the Gateway's mTLS-only Tool authorization route
(`/internal/v1/operations/tool-authorization`) to exchange the Session's service delegation for
the exact owner grant, so a Tool can never read beyond what the signed-in operator may see. Tools
read Registry and Telemetry/Energy owner routes only; the boundary check rejects direct
ClickHouse, Cube, ThingsBoard and Command API paths. There is no Tool that changes equipment.

A Run ends with `investigation_complete` (a Finding with its evidence) or
`investigation_request_input` (one bounded question to the operator). Each Run is limited by
`AgentRunBudget` (model calls, Tool calls, wall clock, query range, result size, tokens); the
production limits are in `src/bootstrap/main.ts`. Pi's internal state is never stored: a new Run
rebuilds the conversation from the committed messages and Artifacts, and a Run interrupted mid
stream is recorded as failed.

The Session events (`hvac.agent.event/v1`) stream over SSE: a snapshot, `assistant.delta` text,
Tool start/finish, Artifacts, input requests and the Run outcome. The Web client types are
generated by `scripts/generate-operations-agent-session-contracts.mjs`.

## Model

The model comes from the environment; DeepSeek is the only provider wired today:

```text
AGENT_MODEL_PROVIDER=deepseek
AGENT_MODEL_ID=<exact model id>
AGENT_MODEL_ALLOWLIST=<comma-separated exact ids>
AGENT_MODEL_THINKING_LEVEL=off|minimal|low|medium|high
AGENT_MODEL_TIMEOUT_MS=<100..120000, default 30000>
AGENT_MODEL_MAX_OUTPUT_TOKENS=<default 2048>
DEEPSEEK_API_KEY=<server credential>
```

## Checks

From the repository root:

```bash
npm --prefix services/operations-agent-service run check     # contracts, typecheck, module boundaries, tests (faux provider)
npm run operations-agent-service:postgres                     # Session persistence against a disposable PostgreSQL
OPERATIONS_AGENT_OPERATIONS_MIGRATOR_DATABASE_URL=... \
  npm --prefix services/operations-agent-service run migrate:operations
```

Modules import each other only through their `index.ts`; `agent` and `application` import no
adapters or external packages (`scripts/check-operations-agent-service-boundaries.mjs`).
