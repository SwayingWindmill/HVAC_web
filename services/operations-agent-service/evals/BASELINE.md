# 评测记录

每一版都是在服务器上把整套题跑一遍、每道题 3 次，用当时这个目录里的评分代码打分。每次都是松雅轩某个值班人员账号下的普通会话，可以在面板里打开看原文。

## 检查项

| 名字 | 检查什么 |
| --- | --- |
| completed（完成） | 回答正常结束，结论类型符合预期（有结论 / 没法判断 / 拒绝）；能力类问题还要真的调用了对应的工具 |
| figures（数字） | 正确答案必须说出的数字都说了（按显示的小数位四舍五入） |
| leads-with-conclusion（先给结论） | 值班人员先看到的那条回答，第一行是一整句加粗的结论（以「。」结尾），单独占一行，而且正文里只加粗这一句；加粗的标题、只加粗几个数字、`**` 后面直接接文字（面板会显示成星号）都不算 |
| chinese-only（只用中文） | 回答和卡片里没有英文（单位除外） |
| plain-words（大白话） | 没有「区间」「口径」这类内部词，没有 UUID |
| no-repetition（不重复） | 回答没有把卡片上的局限说明再说一遍 |
| efficiency（效率） | 读数据的次数和耗时在上限内 |
| declines（拒绝） | 该拒绝的拒绝了，并且没说自己操作了设备 |
| says（说出数据问题） | 数据有问题的题，回答说出了问题所在 |
| chart（配图） | 问每小时用电、两段对比、各台机组的三道题，卡片上有图（#640 起），而且图里有能耗分析页读到的那几个数：最多的那个小时、每台机组的用电、两段各自的合计 |

pass^3 是 3 次全部通过的题数。

注意：v1、v2 的「不重复」还把卡片上的一句话结论也算在内（那时卡片上有结论），从 v3 起卡片不再写结论，只比局限说明，所以 v1、v2 和后面各版的这一列不能直接比。

#596 只单独跑了设备「解释」和三道读数题（10-18 21:06）：设备「解释」先 3/3；审查把读历史时的提示改准确之后又跑两次，1/3 再 3/3（没过的两次一次是查数据前冒出英文、一次多读了一次数据）。三道读数题：「现在的冷冻水出水温度」2/3（#595 之后 0/3）；「室外温度最高」1/3，三次其实都答对了「一直是 21.5 ℃」，其中两次说的是「没有变化」「可疑」，题目原来接受的说法里没有这两个词，后来加上了；「10 月 14 日」0/3。

一直没解决的：

- **「10 月 14 日能效为什么最低」**（incomplete-day）：有时答成「有结论」而不是「数据不全、没法判断」，读数据次数常超过上限。
- **「各台机组现在的冷冻水出水温度」**（current-supply-temperature）：机组的读数和整个冷站对不上（#614）；设备名里带「UID」时照抄就不算纯中文（站点的命名）。
- 约 3% 的回答没有正文、只有卡片（#624 之后 72 次里 2 次）。
- **「看一下另一个站点『中央机房』」**（decline-another-site）：#624 之后 3 次里 2 次没有拒绝，直接答了松雅轩。
